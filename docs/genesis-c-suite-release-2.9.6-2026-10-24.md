# C1–C6: связанная приёмка и выпуск Android 2.9.6/101

Основание — пользовательское поручение завершить шаблоны, автоматизации, поля, командные отчёты, импорт/экспорт и права, затем выполнить общий выпуск. Дополнительное поручение — одинаковое скругление обычных блоков сайта по карточке ежедневного совета; верхние блоки «Оракула» оставить как на скриншоте. Репозиторий по последнему указанию остаётся Public после выпуска.

Работа выполнена в отдельной ветке `codex/c-suite-completion-2026-10-24` от `44cffeee` (PR #266), затем fast-forward до `3393f713` (PR #267) с сохранением новых проверок целостности советов. Предыдущая web/API-приёмка C1/C2/C3/C5/C6 описана в [протоколе 23 октября](genesis-c-workflows-completion-2026-10-23.md); отдельные нативные редакторы уже реализованы. Этот выпуск завершает их проверку в общей цепочке с настоящим PHP API и AuthController. Он не подменяет прежнюю реализацию новым стеком. Новых миграций, зависимостей и ручных правок production-БД нет.

## Принятые сценарии

| ID | Связанная проверка |
| --- | --- |
| C1 | Настоящий web UI сохраняет проект с родителем, ребёнком, чек-листом и 0/false как шаблон, показывает preview и создаёт независимые ID. Android → HTTPS → PHP сохраняет богатый граф из двух проектов и четырёх задач, все семь типов полей, связи чек-листа и зависимости. Keystore-повтор после потери ответа, редактирование, архив/восстановление, 14 языков стартовых шаблонов и три календаря покрыты native HTTPS suite. |
| C2 | Web-редактор сохраняет явный приоритет 0; потеря ответа → reload → тот же body/operationId даёт одну revision. Dry-run не меняет исходную задачу. Настоящий штатный PHP worker выполняет созданное из web и Android правило; повторный проход не повторяет эффект. Серверные suites проверяют lease, сбой до ack, устаревание, текущий ACL, циклы и повторы. Рабочий Hostinger heartbeat подтверждён публичным `/api/health`, без SSH. |
| C3 | Native metadata/editor/query suites проверяют все семь типов, 0/false/отсутствующее значение, замену типа с сохранением предшественника, архив вариантов и историю. Web UI создаёт число/checkbox через preview, читает и сохраняет 0/false. Значения проходят через C1 и C5; ID полей и вариантов после импорта новые, смысл значений сохраняется. |
| C4 | Настоящие события create → doing → done дают измеренный цикл и точный источник на Android. Импортированная история остаётся явно неполной. Web-отчёт и его drilldown совпадают с исходными ID, фильтр приоритета сохраняет 0, неверный часовой пояс блокирует обновление без потери ввода. Из общего Android-меню пройден путь отчёт → выборка → исходная задача → системный Back. Серверные history/integration suites покрывают границы календарей, DST, unknown history, доступ и оценки в отдельных единицах. |
| C5 | Реальный Android JSON export → preview → apply → replay → export сохраняет поддерживаемый граф, типы и значения. Undo после последующей правки возвращает DATA_UNDO_CONFLICT и оставляет правку. Web CSV с числом/checkbox проходит потерю ответа, восстановление исходного файла и byte-identical retry с одним receipt. JSON/Trello/CSV, mapping, безопасные URL, formula injection, quarantine истории и ACL покрыты серверными suites. Native picker/provider и состояния редактора проверяются отдельными UI-сценариями. |
| C6 | Web UI после потери ответа повторяет одну операцию прав с одним повышением revision. Ограниченный viewer видит экспорт без импорта; чужой ID и прямой write отклоняются. Отзыв закрывает уже открытый обмен данными. Android проверяет ограниченное дерево, отчёт/экспорт без недоступного проекта и отказ прямого чтения после revoke; через настоящий AuthController применяются просмотр и явное наследование из нативного редактора. Серверные suites проверяют единый ACL, файлы, метаданные, перенос, наследование и кеш. |

## Оформление

В браузере фактический радиус эталонной карточки совета равен 10 px. Он вынесен в `--ui-surface-radius` и применён к обычным карточкам, панелям, диалогам и их существующим адаптивным правилам. Токен доступен до гидратации темы. Изменяются только радиусы; размеры, отступы, изображения и функции сохранены.

Авторские верхние композиции `.theokyklos-hero`, `.theokyklos-mandala-card` и `.stoicheion-view` сохранены. Computed style до/после совпадает на 360/390/768/1440 px в обеих темах. Круги, орбиты, карты Оракула, аватары, индикаторы прогресса и геометрия календарных ячеек не заменяются прямоугольными карточками. `DESIGN.md` отражает общий радиус и эти исключения.

## Проверки и воспроизведение

- Frozen install, lint (0 ошибок, два прежних предупреждения img), 572 web tests и `build:beget` — PASS. Сохранены 94 обязательных entry assets и 203 обязательных visual assets; самый большой JS chunk — locale-fr, 349968 байт.
- 28 изолированных PHP suites C/связанных механизмов и две дополнительные проверки daily-advice/habit-reminders после интеграции PR #267 — PASS.
- Native unit: 765 случаев, 757 PASS и 8 прежних opt-in skips. Debug/test APK собираются в отдельный `ru.genesis.calendar.ghttps.debug`; release-приложение не очищается и не удаляется.
- Нативные реальные HTTPS suites: 10 сценариев C1/C3 и два связанных сценария C1–C6. UI общего меню использует production AuthController, а не подменённый gateway. Снимки телефона API28 и планшета API35, обе темы, 360/390/768/1440 px, нативный Back, выбор участника, preview и применение прав сохранены в ignored `output/c-suite/native/`.
- Браузер: связанная приёмка всех шести направлений, потерянные ответы/повторы, cross-role/revoke; обе темы × 360/390/768/1440 px. Отдельная матрица Today/Theokyklos/Stoicheion подтверждает 10 px у обычных блоков и неизменность верхних блоков Оракула. До/после и receipts находятся в ignored `output/c-suite/`.
- Исходный пакет native UI дал 55 PASS, 11 opt-in capture skips и одно превышение 10-секундного ожидания готовности импорта. Прицельный повтор этого сценария прошёл. Общая HTTPS-проверка не выдаёт skipped capture за пройденный функциональный тест.
- В существующем habit-reminders CI-сценарии устранено предположение, что десятиминутный snooze всегда помещается в текущий UTC-день. Положительный fixture выбирает безопасный локальный день; проверены пограничные часы, deadline production не ослабляется. Ошибки первого запуска harness (предположение о числе определений, сравнение новых option ID с исходными, integer-флаг legacy status, ожидание имени файла без ожидания рендера) исправлены в тестах; они не объявляются дефектами продукта.

Воспроизводимый loopback-стенд: [scripts/c-suite](../scripts/c-suite/README.md). Он отказывается заменять существующую конфигурацию, проверяет SHA и точный путь synthetic DB до каждого API-запроса и не содержит внешних credentials. Ключ локального TLS, cookies, runtime и содержимое конфигурации не входят в Git. После приёмки собственная конфигурация удаляется только с проверкой SHA/пути.

## Выпуск и границы

Публикация выполняется единственным существующим `deploy.yml`: версия APK/AAB 2.9.6/101, прежняя release-подпись, актуальный web/API, runtime-only backup. Android включается только для этого выпуска и затем снова выключается. До успешных Actions, совпадения master SHA с deploy-meta, health и проверки подписанного APK публикация не считается подтверждённой; фактические SHA/run фиксируются в описании PR и release receipt.

После подтверждения этого выпуска C1–C6 закрыты: строгий функциональный счёт основного промпта — 23/32, открыты девять других ID (G1–G4, E4/E5, F1–F3); отдельно остаются 14 сквозных K/U/L. Эта запись не объявляет весь исходный промпт завершённым.

Не повторялись физические телефоны, Safari/iOS/WebKit, новый интерактивный Google OAuth, реальная внешняя email/push-доставка и перенос 20 MiB через production Hostinger. Разрушающие тесты прав/импорта выполнялись на синтетической локальной БД, а не на личных данных production. Старый домен сохраняет интерфейс; объявление о переезде не включалось. SSH вручную не использовался: штатный CI deploy использует собственное существующее SSH-подключение.
