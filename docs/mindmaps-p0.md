12 октября 2026 · ветка `codex/personal-mindmaps-p0` · база `b40e796`.

Рабочая реализация находится в отдельном worktree. Основной сценарий с настоящей локальной задачей GENESIS и серверным шифрованным документом карты прошёл. **Полная готовность P0 к публикации не подтверждена:** отсутствует создание задачи без даты; живой Google, физическое устройство и screen reader не проверены. ## Что хранится и как восстанавливается

- Документ, view state, графический движок и адаптер задач разделены: [модель](../app/mindmaps-model.ts), [репозиторий](../app/mindmaps-storage.ts), [редактор](../app/Mindmaps.tsx), [полотно](../app/MindmapCanvas.tsx). Новая UI-библиотека не добавлена.
- Сервер хранит отдельные документы с владельцем и ревизией; названия, мысли, заметки, ссылки и 20 версий находятся в AES-GCM-конвертах. Используется действующий ключ workspace через [personalDocumentAccess](../app/cloud-sync.ts), с AAD, включающими пользователя и назначение конверта. Новая авторизация и второй store задач отсутствуют.
- В localStorage карты, view state и журнал преобразования также зашифрованы. Обычный task store продолжает использовать существующую модель приложения; новое шифрование карт не является заявлением о переработке старого task cache.
- Сервер валидирует доступ, версию и размеры конверта. Скрытый граф валидируется клиентом после расшифрования. Неподдерживаемая версия блокирует чтение/перезапись.
- Каждый writer имеет собственный UUID и защищённый черновик. Неотвеченный запрос хранится отдельно от более нового текста; повтор отправляет прежний operation ID и точный конверт, затем новую ревизию. Квитанции операций переживают сокращение истории.
- CAS не делает silent last-write-wins. При конфликте остаются оба текста; пользователь может открыть серверный вариант или сохранить отдельную карту. Автоматического фонового retry после восстановления сети нет — есть явная команда.
- Наименование, дата, проект и состояние TaskRef разрешаются из настоящей задачи. Узел не содержит независимой редактируемой копии этих полей. Удаление/перемещение и история карты не изменяют задачи. ProjectRef не добавляет задачи проекта в счётчик; повторные ссылки считаются один раз.
- Преобразование использует task ID `maptask-<sha256(mapId:nodeId)>` и зашифрованный журнал до записи задачи. Потеря ответа и сбой записи карты восстанавливают тот же ID. Успешную задачу не удаляют как компенсацию ошибки карты.
- Для Google Calendar внешнее событие получает детерминированный ID. Повтор сначала читает его, POST 409 тоже разрешается чтением; существующее событие не перезаписывается повтором создания. Частичная запись в несколько аккаунтов возобновляется. Явное конкурентное удаление задачи использует обычную очистку внешних копий. **Проверено контрактной симуляцией провайдера, не живым Google.**
- Повторяющаяся задача ссылается на конкретный день. При отделении/переносе экземпляра сохраняется `recurrenceOriginalDate`; Google metadata дополнено обратно совместимым полем. Старые исключения, уже перенесённые без такого поля, не всегда можно однозначно сопоставить.

Лимиты: 1000 узлов, глубина 32, 2 МБ открытого документа, вставка до 200 мыслей/100 КБ, 200 карт аккаунта, 20 серверных версий, суммарный бюджет ciphertext истории 40 МБ. Архив входит в квоту. Очистка старых журналов/квитанций и отдельный пользовательский экран управления квотой пока отсутствуют; это эксплуатационное ограничение пилота.

### Измерения

Изолированный Chrome headless, Windows на данном компьютере, 1440×1000, Vite dev + локальный PHP/SQLite, без throttling. DOM click → появление нужного элемента + два animation frame; 5 переключений. Поиск выполнялся перед замером фокуса.

| Узлов | Навигация до первого узла | Структура, диапазон | Полотно, диапазон | Фокус на ветке |
| --- | ---: | ---: | ---: | ---: |
| 200 | 872 мс | 52–139 мс | 30–98 мс | 12 мс |
| 1000 | 903 мс | 409–440 мс | 30–93 мс | 96 мс |

Первый сценарный замер с Playwright locator/scroll и параллельными процессами дал до 10,374 с на двойное переключение 1000 узлов. Он сохранён отдельно; эти числа нельзя сравнивать напрямую с DOM click-to-paint. В полотно добавлено ограничение числа видимых DOM-кнопок, геометрия дерева сохраняется. 1000-узловая Структура остаётся полной и заметно тяжелее полотна. Это не замер на слабом телефоне.

## Миграция, флаг и выпуск

Добавлена только [047_personal_mindmaps.sql](../server/migrations/047_personal_mindmaps.sql): personal_mindmaps, personal_mindmap_versions, personal_mindmap_receipts, personal_task_creations. Применяется обычным механизмом при обращении к БД. В этой работе применена только к изолированной локальной SQLite.

API: GET /mindmaps, GET /mindmaps/:id/history, PUT /mindmaps/:id, createOnly для существующего PUT /tasks/:id. Действующие сессии/CSRF/owner checks сохраняются. Дополнены resource body limit и метаданные повторяющегося экземпляра.

Флаг веб-сборки: `GENESIS_MINDMAPS=true`; по умолчанию false. Для vinext используется `NEXT_PUBLIC_GENESIS_MINDMAPS=true`. Выключение скрывает вход и не удаляет данные. Код откатывается revert; additive-таблицы остаются. Автоматический database rollback не предусмотрен.

Перед будущим выпуском требуется отдельное разрешение, текущий workflow deploy.yml, его штатный server-only backup и проверка аддитивной миграции на разрешённом снимке. После выпуска — SHA master в deploy-meta.json и /api/health. Эти операции здесь не выполнялись; SSH не использовался.

## Оставшиеся ограничения и следующая проверка

1. Разрешить расхождение «задача без даты»: нужна совместимая доменная поддержка undated task во всех существующих представлениях/синхронизации либо явное изменение продуктового критерия. Текущий пилот честно использует обязательную дату штатной формы.
2. Проверить на разрешённом Google test account: создание/повтор после обрыва, обычное редактирование без новых внешних копий, два аккаунта и read-only. Native Google Tasks creation из мысли требует отдельного безопасного протокола; оно отключено.
3. Провести screen-reader и физический мобильный тест, включая экранную клавиатуру, touch-pan, safe areas и OS text scaling. Pointer-pan, zoom, восстановление координат и переход в месячный календарь в Chrome проверены.
4. На legacy перенесённых повторениях без originalDate возможна недоступная ссылка. Нужен отдельный совместимый сценарий сопоставления; автоматически привязывать ко всей серии нельзя.
5. Ошибки исходного typecheck остаются; полный typecheck не является зелёным release gate.
6. Локальная квота браузера может быть исчерпана; UI сообщает ошибку и не обещает сохранённый черновик. Нужны эксплуатационные правила очистки журналов/квитанций и квоты истории перед широким использованием.
