# C6 — проектные ограничения, непубликуемый этап

Рабочая ветка `codex/genesis-complete-acceptance`, после F checkpoint `8276f8d`. Запрет деплоя и Android-публикации сохраняется. SSH не использовался.

## Решение и реализация

Существующий индекс `shared_project_members` применяется всеми task/query/file API. Новая политика включается владельцем пространства явно и не меняет старые права миграцией. Поддержаны роли редактирования, комментариев, просмотра, явное исключение и наследование на существующие/будущие подпроекты. Повышение в администратора сохраняет выбранную политику; при понижении ограничения восстанавливаются.

В «Команда и приглашения → Участники и права → Доступ к проектам» доступны поиск, порционное отображение правил без потери остального выбора, readonly-предпросмотр фактических прав и снятия назначений, блокировка последнего владельца, применение и устойчивый повтор после потерянного ответа. Конфликт структуры/прав сохраняет черновик. Перед закрытием страницы изменённый выбор защищён beforeunload.

Отзыв доступа атомарно обновляет индекс, назначения, Google projection links и приглашения. Открытый подтверждённо недоступный проект очищается после 401/403/404. Поиск, календарь, история, архив/корзина, карты и их версии используют актуальный индекс. История сохраняет canonical reference IDs и скрывает названия/ID закрытых проектов, задач и прежних досок. Уже скачанные файлы технически не могут быть отозваны с чужого устройства; интерфейс это объясняет.

Новые строки находятся в `shared-work-translations` для всех 14 языков, подключены к вебу и Android. Отдельные locale-work chunks сохраняют лимит существующих chunks 350000 bytes.

## Миграции и откат

069: opt-in policy, grants и receipts. 070: явное исключение из наследования. 071: sidecar scopes для удалённых карт. Старая двухколоночная таблица deletion receipts не меняется, поэтому прежний серверный INSERT при code rollback остаётся совместим. Миграции проверены на чистой SQLite со включёнными foreign keys. При будущем CI-деплое действует существующая согласованная server-only SQLite/config backup; production-БД не трогалась.

Code rollback выполняется через Git revert и штатный workflow только после разрешённого выпуска; автоматического database rollback нет. Перед откатом на сервер, не знающий ограничений C6, нужно учесть, что он не ограничивает новые потомки и role caps: разрешённый выпуск с ограничениями нельзя откатывать без проверки этой политики.
