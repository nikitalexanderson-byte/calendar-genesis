# Разовые сакральные практики и восстановление после API timeout

Изменения подготовлены отдельным PR после выпуска #264 (`a1b81824`). Этот PR не включает деплой, изменение видимости репозитория или выпуск Android. Подтверждение пользователя: за пропуск срока однократно списываются **10 Лавров**, XP и ранг сохраняются.

## Практики: сайт и Android

- Новая сакральная практика требует одно выполнение. По умолчанию доступны день создания и следующий день. После успеха практика попадает в «Завершённые», дальнейшие выполнения и напоминания не предлагаются.
- Для практики из гадания крайний срок — конец дня, следующего за исходным днём гадания. Повторное открытие старого расклада срок не продлевает; создание из истёкшего расклада отклоняется с пояснением.
- До закрытия можно изменить расписание, крайний срок и время в существующем редакторе, сохраняя три календаря ввода и часовой пояс. Web-редактор новой практики также позволяет выбрать число выполнений; после создания цель фиксируется.
- До подтверждения создания, в редакторе и в самой практике видны предупреждение о штрафе и срок. Общий текст переведён на 14 языков и используется нативным клиентом из того же JSON.
- Промежуточный день доступного окна нейтрален для дневной цели. Учитывается день своевременного успеха либо крайний срок; ежедневная серия не требует повторять уже выполненную практику.
- При сверке после истечения срока практика отображается в «Не выполнены», в журнал добавляется детерминированная транзакция `practice-expired:self:<habitId>` на −10 Лавров. Повторное открытие, повторная синхронизация и дубли журнала второй штраф не создают. Своевременная offline-отметка, полученная позднее, исправляет ошибочно рассчитанный штраф.
- Конкурентные offline-отметки не удваивают XP сверх настроенной цели. История не удаляется. Правило обнуления Лавров при удалении до 50 выполнений к конечной практике не применяется. При подключении прежней обычной привычки её законные более ранние списания сохраняются.
- Старые незавершённые практики не получают штрафы задним числом. Выполненные старые практики с распознаваемым заводским расписанием отображаются завершёнными без переписывания истории; изменённые пользователем расписания и метрики сохраняются.
- Состояния «Завершённые» и «Не выполнены» — вычисляемые фильтры поверх существующего lifecycle. На узком сайте используется один список состояний; desktop сохраняет кнопки. Android использует существующее меню с единым радиусом и целью касания 48 dp.

## API 504

Воспроизведён механизм очереди PHP-запросов: медленный shared-запрос удерживал session lock, заставляя остальные запросы того же пользователя ждать. После проверки авторизации и CSRF shared API освобождает lock до Google I/O, чтения вложений и запросов проекта. Параллельные Google-записи защищены отдельным неблокирующим lock по пользователю; HTTP batch ограничен тремя элементами.

Клиентское чтение не перекрывается собственным polling, отменяется при смене контекста и повторяется с паузой до 30 секунд. Для временных HTTP 408/502/503/504 показано локализованное пояснение и компактное действие повтора. Если доступна защищённая копия shared-данных, она сохраняется с отметкой устаревания до успешного чтения соответствующего пути. Первое видимое чтение разрешено и при открытии уже без сети, чтобы восстановить кеш; дальнейший polling ждёт возвращения сети. Записи автоматически не повторяются; черновики сохраняются. Проверки 401/403/404 по-прежнему отзывают доступ к кешу.

Точный источник единичного исторического 504 у Юры без времени запроса и серверных логов не установлен. Исправление устраняет воспроизводимую блокировку и улучшает восстановление; оно не гарантирует отсутствия инфраструктурных timeout.

## Проверки

- `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm test`, `pnpm build:beget`: результаты финального прогона фиксируются в PR. Проверены 569 web-тестов. Линтер сохраняет два прежних `no-img-element` предупреждения майндмепов.
- Android unit: **763 cases, 755 выполнены, 8 прежних opt-in skips, 0 failures/errors**. Собраны debug APK и instrumentation APK только с отдельным application ID `ru.genesis.calendar.qa.debug`; пользовательские release-приложения не удалялись и не очищались.
- API28 phone и API35 tablet: на каждом **4 функциональных сценария** — фильтры состояний и три полных restoration-сценария, включая светлую и тёмную схемы. Дополнительно на каждом устройстве **4 нативных Compose capture**: API28 — 360/390 dp, API35 — 768/1440 dp, обе схемы. Это логическая ширина Compose, а не физическое разрешение экранов.
- Найдено и исправлено реальное падение Android9 при греческих названиях: ICU не принимал `\p{IsGreek}`; используется совместимое `\p{sc=Greek}`. Проверены акценты, кириллическая/латинская локализация, сохранение одиночных греческих символов и полный Android9 flow.
- Браузер Chromium через Playwright: **360/390/768/1440 px × обе схемы**. Проверены отсутствие горизонтального overflow, минимум 44 px для видимых кнопок/списков, переходы completed/missed, закрытие после одного выполнения, SVG и действие повтора загрузки.
- PHP: второй реальный процесс читает ту же авторизованную сессию до завершения первого; CSRF сохранён. Проверены неблокирующий Google lock, shared projects/collaboration, permissions/approvals, logout/auth, bounded input/resource limits, downloads, шифрование/повтор/backup/ACL вложений. Только изолированная синтетическая SQLite; временный config удалён после проверки владения.

## Границы проверки

Физические Samsung/realme отключены. Не проверены их OEM-ограничения питания, фактическая речь TalkBack, Safari/iOS/WebKit, непрерывный двухдневный прогон по настоящим часам и поведение ещё не обновлённых установленных старых клиентов.
