# C3: нативное управление определениями полей — 21 октября 2026

## Аудит и предлагаемый срез

В Android уже реализованы типизированные значения при создании и редактировании задачи. Веб и PHP поддерживают определения семи типов, архив, историю и преемников при смене типа. Нативного управления определениями, их видимостью и историей пока нет. Следующий срез расширяет один существующий проектный экран настройками полей; остальные C3-интеграции и общий выпуск остаются обязательными.

Сервер — источник актуальных прав и нормализации. Управление разрешено owner/admin пространства; право manageProjects отдельного проекта его не заменяет. Чтение: GET `/shared/spaces/:space/custom-fields?projectId=:project&archived=true`; история: GET `/shared/custom-fields/:id/history`; preview и PUT используют существующий `/shared/spaces/:space/custom-fields`. Миграций и изменения production-БД не требуется.

Редактор должен показывать название без перевода, тип, область (этот проект/всё пространство), порядок, required/showCard/showList/archived, варианты с отдельным архивом. Архив сохраняет значения. Перед сохранением нужен реальный preview с valueCount/fingerprint/previousRevision; смена типа при наличии значений требует отдельного согласия на создание преемника и сохранение исходного поля в архиве. Исторические настройки возвращаются в черновик с актуальной ожидаемой ревизией и новым preview.

Переиспользовать зашифрованный PlanningJournal с отдельным контрактом и назначением хранилища. Точное тело PUT и operationId сохраняются до отправки и повторяются после потерянного ответа; pending-команда не заменяется новым черновиком. Подтверждение проверяет все возвращённые свойства, previousFieldId и преемника. Права перечитываются перед preview/prepare; смена аккаунта/проекта/отзыв доступа очищают живые данные и отменяют поздние ответы.

THESIS: администратор понимает влияние изменения поля до сохранения и может восстановить настройки без потери значений. OWN-WORLD: существующие STANDART light/dark, Material/Affairs, 48dp, существующие шрифты и ассеты. STORY: проект → поля → определение → preview → подтверждение → результат/история. FIRST VIEWPORT: библиотека с названием/типом/архивом; подробные настройки раскрываются после выбора. FORM: расширение существующего интерфейса, без новой UI-библиотеки.

Уточнение21 октября: общий стиль иконок/кнопок применяется одновременно к соответствующему web и native экрану C3. Самостоятельные блоки: каталог; основные настройки; отображение/обязательность; варианты; проверенные изменения; история/копии. На узком экране каталог и редактирование сменяют друг друга с системным Back, на широком — две области. Добавление, обновление, настройка, история и отмена используют общие icon actions с подсказками; основное подтверждение сохраняет короткую подпись. Неоднозначный переход типа объясняется до подтверждения.

Проверить: права пространства и свежесть контекста; все семь типов; 0/false/отсутствие; сохранение архивных вариантов; type transition; конфликт и lost reply с тем же operationId; recreation/CAS; независимый ввод календаря; обе темы × 360/390/768/1440, длинные переводы/CJK и увеличенный шрифт. Краткие списки раскрываются по пять элементов, серверные данные не обрезаются молча. Непроверенные состояния будут перечислены отдельно.

## Первый слой: чтение определений, истории и preview

Продолжение начато от сохранённого C2 checkpoint `f6c5d42` в `codex/native-field-management`. Добавлены три SDK/gateway/controller операции чтения и `CustomFieldDefinitionProtocol`. Используется существующий online account/generation/workspace guard. Каталог проверяет область пространства/проекта и типизированные определения; история проверяет тот же field/space, порядок и уникальность ревизий, допускает прежнюю область проекта внутри разрешённой сервером истории. Результат копируется, имена/варианты не переводятся и локально не нормализуются. Preview сохраняет нормализованный сервером текст, точные false/0, fingerprint/valueCount/previousRevision и обязательное обещание сохранения прежних значений.

Первый HTTPS запуск выявил отсутствующий маршрут в native allowlist: запрос был остановлен до HTTP. Разрешены только точные GET каталога/истории и POST preview, с проверенными идентификаторами и query. Новый route regression отклоняет PUT/PATCH/DELETE, посторонние параметры и traversal; разрешение записи определений отложено до реализации journal. Исходный сбой сохранён в `output/native-field-definitions/first-route-guard.log`.

Новые проверки:7 protocol cases и1 route case; дополнительно прежние9 CustomFieldProtocol cases. Есть проверка201 ревизии истории, старой области, cross-space/field подмены, дубликатов ревизии, неправильного scope/revision/типа, false/0, серверной нормализации имени и сохранения исключённых вариантов только архивными. Guard отклоняет каталоги свыше5000 и истории свыше10000 элементов; молчаливой обрезки нет. Приёмка больших реальных серверных историй и подходящая пагинация остаются обязательными.

Реальный Android HTTPS/PHP сценарий прошёл на API28 и API35: создание fixture семи определений → read/preview → задача с number0 / checkbox false / select first → переход number→text с отдельным successor и архивом исходного → исключение варианта select с сохранением в архиве → чтение полного/действующего каталога и истории → проверка прежних значений задачи → отказ постороннему аккаунту в трёх чтениях/preview. Записи выполняет только контролируемый fixture через существующий API; новый прикладной мост содержит чтение/preview. На каждой API вместе с ним повторно прошёл C2 lost-reply/recreation контроль. Логи `output/native-field-definitions/https-emulator-{5554,5556}.log`.

Полный JVM набор:630 cases,625 выполнены,5 предусмотренных opt-in skips,0 failures/errors; C1/C2 HTTP opt-in включены. Лог `output/native-field-definitions-accepted-jvm.log`. Frozen pnpm install/lint/364 tests с14 языками/build:beget прошли;0 lint errors/2 прежних img warnings,90 entry/203 visual assets. Native lint и production-origin unsigned release/R8 прошли (`output/native-field-definitions-accepted-{lint,release}.log`). ART повторно инициализировал18 существующих C1/C2 UI holders на обеих API как регрессию кандидата; это не signed startup и не выполнение C3 UI. Новый C3 протокол исполнялся в debug HTTPS сценарии. Бинарные артефакты, R8 mapping, SHA, source/log receipts сохранены отдельно от C2: `output/native-field-definitions/{artifacts,receipt.json}` и `output/native-field-definitions-runtime/receipt.json`.

C2 контроль здесь восстанавливает Compose saved state и перечитывает настоящий Keystore journal; отдельный kill/restart процесса с незавершённой management-командой этим не заявляется.

Новый пользовательский экран и новые UI-строки в этом шаге не добавлены; матрица C2 относится только к уже принятому экрану C2. Native C3 UI, role-change/late-response lifecycle, отдельно project manager без space admin, journal/CAS/replay/receipt, восстановление настроек из истории, большой серверный набор, видимость/фильтры/сортировка и общие C/G/B интеграции остаются открытыми. Signed startup/Google/физические устройства и production приёмка не выполнены. Полный C3,21 частичный ID и14 критериев K/U/L остаются открытыми. SSH не использовался.

## Второй слой: durable writer и единый экран управления

`CustomFieldEditorProtocol`, `CustomFieldEditorJournalContract` и `SharedFieldEditorService` используют отдельное назначение Keystore `field-editor` и namespace `field-definition-editor-v1`. Неполный ввод, включая незаконченный порядок и пустой заголовок, сохраняется отдельно от нормализованного сервером preview. Изменение настроек сбрасывает review/consent. Сохранение собственного ввода не требует сети; чтение сохранённых метаданных, preview/prepare/send требуют свежую роль owner/admin пространства. manageProjects её не заменяет.

До первого PUT повторно проверяются контекст, очередь задач и точное соответствие просмотренному fingerprint/preview; type replacement требует отдельного согласия. Тело/operationId и attempt marker уже зафиксированы до HTTPS. После попытки повторяетcя исходный payload без нового preview или ревизии. Полная receipt проверяет нормализованные настройки, варианты/флаги/scope/revision и predecessor/previousFieldId преемника. Неполный ответ остаётся pending; повторный отказ после неопределённого ответа не доказывает отсутствие сохранения. Pending с попыткой нельзя удалить, заменить копией или перебазировать. Явная rebase после доказанного отказа сохраняет ввод и требует нового review; история возвращает настройки в черновик с текущей ревизией. Аккаунт/generation/workspace/caller и epoch отменяют поздние результаты; отзыв доступа очищает каталог, историю, копии и видимый черновик.

Нативный экран в меню проекта owner/admin: каталог с поиском по названиям/архивом; самостоятельные блоки настроек, отображения/обязательности, вариантов, реального preview, истории и копий. Краткие списки раскрываются по пять без обрезки серверных данных. Телефон переключает каталог/редактор через Back, широкое окно показывает их рядом. Переиспользуются Affairs/Material, 48dp icon actions с доступными именами/long-press подсказками и короткое основное подтверждение. В web-менеджере согласованы эти блоки, поиск/архив и общие icon actions 44px; desktop-диалог расширяется только при открытом менеджере полей. Стек, STANDART и ассеты сохранены.

Интеграция выявила лимит bytecode существующего `SharedProjectsContent`: навигация C3 объединена с текущим tool-navigation holder, composable-подготовка сообщений полей вынесена в функцию. Поведение проекта сохранено. Первый HTTPS проход обнаружил ошибочное требование `permissions.read`: обычный snapshot имеет шесть управляющих флагов, чтение уже проверено сервером. Исправлено по реальному контракту, свежие роль пространства и проектный доступ обязательны. Два сбоя invitation fixture исправлены по отсутствующему projectId в списке и вложенному invitation envelope; PHP/production-контракт не менялся. Диагностические логи сохранены.

Полный набор:646 cases,641 выполнен,5 opt-in skips,0 failures/errors. Frozen install/lint/364 web tests/i18n/build:beget прошли:0 lint errors/2 прежних img warnings,90 entry/203 visual assets.
