# C6: нативное управление доступом к проектам

Срез после C4/PR #224 реализован и прошёл локальную приёмку исходников. Server/web C6 уже используют единый индекс доступа, явные исключения, наследование, fingerprint/CAS и receipts. До этого Android предлагал только роли участников текущего проекта. Общий остаток — 21 частичный функциональный ID и 14 K/U/L; новый публичный APK этим этапом не выпускается.

Добавлен один экран: действие «Доступ к проектам» для владельца пространства, выбор участника из существующего space settings API, поиск проектов и порционное раскрытие по пять, роли просмотра/комментариев/редактирования/исключения и явное наследование. Перед применением видны точные изменения прав, снятие назначений, будущая политика и блокировка последнего владельца. Владелец/администратор не получает ограничения скрытым понижением роли. Используются существующие STANDART/Material3 и общие disclosure/icon/tooltip-компоненты. На телефоне предпросмотр заменяет форму с понятным возвратом к редактированию; при 900dp+ условия и последствия стоят рядом.

Черновик содержит только scoped IDs, выбор правил и hashes; названия/участники/результаты предпросмотра не сохраняются. Зашифрованный journal переиспользуется с отдельным namespace и ключом account + space + target. Конкурирующий редактор сохраняет отдельную версию; cold reopen предлагает явный выбор копий, их дата и состав правил различимы. Заполненную квоту можно освободить, сохранив собственный ввод. Команда после подтверждения замораживается до HTTPS-запроса и безопасно повторяется после потери ответа. Неверный success receipt также остаётся неопределённой командой, которую нельзя удалить или заменить новой отправкой. Автоматической отправки прав из offline-очереди нет.

Перед подготовкой повторно проверяется точный предпросмотр и отсутствие старой локальной очереди; перед replay — текущий доступ владельца. Изменения fingerprint/состава назначений требуют нового видимого предпросмотра. Native protocol проверяет read/role/permission consistency и снятые назначения. Смена аккаунта/scope, отключение shared и смена sign-in состояния после запроса не возвращают поздний ответ в UI. Отзыв доступа очищает приватные названия. Offline показывает одно сообщение и действие повтора; неизвестную отправку можно повторить одной кнопкой. Причина LAST_OWNER видна и в коротком landscape.

Локальные доказательства:

- 468 JVM tests, 0 skipped/failures/errors: protocol, journal, service и UI-state, в том числе два настоящих loopback HTTP integration — C5 и C6. C6 проверяет readonly preview, CAS после добавления проекта, сохранение выбора, commit с потерянным ответом, тот же operationId/body/revision, недоступность исключённого подпроекта и наследование новым подпроектом. После теста права синтетического участника возвращены исходной политике. Google-сессия, cookies и CSRF не печатаются и не входят в tracked fixtures.
- Финальный API28: runner OK (15 tests), 14 выполненных — 6 C6 UI, Keystore storage, 4 controller, 2 route и project-menu entry. Один capture-only assumption skip. API35: runner OK (20 tests), 18 выполненных с четырьмя C4 report regression, два capture-only skip. Проверены поиск/больше пяти проектов без потери правил, LAST_OWNER, прямой retry, revoked names, смена участника/Back, cold copy picker, offline controller и AAD чужого аккаунта/участника.
- Сохранены 8 before, 88 initial и 108 confirm PNG. Обе схемы × 360/390/768/1440; короткий landscape 592; 14 языков при 390/font1.3. Первый проход имеет шесть состояний; подтверждающий дополнительно включает conflict/versions (восемь состояний). Locale-матрица проверяет rules, не все переведённые интерактивные состояния. Представительные размеры, обе темы, немецкий/font1.3, offline/pending, короткий blocker и две версии copy picker осмотрены. Один общий fix/confirm-проход; дополнительная полировка не проводилась. Видимый ripple на некоторых кадрах — состояние нажатия стандартной кнопки. Короткое окно прокручивается.
- `pnpm install --frozen-lockfile`, lint (0 ошибок, 2 прежних img warnings), 360 web tests, `pnpm build:beget`, native i18n audit и обе QA APK сборки прошли. Все 90 mandatory entry и 203 visual assets сохранены, максимальный JS chunk 349993 bytes. Web UI этим срезом не менялся; новый browser visual-проход не проводился. Полный tsc с прежними 9 ошибками не объявляется чистым.

Логи: `output/native-project-access-{final-build,install,lint,web-tests,web-build}.log`, `output/native-project-access-device-api{28,35}-final.log`; снимки `output/playwright/access-{before,initial*,confirm*}-*.png`. QA устанавливалась только как `ru.genesis.calendar.c5qa.debug` на два эмулятора; официальная GENESIS и очередь Samsung не изменялись.

Не проверены: физический Samsung, TalkBack, все IME/foldable/переведённые состояния, настоящие native Google/HTTPS, signed/R8 C6, крупные пространства, синхронизация отзыва прав со всеми offline-кешами другого устройства, Google projection/push cleanup и полный общий release flow. Уже скачанные человеком файлы отозвать невозможно; UI это объясняет. Публичный Android остаётся 2.9.0/95; C6 остаётся частичным.

Новых миграций и ручных production-БД изменений нет. Операторский SSH не использовался; публикация выполняется существующим GitHub deploy workflow. Следующий функциональный срез — native C3 поля задачи, затем C1/C2, зависимые B/E/F и общая A4/K/U/L приёмка.
