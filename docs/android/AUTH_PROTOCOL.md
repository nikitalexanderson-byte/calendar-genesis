Пути в таблице относительны `/api`. Cookie `GENESISSESSID`: Secure по конфигурации, HttpOnly, SameSite=Lax, path `/`, срок 30 дней. Изменяющие запросы используют `X-CSRF-Token`; клиент также отправляет `X-Genesis-Time-Zone`. Native HTTP-клиент должен иметь собственное защищённое cookie/session storage. Cookie Custom Tab не передаётся приложению автоматически; копирование browser cookie/скрейпинг не является решением.

Google identity scopes: `openid email profile`. Browser `purpose=services|link` и отдельный Android AuthorizationClient flow запрашивают `calendar.app.created` и `tasks`, требуют текущую сессию и явное согласие; service grant ограничен текущим primary Google `sub`. Refresh/access tokens остаются на backend. За импорт/экспорт отвечает существующий PHP Google integration, не второй Android importer.

Bindings задачи: `googleAccountId`, `googleAccountEmail`, `googleEventId`, `googleTaskId`, `googleTaskListId`, `syncAccountIds`, `googleLinks[accountId]` (`eventId`, `taskId`, `taskListId` в соответствующей модели). Не пересчитывать IDs из категории и не объединять аккаунты по email. При переносе проверить точные TS типы `GenesisTask`, `GoogleTaskLink`; содержимое задач Google не является частью encrypted workspace blob.

## Wire-format шифрования (реализован независимый codec)

Workspace key: 32 случайных байта, стандартный Base64 (`+`, `/`, `=`), не пароль. AES-256-GCM, IV 12 случайных байт для **каждого** шифрования, tag 128 бит. `ciphertext = Base64(encryptedBytes || tag)`, `iv = Base64(ivBytes)`. AAD отсутствует; KDF отсутствует. Plaintext = UTF-8 JSON из `workspaceDocument()` с projects/categories/taskListLinks и полной HabitWorkspace, включая syncMetadata. Перечень полей в `app/cloud-sync.ts` является источником истины. Codec не нормализует и не теряет неизвестные JSON-поля.

`version`, `expectedVersion`, `updatedAt` — внешние поля протокола синхронизации, не параметры AES. Текущая схема их криптографически не связывает с blob через AAD; самостоятельно добавлять AAD нельзя, это нарушит web-совместимость. Защита от stale writes обеспечивается CAS на сервере и отдельным нативным трёхсторонним merge для изменённых секций (`CloudWorkspaceSync` / `WorkspacePatch`). Реальная конкурентная запись из двух устройств ещё не проверена.

Recovery: recovery code = Base64(32 случайных байта), используется напрямую как AES-256-GCM wrapping key. Оборачиваются **сырые 32 байта** workspace key, не его Base64-строка. IV снова 12 случайных байт; wrappedKey содержит 32+16 байт. Ошибочный recovery/key/tag не возвращает пустую структуру и не создаёт новый ключ.

Реальные режимы:

- `account`/`legacy`: получить `workspace.key` через авторизованный HTTPS bootstrap; хранить локально только под Keystore-обёрткой. Серверный ключ доступен backend, поэтому называть это zero-knowledge E2EE нельзя.
- `client`: использовать существующий ключ устройства или unwrap `wrappedKey`/`wrappedKeyIv` существующим recovery code. Web затем посылает ключ на `/workspace/key`, мигрируя в account mode. Android не должен молча менять режим/ключ до реализации подтверждённого recovery flow.
- `new`: новый ключ разрешён только для подтверждённого действительно пустого нового workspace. Никогда не трактовать ошибку decrypt/HTTP/null key как разрешение создать новый vault.

`WorkspaceCipher.kt` использует JCA `AES/GCM/NoPadding`, без внешней crypto library. API возвращает bytes, чтобы не смешивать crypto с JSON/schema/merge. `encrypt()` генерирует IV через SecureRandom; deterministic IV доступен только internal для тестов. Base64 API требует Android 26+, что совпадает с целевым minSdk этой реализации. ByteArray с ключом caller обнуляет после использования; полного zeroization JVM/ART не обещаем.

Тестовые файлы: `android/app/src/test/java/ru/genesis/calendar/security/WorkspaceCipherTest.kt` и `webcrypto-vectors.mjs`. Они содержат только синтетический ключ 00…1f/контент fixture-project. Покрытие: web ciphertext→Kotlin, равенство Kotlin ciphertext с WebCrypto, recovery wrap/unwrap, неверный ключ, tag/IV tampering, malformed Base64/length, random IV, empty authenticated payload. Команда web reference: `node android/app/src/test/java/ru/genesis/calendar/security/webcrypto-vectors.mjs`. Kotlin: `gradlew.bat :app:testDebugUnitTest --tests ru.genesis.calendar.security.WorkspaceCipherTest` из android при настроенном JDK. Факт запуска фиксирует STATUS; наличие тестов не равно PASS. Это primitive interoperability, а не проверка живого аккаунта/Keystore/full sync.

## Опубликованное расширение native login

Расширение в `server/src/native-auth.php` и `server/public/api/index.php` оставляет web OAuth routes и session middleware прежними. Публичный Web OAuth client ID: `406005321419-ea3m6db70rl4uog3shtmn2v8fuavsuug.apps.googleusercontent.com`, подтверждён в Google Cloud Console. В Google Cloud также подтверждены два Android OAuth client: debug — package `ru.genesis.calendar.debug`, SHA-1 `47:45:C0:D2:1F:E4:E3:E8:1B:AA:F6:87:C3:26:04:EA:FC:26:C3:98`; release — package `ru.genesis.calendar`, SHA-1 `9A:28:AE:70:B1:93:3D:86:FF:3A:4E:F9:31:E9:24:F8:1A:44:26:BC`. Публичные client ID не являются секретами; JSON credentials и ключи не скачивались. Audience — External / In production; Google Calendar API и Google Tasks API включены.

1. Native получает `GET /api/session`, сохраняет собственный cookie и csrf в account-neutral preauth state. Затем `POST /api/auth/google/native/challenge` с `{}`, этим cookie и `X-CSRF-Token`. Сервер выдаёт `{nonce,expiresIn:300,serverClientId}`, nonce содержит 32 случайных байта Base64url. Hash/issuedAt хранится в той же session; ответ `Cache-Control:no-store`. Лимит 8 challenges на session за минуту, затем 429 и Retry-After:60. Это не глобальная anti-abuse защита; перед публичным релизом необходим HTTP/load audit существующего edge rate limiting.
2. Credential Manager использует Web client ID через `setServerClientId`, nonce через `setNonce`. Пользователь выбирает Google-аккаунт. Приложение отправляет `POST /api/auth/google/native` JSON `{idToken}` с тем же cookie/CSRF. Ни token, ни cookie не входят в URL/logs/analytics.
3. Backend до любого upsert выполняет узкую RS256 проверку через OpenSSL, получая публичный PEM certificate только по фиксированному HTTPS `https://www.googleapis.com/oauth2/v1/certs`. Google официально документирует PEM как альтернативу JWKS. Composer/сторонняя библиотека в существующем backend отсутствует; реализация не содержит собственного RSA/ASN.1 алгоритма. Независимый security review всё ещё нужен до расширения публичного использования, хотя маршрут уже опубликован с согласия владельца. `alg` должен быть RS256, RSA ≥2048 бит, подпись верна; `iss` точно Google, `aud` точно настроенный Web client ID, `exp` ещё не прошёл, `iat` не позже now+60 и не раньше challenge-60; `sub` непустой, `email_verified=true`, nonce совпадает с одноразовым challenge. `azp` может обозначать Android OAuth client; валидируется формат, но это не device attestation/allowlist приложения. Основа авторизации — проверенная Google identity и строгое Web audience. Токены ограничены 16 KiB, JSON body 20 KB. `jku`, `x5u`, `crit`, none/HS256 не принимаются; tokeninfo не используется.
4. Challenge погашается **до** разбора body/signature проверки, включая неуспешную попытку. После валидации вызывается `genesisUpsertGoogleUser(verifiedProfile, [], false)` для существующих rules/bindings, регенерируются session ID и csrf. Ответ `{user,csrf}` и обновлённый Secure cookie. Клиент только после этого делает `/bootstrap` и открывает **полученный** user.uid scope. Отменённый login оставляет предыдущий account state без подмены. Ошибки возвращают generic коды NATIVE_AUTH_INVALID (401), INVALID_REQUEST (400), RATE_LIMIT (429), TEMPORARILY_UNAVAILABLE/NOT_CONFIGURED (503); token/claims не пишутся в логи.
5. Защита от account-switch race: session generation/version на клиенте, отмена старых запросов/workers; поздний response не применяется к новому uid. Google grants не запрашиваются этим login и существующие server refresh tokens не заменяются.
6. Public certs кэшируются в существующей server session до max-age минус Age (не более 24 часов); неизвестный kid не вызывает произвольную загрузку URL и fail-closed отклоняется. После истечения cache данные запрашиваются заново. Повторный login после сетевой ошибки требует нового challenge. Cache miss на новом session выполняет bounded HTTPS fetch; глобальный shared cache можно добавить отдельно после измерений.

Standalone тесты `server/tests/native-auth.php` генерируют временные RSA keys только в памяти и не требуют config/БД/сети. Проверяются реальная подпись, forged signature, wrong aud/iss/expiry/iat/nonce, nonce replay/expiry, rate limit, unverified email, malformed/oversized token, alg confusion и token-supplied keys. Source guard дополнительно проверяет CSRF calls и наличие browser routes, но не выдаётся за HTTP integration test. Команда: `php server/tests/native-auth.php`; syntax: `php -l server/src/native-auth.php`, `php -l server/public/api/index.php`, `php -l server/tests/native-auth.php`. Portable PHP8.3.35, syntax трёх файлов и 44 standalone checks PASS. Изолированные HTTP/session тесты и реальный debug OAuth PASS до/после PR #29; release OAuth, browser regression и независимый security review не завершены.

## Native Calendar/Tasks authorization

После identity-входа Android показывает отдельное объяснение Calendar и Tasks. По подтверждению `AuthorizationClient` запрашивает оба service scope и offline access для публичного Web/server client ID. Если Google возвращает resolution, приложение запускает его через `PendingIntent`; одноразовый `serverAuthCode` затем передаётся по HTTPS в `/auth/google/native/services`. Backend обменивает код с client secret, получает профиль по access token и сохраняет tokens/scopes только если проверенный `sub` совпадает с primary `google_sub` текущей GENESIS-сессии. Email служит только профильным полем.

Identity, Calendar grant, Tasks grant и готовность синхронизации представлены раздельно. Calendar-only и Tasks-only состояния не считаются полным подключением. При `invalid_grant`, API 401 или подтверждённом недостаточном scope сервер сбрасывает/уменьшает состояние разрешений, чтобы клиент предложил reconnect. Обычное истечение access token обновляется через refresh token. Logout очищает native session, Credential Manager selection и account-scoped alarms; server tokens другого пользователя не копируются на устройство.

Источники платформенного протокола, проверенные при аудите: [Credential Manager](https://developer.android.com/identity/sign-in/credential-manager-siwg-implementation), [Google backend token verification](https://developers.google.com/identity/sign-in/android/backend-auth), [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect).

## Android auth panel (живой debug-вход выполнен)

`android/app/src/main/java/ru/genesis/calendar/auth/` содержит `AuthProtocol`, `AuthSessionClient`, `AuthController`, `AuthPanel`, `AccountSettings`, `MultiAccountPanel`, `CloudWorkspacePreview`, `CloudWorkspaceSync` и `CloudTaskSync`. Точка Compose-интеграции: `AuthPanel(app)` в настройках. Подтверждённая серверная сессия автоматически вызывает `/bootstrap`; после проверки пользователя расшифрованный account-mode документ и задачи Google импортируются в отдельный локально зашифрованный account scope. Изолированные debug-черновики не мигрируют туда. При изменениях account scope outbox отправляет только затронутые секции workspace зашифрованным CAS/merge-запросом, а задачи — существующими маршрутами Google Tasks; при ошибках pending-записи остаются локально. Отдельной кнопки «расшифровать» нет. В client-mode требуется recovery code; ошибка расшифровки не считается пустым облаком. Начиная с alpha13 APK имеет одну рабочую тему на тёплой палитре Standart; веб-настройка `theme` остаётся на сайте, но Android не переключает её и не зеркалирует.

Сеть запускается при старте приложения для восстановления сессии, после входа/выхода и при явных действиях в настройках. OAuth использует `GetSignInWithGoogleOption` button flow с nonce/serverClientId **из server challenge**, а не с локальным случайным nonce. До успешного challenge provider UI/token request не запускается. Обрабатываются пользовательская отмена, отсутствие credential/provider, недоступный сервер, TLS/network failure и rate limit; подробные исключения/токены не отображаются и не логируются. Путь/фаза/класс сетевой ошибки пишутся только в debug log без credential/cookie/claims.

Фиксированный origin `https://genesiscalendar.ru`, разрешены только явные auth/session, workspace/bootstrap, account preferences, unlink-account и task-write пути; HTTPS стандартной платформенной проверкой сертификата, redirects запрещены, обычный ответ ограничен 128 KiB, workspace 11 MB, bootstrap 24 MB, query tokens отсутствуют. Отдельный native cookie jar принимает только `GENESISSESSID` с Secure+HttpOnly и разрешённым domain/path. Cookie/CSRF/expiry сериализуются в private preferences `genesis.native.auth.v1` под существующим Android Keystore `LocalCipher` с отдельным AAD `genesis.native.auth.v1|https://genesiscalendar.ru`. Browser cookie не копируется; persistent identity/email не сохраняются. Backup уже выключен в приложении; auth не меняет Manifest.

Controller singleton ведёт generation для каждого действия: поздний ответ прежней операции не обновляет cookie/UI. Logout сначала инвалидирует предыдущие callbacks, удаляет local credential, затем пытается закрыть прежнюю серверную сессию и очистить Credential Manager state. При offline/logout failure UI прямо говорит, что отзыв на сервере не подтверждён. Это не удаляет личные данные или локальные черновики. При cold start cached identity не выдаётся за подтверждённую: приложение само перепроверяет её через `/session` и открывает облако. Полный набор race/cancellation сценариев пока NOT_RUN.

Portable PHP reproduction: set `$phpRuntime` to the extracted official runtime, then `$env:OPENSSL_CONF="$phpRuntime\extras\ssl\openssl.cnf"`; execute `& "$phpRuntime\php.exe" -n -d "extension_dir=$phpRuntime\ext" -d extension=openssl server/tests/native-auth.php`. Run `php.exe -n -l` separately for `server/src/native-auth.php`, `server/public/api/index.php`, `server/tests/native-auth.php`. No production config, DB, real identity or network is used by this standalone suite.
