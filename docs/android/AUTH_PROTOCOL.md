# GENESIS Android: фактический auth / workspace protocol

Аудит 23.09.2026. Источники: `app/cloud-sync.ts`, `app/workspace-sync-state.ts`, `server/public/api/index.php`, `server/src/bootstrap.php`, `server/src/repository.php`, `server/src/google.php`. Закрытые config, runtime-БД и токены не читались. SSH не использовался.

## Текущая авторизация и API

Production origin: `https://genesiscalendar.ru`; API prefix `/api`. Android token-login добавлен **только в локальную ветку**, не опубликован. Авторитет аккаунта — проверенный Google `sub`; `genesisUpsertGoogleUser()` проверяет `email_verified`, запрещённые identity и существующие bindings. Существующий linked Google sub возвращает владельца соответствующего workspace. Произвольный email клиента не является удостоверением личности.

| Реальный endpoint | Контракт |
| --- | --- |
| `GET /session` | `{user, csrf}`; user может быть null. |
| `GET /auth/google/start?purpose=login&return_to=/…` | Browser OAuth: случайные state + PKCE S256, сервер хранит verifier/state в PHP session; return_to только относительный путь. |
| `GET /auth/google/callback` | State одноразовый, окно 600 секунд; server code exchange; Google userinfo; проверенный sub/email; session ID регенерируется. |
| `GET /bootstrap` | Защищённая сессия; `{user, csrf, tasks, taskLists, workspace, syncWarning}`. Может вызвать серверный импорт Google Tasks/Calendar. |
| `GET /workspace` | `{workspace:{key,keyMode,wrappedKey,wrappedKeyIv,envelope}}`. |
| `PUT /workspace` | JSON `{ciphertext,iv,version,expectedVersion,…metrics}` + CSRF. Сервер CAS по expectedVersion, сам увеличивает version; конфликт не должен тихо перетирать blob. |
| `PUT /workspace/key` | `{key,wrappedKey,iv}` + CSRF; текущий backend сохраняет key в server escrow и устанавливает mode=account. |
| `GET /sync/tasks` | Сервер читает Google; возвращает tasks/taskLists/syncedAt/syncWarning. |
| `POST /auth/logout` | CSRF; завершает PHP session и удаляет cookie. Клиент должен отдельно отменить свои alarms/workers и очистить local session. |

Пути в таблице относительны `/api`. Cookie `GENESISSESSID`: Secure по конфигурации, HttpOnly, SameSite=Lax, path `/`, срок 30 дней. Изменяющие запросы используют `X-CSRF-Token`; клиент также отправляет `X-Genesis-Time-Zone`. Native HTTP-клиент должен иметь собственное защищённое cookie/session storage. Cookie Custom Tab не передаётся приложению автоматически; копирование browser cookie/скрейпинг не является решением.

Google login scopes: `openid email profile`. `purpose=services|link` добавляет `calendar.app.created` и `tasks`, требует текущую сессию и явное согласие; services ограничен текущим primary Google sub. Refresh/access tokens остаются на backend. За импорт/экспорт отвечает существующий PHP Google integration, не второй Android importer.

Bindings задачи: `googleAccountId`, `googleAccountEmail`, `googleEventId`, `googleTaskId`, `googleTaskListId`, `syncAccountIds`, `googleLinks[accountId]` (`eventId`, `taskId`, `taskListId` в соответствующей модели). Не пересчитывать IDs из категории и не объединять аккаунты по email. При переносе проверить точные TS типы `GenesisTask`, `GoogleTaskLink`; содержимое задач Google не является частью encrypted workspace blob.

## Wire-format шифрования (реализован независимый codec)

Workspace key: 32 случайных байта, стандартный Base64 (`+`, `/`, `=`), не пароль. AES-256-GCM, IV 12 случайных байт для **каждого** шифрования, tag 128 бит. `ciphertext = Base64(encryptedBytes || tag)`, `iv = Base64(ivBytes)`. AAD отсутствует; KDF отсутствует. Plaintext = UTF-8 JSON из `workspaceDocument()` с projects/categories/taskListLinks и полной HabitWorkspace, включая syncMetadata. Перечень полей в `app/cloud-sync.ts` является источником истины. Codec не нормализует и не теряет неизвестные JSON-поля.

`version`, `expectedVersion`, `updatedAt` — внешние поля протокола синхронизации, не параметры AES. Текущая схема их криптографически не связывает с blob через AAD; самостоятельно добавлять AAD нельзя, это нарушит web-совместимость. Защита от stale writes обеспечивается CAS на сервере и merge из `app/workspace-sync-state.ts`, который ещё необходимо переносить отдельно.

Recovery: recovery code = Base64(32 случайных байта), используется напрямую как AES-256-GCM wrapping key. Оборачиваются **сырые 32 байта** workspace key, не его Base64-строка. IV снова 12 случайных байт; wrappedKey содержит 32+16 байт. Ошибочный recovery/key/tag не возвращает пустую структуру и не создаёт новый ключ.

Реальные режимы:

- `account`/`legacy`: получить `workspace.key` через авторизованный HTTPS bootstrap; хранить локально только под Keystore-обёрткой. Серверный ключ доступен backend, поэтому называть это zero-knowledge E2EE нельзя.
- `client`: использовать существующий ключ устройства или unwrap `wrappedKey`/`wrappedKeyIv` существующим recovery code. Web затем посылает ключ на `/workspace/key`, мигрируя в account mode. Android не должен молча менять режим/ключ до реализации подтверждённого recovery flow.
- `new`: новый ключ разрешён только для подтверждённого действительно пустого нового workspace. Никогда не трактовать ошибку decrypt/HTTP/null key как разрешение создать новый vault.

`WorkspaceCipher.kt` использует JCA `AES/GCM/NoPadding`, без внешней crypto library. API возвращает bytes, чтобы не смешивать crypto с JSON/schema/merge. `encrypt()` генерирует IV через SecureRandom; deterministic IV доступен только internal для тестов. Base64 API требует Android 26+, что совпадает с целевым minSdk этой реализации. ByteArray с ключом caller обнуляет после использования; полного zeroization JVM/ART не обещаем.

Тестовые файлы: `android/app/src/test/java/ru/genesis/calendar/security/WorkspaceCipherTest.kt` и `webcrypto-vectors.mjs`. Они содержат только синтетический ключ 00…1f/контент fixture-project. Покрытие: web ciphertext→Kotlin, равенство Kotlin ciphertext с WebCrypto, recovery wrap/unwrap, неверный ключ, tag/IV tampering, malformed Base64/length, random IV, empty authenticated payload. Команда web reference: `node android/app/src/test/java/ru/genesis/calendar/security/webcrypto-vectors.mjs`. Kotlin: `gradlew.bat :app:testDebugUnitTest --tests ru.genesis.calendar.security.WorkspaceCipherTest` из android при настроенном JDK. Факт запуска фиксирует STATUS; наличие тестов не равно PASS. Это primitive interoperability, а не проверка живого аккаунта/Keystore/full sync.

## Реализованное локальное расширение native login (не опубликовано)

Расширение в `server/src/native-auth.php` и `server/public/api/index.php` оставляет web OAuth routes и session middleware прежними. Публичный Web OAuth client ID: `406005321419-ea3m6db70rl4uog3shtmn2v8fuavsuug.apps.googleusercontent.com`, извлечён только из публичного OAuth redirect. Нужны Android clients для package/certificate пар.

1. Native получает `GET /api/session`, сохраняет собственный cookie и csrf в account-neutral preauth state. Затем `POST /api/auth/google/native/challenge` с `{}`, этим cookie и `X-CSRF-Token`. Сервер выдаёт `{nonce,expiresIn:300,serverClientId}`, nonce содержит 32 случайных байта Base64url. Hash/issuedAt хранится в той же session; ответ `Cache-Control:no-store`. Лимит 8 challenges на session за минуту, затем 429 и Retry-After:60. Это не глобальная anti-abuse защита; перед публичным релизом необходим HTTP/load audit существующего edge rate limiting.
2. Credential Manager использует Web client ID через `setServerClientId`, nonce через `setNonce`. Пользователь выбирает Google-аккаунт. Приложение отправляет `POST /api/auth/google/native` JSON `{idToken}` с тем же cookie/CSRF. Ни token, ни cookie не входят в URL/logs/analytics.
3. Backend до любого upsert выполняет узкую RS256 проверку через OpenSSL, получая публичный PEM certificate только по фиксированному HTTPS `https://www.googleapis.com/oauth2/v1/certs`. Google официально документирует PEM как альтернативу JWKS. Composer/сторонняя библиотека в существующем backend отсутствует; реализация не содержит собственного RSA/ASN.1 алгоритма, но всё равно требует независимого security review перед публикацией. `alg` должен быть RS256, RSA ≥2048 бит, подпись верна; `iss` точно Google, `aud` точно настроенный Web client ID, `exp` ещё не прошёл, `iat` не позже now+60 и не раньше challenge-60; `sub` непустой, `email_verified=true`, nonce совпадает с одноразовым challenge. `azp` может обозначать Android OAuth client; валидируется формат, но это не device attestation/allowlist приложения. Основа авторизации — проверенная Google identity и строгое Web audience. Токены ограничены 16 KiB, JSON body 20 KB. `jku`, `x5u`, `crit`, none/HS256 не принимаются; tokeninfo не используется.
4. Challenge погашается **до** разбора body/signature проверки, включая неуспешную попытку. После валидации вызывается `genesisUpsertGoogleUser(verifiedProfile, [], false)` для существующих rules/bindings, регенерируются session ID и csrf. Ответ `{user,csrf}` и обновлённый Secure cookie. Клиент только после этого делает `/bootstrap` и открывает **полученный** user.uid scope. Отменённый login оставляет предыдущий account state без подмены. Ошибки возвращают generic коды NATIVE_AUTH_INVALID (401), INVALID_REQUEST (400), RATE_LIMIT (429), TEMPORARILY_UNAVAILABLE/NOT_CONFIGURED (503); token/claims не пишутся в логи.
5. Защита от account-switch race: session generation/version на клиенте, отмена старых запросов/workers; поздний response не применяется к новому uid. Google grants не запрашиваются этим login и существующие server refresh tokens не заменяются.
6. Public certs кэшируются в существующей server session до max-age минус Age (не более 24 часов); неизвестный kid не вызывает произвольную загрузку URL и fail-closed отклоняется. После истечения cache данные запрашиваются заново. Повторный login после сетевой ошибки требует нового challenge. Cache miss на новом session выполняет bounded HTTPS fetch; глобальный shared cache можно добавить отдельно после измерений.

Standalone тесты `server/tests/native-auth.php` генерируют временные RSA keys только в памяти и не требуют config/БД/сети. Проверяются реальная подпись, forged signature, wrong aud/iss/expiry/iat/nonce, nonce replay/expiry, rate limit, unverified email, malformed/oversized token, alg confusion и token-supplied keys. Source guard дополнительно проверяет CSRF calls и наличие browser routes, но не выдаётся за HTTP integration test. Команда: `php server/tests/native-auth.php`; syntax: `php -l server/src/native-auth.php`, `php -l server/public/api/index.php`, `php -l server/tests/native-auth.php`. Итог интеграции 23.09.2026: portable PHP8.3.35, syntax трёх файлов PASS, 44 standalone checks PASS. Обязательны последующие isolated HTTP/session tests (cookie rotation/CSRF/replay), blocked identity/linked sub существующего repository и реальный debug/release OAuth. Production не менялся.

Calendar/Tasks authorization на Android требует отдельного завершённого решения (AuthorizationClient server-auth-code exchange или безопасный session-bound browser handoff). Нельзя открывать существующий services URL в браузере и считать, что native session будет использована. Перед реализацией согласовать контракт grant handoff, сохранить scope/account intent, одноразовый code/PKCE, без токенов в callback URL. Это отдельный блокер от базового ID-token login.

Источники платформенного протокола, проверенные при аудите: [Credential Manager](https://developer.android.com/identity/sign-in/credential-manager-siwg-implementation), [Google backend token verification](https://developers.google.com/identity/sign-in/android/backend-auth), [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect).

Read-only review потока подтверждает по исходникам: challenge потребляется до разбора запроса, валидация подписи обязательна до вызова repository, browser routes не заменены, CSRF middleware вызывается первой операцией обоих native routes. Оставшиеся ограничения review:

- Per-session rate limit не защищает от атакующего, создающего новые sessions; перед публичным включением нужен проверенный edge/global rate limit, не только данный helper.
- Google certificates кэшируются отдельно в каждой session. Unknown kid при свежем cache отклоняется без force-refresh; это безопасный отказ, но может временно мешать входу при смене ключей. Сценарии реальной rotation/сети ещё не испытаны.
- `azp` проверяется по формату, не allowlist; endpoint удостоверяет пользователя Google с правильным Web audience и session nonce, а не подлинность Android APK. Нельзя использовать результат как device attestation.
- Реальные cookie persistence/regeneration, rejected CSRF, сохранность прежней сессии при отказе, linked account binding и browser OAuth regression ещё не запущены. Нужны отдельные isolated HTTP integration tests перед deploy.
- Используется собственная ограниченная JWT оболочка над OpenSSL, а не Google library. До публичного релиза обязателен независимый security review; локальный self-review не является таким заключением.

## Android auth panel (локальный код, живой вход не выполнялся)

`android/app/src/main/java/ru/genesis/calendar/auth/` содержит `AuthProtocol`, `AuthSessionClient`, `AuthController`, `AuthPanel` и `CloudWorkspacePreview`. Точка Compose-интеграции: `AuthPanel(app)` в настройках. Вход не меняет `workspaceScope`, DB, локальные задачи/привычки или alarms. Отдельная кнопка «Проверить облачные данные» явно вызывает `/bootstrap`, проверяет identity, расшифровывает account-mode blob только в памяти и показывает количества проектов, категорий, привычек, отметок, сна, настроения, наград, испытаний и серверных задач. `/bootstrap` может запустить серверный импорт Google Tasks; это не запись в локальное Android-хранилище. В client-mode требуется recovery code; ошибка расшифровки не считается пустым облаком. Полный импорт/merge и двусторонняя синхронизация ещё не подключены, что явно написано в интерфейсе.

Сеть запускается только кнопками: проверить session / войти Google / проверить облачные данные / выйти. OAuth использует `GetSignInWithGoogleOption` button flow с nonce/serverClientId **из server challenge**, а не с локальным случайным nonce. До успешного challenge provider UI/token request не запускается; текущий production 404 обрабатывается как «Нативный вход ещё не опубликован». Обрабатываются пользовательская отмена, отсутствие credential/provider, недоступный сервер, TLS/network failure и rate limit; подробные исключения/токены не отображаются и не логируются.

Фиксированный origin `https://genesiscalendar.ru`, разрешены только явные auth/session и read-only workspace/bootstrap пути; HTTPS стандартной платформенной проверкой сертификата, redirects запрещены, обычный ответ ограничен 128 KiB, workspace 11 MB, bootstrap 24 MB, query tokens отсутствуют. Отдельный native cookie jar принимает только `GENESISSESSID` с Secure+HttpOnly и разрешённым domain/path. Cookie/CSRF/expiry сериализуются в private preferences `genesis.native.auth.v1` под существующим Android Keystore `LocalCipher` с отдельным AAD `genesis.native.auth.v1|https://genesiscalendar.ru`. Browser cookie не копируется; persistent identity/email не сохраняются. Backup уже выключен в приложении; auth не меняет Manifest.

Controller singleton ведёт generation для каждого действия: поздний ответ прежней операции не обновляет cookie/UI. Logout сначала инвалидирует предыдущие callbacks, удаляет local credential, затем пытается закрыть прежнюю серверную сессию и очистить Credential Manager state. При offline/logout failure UI прямо говорит, что отзыв на сервере не подтверждён. Это не удаляет личные данные или локальные черновики. При cold start cached identity не выдаётся за подтверждённую — нужна кнопка проверки. Фактические race/cancellation/device сценарии пока NOT_RUN.
