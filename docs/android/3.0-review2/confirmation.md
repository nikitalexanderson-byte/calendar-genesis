# Подтверждение исходных замечаний второго прохода

26 октября 2026. Отдельный агент просмотрел реальные PNG и связанные исходники; новый набор концепций или открытый цикл полировки не проводился.

- R3/R4: «Шалфей» и «Структура» больше не разорваны внутри слова. Полнооконный захват устранил ошибочную интерпретацию обрезанного Compose root как overflow продукта.
- R5: Save получил основной filled-стиль; преобразование мысли в задачу — outlined. Дополнительная проверка достижимой shared callback ветки обнаружила недоведённую часть того же замечания; она исправлена в app source `442ef130` вместе с локальной веткой. Поведение callback не менялось.
- R6: ошибка локального черновика сообщает о тексте в форме, не обещает подтверждённое сохранение. Проверяется синтетический отказ store и повторная попытка.
- R8: полнооконный PNG действительно содержит окно восстановления ключа, а не только лежащий под ним список сообщений; заголовок/действие соответствуют восстановлению.
- R9: первый свежий QWERTY-кадр выявил P1: header/Close перекрывались status bar при длинном тексте. После внешнего safeDrawing-wrapper независимый просмотр подтвердил исправление. В кадре `review2-safe-insets-final` status bar занимает y=0–48px, Surface начинается около 80 px, весь Close расположен примерно 105–199 px; Save около 940–1036 px, выше QWERTY около 1090 px. Регрессия сравнивает реальные экранные bounds с текущими WindowInsets и сохраняет длинную запись.
- R10: в подтверждающем font130-кадре найдено реальное перекрытие названия узла кнопкой связи. После узкого исправления отдельный просмотр [свежего кадра](after/r10-font130/3.0-workspace-360-light-mindmap-canvas.png), runId `review2-r10-map-font130`, подтвердил: текст завершается многоточием, не попадает под кнопку, кнопка полностью видима. Source `456e0030`, debug SHA-256 `0018eb6808d0537367f6cb33e6bcc3eb1e1d873a8646ab8ee1d4ce43f48d4b23`; код сохраняет 48dp action и резервирует 56dp. Геометрическая регрессия прошла на четырёх previews в каждом из двух fontScale.

Последний сценарий сначала ошибочно сравнивал bounds с Android dimension resource 128 px; его значение не соответствовало фактической панели 48 px после изменения размера эмулятора. Исправлено измерение теста, визуальный фикс не откатывался. Результат финальных прогонов и точная версия APK приведены в [acceptance.md](acceptance.md).

Это ограниченное экспертное подтверждение исходных замечаний, без исследования с реальными пользователями и без заявления полного WCAG/TalkBack/live-интеграционного покрытия.
