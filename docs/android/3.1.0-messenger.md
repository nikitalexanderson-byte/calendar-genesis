# Сообщения GENESIS 3.1.0

## Аккаунт и режимы

На сайте и в Android используется существующая Google-сессия GENESIS. У сообщений нет собственного входа, пароля, Google OAuth scope или зависимости от флажка «Общие дела». Точный email зарегистрированного пользователя позволяет добавить контакт и открыть обычную личную переписку. Префиксный поиск по каталогу пользователей не предоставляется. Контакты принадлежат своему владельцу; Google Contacts не читается.

Обычные личные и групповые чаты синхронизируются между устройствами после Google-входа. Текст защищён TLS при передаче и secretbox с серверным ключом при хранении. Это серверное шифрование: сервис может расшифровать текст. Группы поддерживают приглашения с принятием, добавление и исключение участников, выход и передачу владения. Размер группы ограничен 50 участниками.

У каждого общего проекта может быть один чат. Право чтения/отправки проверяется через текущий project ACL на каждом запросе. Отправка требует права комментировать. Архивирование, удаление или исключение из проекта немедленно ограничивают последующие API-запросы. Название и участники определяются проектом.

## Секретные чаты

Секретный чат — переписка двух конкретных устройств. Инициатор создаёт приглашение со своего устройства; получатель принимает его на втором устройстве. Конечные устройства и отпечатки ключей фиксируются для этого чата и не заменяются автоматически при новом Google-входе.

Закрытые P-256 ключи создаются локально. Web хранит CryptoKey в IndexedDB, Android — приватный материал в Room, зашифрованном Android Keystore через существующий LocalCipher. Сервер получает только публичный ключ. ECDH → HKDF-SHA256 → AES-256-GCM использует существующий проверяемый межплатформенный формат. Отдельный контекст `messenger-secret-v1` отделяет эти чаты от старой системы; AAD связывает шифротекст с чатом, сообщением, отправителем и revision. Случайный 96-битный IV создаётся для каждого шифрования. Отпечатки устройств закрепляются локально; их изменение останавливает обмен.

Код безопасности можно сравнить вне сервиса; сохранять его не требуется. Другой вошедший в тот же аккаунт клиент не получает закрытый ключ и не может прочесть секретную историю. Очистка локальных данных, удаление приложения, выход с удалением локального хранилища или потеря устройства делают такую историю недоступной. Сервер и Google-вход не восстанавливают этот ключ.

Это собственная реализация GENESIS на стандартных криптографических примитивах, **не MTProto и не Signal**. Текущий формат не реализует Double Ratchet и не обещает прямую секретность после компрометации долговременного ключа. Независимый криптографический аудит не проведён. Нельзя заявлять о равенстве гарантий Telegram либо об аудированной защите.

## Совместимость и надёжность

`shared_private_*` и старый неизменяемый ключ аккаунта не изменяются. Прежняя история доступна отдельно. Утраченный старый ключ нельзя восстановить новым механизмом; обычные новые чаты не блокируются этим состоянием.

Команды отправки хранятся до подтверждения: web — локально в AES-GCM-конверте с привязкой к аккаунту и чату, Android — в зашифрованной Room. Повтор использует тот же ID и тот же шифротекст. Сервер проверяет автора, revision и повторную команду. Сообщения можно редактировать и удалять; пагинация и read cursor проверяются относительно конкретного чата. Текст не включается в список чатов/уведомлений. Обновление открытой переписки и списка выполняется с интервалом 5 секунд, только при видимом интерфейсе/активном lifecycle.

Миграция `087_messenger.sql` только добавляет таблицы. Старые клиенты и code rollback продолжают использовать прежние таблицы. Перед production штатный deploy должен сохранить согласованную runtime SQLite-копию. Откат кода не удаляет новые таблицы и переписку; автоматический database rollback запрещён.

## Проверки и выпуск

Изолированный PHP-тест `server/tests/messenger.php`: ACL, отсутствие зависимости от shared opt-in, шифрование cloud text в БД, идемпотентность, ревизии, блокировки, приглашения, неизменность ключей, привязка к устройствам, отзыв устройства и project membership.

Android: `MessengerRepositoryTest` проверяет отсутствие запросов ключей в обычном чате, повтор после потерянного ответа и смену аккаунта. `Messenger310Test` проверяет обычную отправку, контакты и диалог создания без повторного входа и восстановления ключа.

Матрица браузерных и нативных проверок, фактические результаты и непроверенные состояния фиксируются в отчёте приёмки перед выпуском. Фактический выпуск на сайте, Samsung и в Alpha фиксируется отдельно в отчёте 3.1.0-release-audit.md и ignored release-result.json.
