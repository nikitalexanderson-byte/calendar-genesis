# Android 3.0: личные сообщения и восстановление

Native реализация существующего протокола web/API. Backend, таблицы, production-ключи и серверные данные не изменялись. Личные сообщения доступны только при действующих разрешениях общих дел; все запросы проходят через прежнюю authenticated session и проверку её поколения.

## Ключи и совместимость

- Независимая ECDH P-256 identity, HKDF-SHA256 и AES-GCM-256; ключ личного workspace не используется вместо ключа сообщений.
- Канонический публичный JWK и fingerprint, salt/AAD сообщения и файла, URL-safe base64 без padding совпадают с `app/private-message-crypto.ts`.
- Identity записывается в зашифрованное хранилище **до** регистрации на сервере. Наличие server key без local private key требует импорта резервной копии; новый ключ поверх существующего не создаётся.
- Импорт проверяет соответствие private/public частей и серверному fingerprint. PBKDF2-HMAC-SHA256, 310000 итераций, пароль от 12 символов и формат backup совместимы с web.
- Первый зарегистрированный fingerprint собеседника закрепляется. Изменение блокирует отправку и загрузку файлов; автоматического сброса доверия нет. В интерфейсе доступен код безопасности для сверки по другому каналу.

## Долговечность и файлы

- Identity, trust pins, текст/метаданные черновиков, точные pending-команды и отдельные file chunks защищены существующим Android Keystore `LocalCipher`; plaintext body/filename не записывается в Room или SavedState.
- Один файл до 10 MiB, до 5 файлов на сообщение; wire chunks по 256 KiB. Каждый локальный защищённый Room cell не больше 512 KiB, без изменения схемы БД.
- Точная encrypted command сохраняется до сети. Lost POST receipt доказывается чтением страниц либо безопасным replay того же ID/ciphertext. Для PATCH/DELETE используется стабильный seq, ожидаемая следующая revision и сравнение ciphertext/deletion.
- После подтверждения upload повтор сообщения выполняется перед попыткой загрузить chunks: уже привязанные к отправленному сообщению файлы не перезаписываются.
- Только definitive `PRIVATE_FILE_NOT_READY` запускает recovery истёкшего непривязанного upload. Сначала проверяется сообщение и уже привязанные chunks; затем повторяются прежние IDs/ciphertext/CAS.
- При реальном конфликте другой revision пользователь может сохранить копию. Приложение сначала проверяет receipt, затем расшифровывает доступные исходные файлы и заново шифрует их для новых message/file IDs и нового AAD. Переход сохраняется в журнале; ошибка записи/перезапуск не повторяют исходную мутацию. Если исходный файл недоступен, операция прекращается с сохранением исходного журнала, без частичного удаления.
- Неподтверждённое удаление можно прекратить после сверки с сервером. Это не отменяет уже выполненное удаление. Удаление отправленной строки сохраняет независимый новый черновик.
- Очистка переписки требует подтверждения и не повторяется автоматически после потерянного ответа: новый повтор мог бы удалить уже новые сообщения.
- Autosave привязан к захваченным conversation/draft ID и revision. Запоздавший callback сохраняет текст только в исходный черновик; уже отправленный/сброшенный черновик не воскрешается в другом чате. Вход в mutex происходит в порядке UI-событий перед фоновым Room IO.
- Открытая переписка обновляется каждые 5 секунд только внутри `repeatOnLifecycle(STARTED)`, с захваченным conversation ID. Опрос сохраняет загруженную старую историю и редактор. Временная сеть не меняет зашифрованные draft/command записи; 401/403/404 скрывают текущую переписку и прекращают опрос. Declined invitation отображается отдельно от pending.

## Реальная проверка и ограничения

Финальная сборка `final-admin-lint-frozen-build.log`: `MessagingCryptoTest` 5 PASS и `MessagingRepositoryTest` 15 PASS, включая expiry/CAS-copy/disk-restart/delete-draft guards, captured-ID autosave, declined и обновление истории/отзыв доступа. APK с SHA-256 prefix `b25e` на эмуляторе: `MessagingScreenTest` 2 PASS и `MessagingInteropTest` 1 PASS. Последний расшифровал действительные TS WebCrypto message/file/Unicode-password backup fixtures именно провайдерами Android, отдельно от native roundtrip. Полные build/hash и итог линтера фиксирует общий отчёт 3.0.

`DiaryProtocolTest` 5 и `DiaryRepositoryTest` 12 PASS, `DiaryScreenTest` 4 PASS, `DiaryRoomStoreTest` large3.2MiB 1 PASS также повторены в финальной сборке/APK. Diary ciphertext атомарно разбивается на bounded Room chunks; старый single-row формат читается.

Не проверены живые production-аккаунты с двух устройств, реальное принятие приглашения/смена ролей, web↔Android передача backup/file через SAF, восстановление после уничтожения процесса во время реального upload и фактическое 24h server expiry. UI-тесты synthetic и не доказывают OAuth/production API. RU/EN новых сообщений покрыты native audit; полная переводческая и визуальная приёмка F25 на остальных 12 языках не выполнена, возможен EN fallback. Шесть пунктов release notes 3.0 имеют прямые переводы на все 14 языков; полный `native-3-translations.json` содержит одинаковые 87 непустых ключей на язык. SSH не использовался.
