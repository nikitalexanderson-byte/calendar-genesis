# C3 — пользовательские поля, непубликуемый веб-этап

Непубликуемая ветка `codex/genesis-complete-acceptance`. Поля отсутствовали в API, карточке, запросах и Android. Существующие query/saved-view predicates, task revision/receipt и server content encryption переиспользуются. C3 не закрыт до сквозной проверки и зависимых C1/C2/C5-интеграций.

Область определения: пространство либо один проект. Управление определениями — owner/admin пространства; чтение project definitions и task values требует текущего доступа C6. Типы: text, number, date, select, multi, checkbox, URL. Canonical даты не зависят от отображаемого календаря. Значения шифруются на сервере, 0 и false отличаются от отсутствия.

Первый UI-срез — существующая карточка общей задачи и управление определениями в текущем проекте. Сохраняются STANDART, обе темы и текущие ассеты. Фильтры/сортировка используют тот же серверный query engine, затем интегрируются с сохранёнными представлениями.

Архивирование заменяет необратимое удаление: определения и значения остаются видимыми в истории и могут быть восстановлены. Удалённые варианты списка становятся архивными; существующее значение не меняется. Тип поля со значениями меняется через явный предпросмотр: создаётся поле-преемник, старое архивируется вместе с прежними данными. Прямого скрытого преобразования нет. Изменение области, которое исключило бы существующие значения, блокируется с объяснением.

Миграция072 добавляет только новые sidecar tables, не меняет старые task/read schemas. Перед будущим разрешённым выпуском — штатный server-only backup, чистая миграция/foreign keys и проверка rollback. Production и SSH не использовались.

## Реализовано

API определения/preview/save/history, семь типов, обязательность, порядок и область, видимость в карточке/списке, архив/восстановление и история настроек. Число0, boolean false и отсутствие различаются. Смена типа со значениями создаёт преемника после явного подтверждения, старое поле архивируется. Удалённый вариант остаётся архивным; исходные значения не переписываются.

Управление доступно в настройках проекта владельцу/администратору пространства. Чтение определений проекта и значений задач ограничено C6. Значения, определения и версии шифруются при хранении. Переход к другому scope блокируется, если это скрыло бы существующие значения. Несовместимый перенос задачи с проектными значениями также блокируется с объяснением, сохраняя исходную задачу.

Редактор подключён к созданию и изменению общей задачи. Обязательные поля находятся вне свёрнутых дополнительных настроек. Режим даты использует текущий CalendarDatePicker, сохраняется ISO. В карточке и списке показаны типовые локализованные значения; пользовательские названия, варианты и текст остаются как введены. В журнале сохраняются снимки определений, чтобы переименования не переписывали прошлое.

Серверный query engine ищет по значениям и названиям вариантов, поддерживает типовые условия, scope полей и сортировку с устойчивыми страницами/пустыми значениями. UI подключён к проектному списку/доскам/календарю и сохранённым представлениям. Explicit missing отличается от0/false. Текст условия и фильтр не выдают доступ к проекту.

Старый клиент, не передающий customFields, сохраняет прежние значения. Повторяющиеся серии включают поля в снимок и проходят актуальную проверку при создании экземпляра. Мутация задачи, значения и audit находятся в одной транзакции. Definition preview использует fingerprint/revision; retry после потерянного ответа повторяет тот же operationId, receipt и ID поля. Черновики сохраняются при409/сети и защищены при закрытии страницы/карточки.

## Миграция, ограничения и следующий шаг

072 добавляет только sidecar tables; текущий C6 fresh-schema test выполняет весь набор миграций с foreign keys. Старый код сохраняет значения при обычном task update, но не знает новой required-политики; code rollback при её использовании требует отдельной проверки поведения. Database rollback не выполняется. Production не менялся, SSH не использовался.

Не закрыты C1/C2/C5-интеграции полей, полная нативная UI/data acceptance, физический offline upgrade и общая приёмка. Гантт сохраняет прежний отдельный режим без проектного custom-filter UI; его связанная фильтрация/отчёты проверяются в G и зависимых B. Массовое изменение custom values пока не добавлено как самостоятельное действие. Подзадачи/конверсия чек-листа не получают обязательное значение автоматически — их зависимый редактор ещё надо завершить. Последующее изменение обязательности может потребовать заполнить поле при следующем завершении задачи, сохраняя старые записи.

Следующий основной этап — C1 шаблоны (`genesis-templates-2026-10-18.md`), затем C2/C5/C4/G, зависимые B и полная нативная/общая приёмка. Запрет деплоя сохраняется.
