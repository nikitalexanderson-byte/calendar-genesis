# Фюзис: восстановление видимости входа

> Исторический отчёт PR #278. Пользователь отменил отдельное подтверждение Google и пароль Фюзиса. Текущий сценарий: [единый вход](physis-unified-login.md). Повторный OAuth из этого отчёта больше не применяется.

24 октября 2026. После активации пользователь сообщил, что под `nikitalexanderson@gmail.com` пункта нет в меню. В коде проверка допуска выполнялась только при изменении user ID и скрывала пункт при любой ошибке. Воспроизведены отсутствие входа у primary-сессии, созданной до trusted claims, и отсутствие повторной проверки после временной ошибки сети. Состояние именно пользовательского браузера не извлекалось.

## Поведение

- Для старой primary Google-сессии тестера `GET /api/physis/v1/access` по-прежнему отвечает 403 `PHYSIS_UNAVAILABLE`, дополняя его `reauthRequired: true`. Это только предложение подтвердить Google-вход. Owner ID, vault и записи не выдаются; все операции с данными сохраняют прежнюю строгую проверку.
- Подсказка доступна только при включённом пилоте, совпадении primary Google subject и точного email владельца с allowlist, отсутствии доверенного channel. Native, linked, unverified web, чужой пользователь и anonymous её не получают. Полностью недействительные старые сессии без primary identity не получают подсказку и проходят общий вход.
- В браузере появляется пункт «Фюзис» и экран «Подтвердить вход Google». Кнопка использует существующий OAuth login с возвратом в `#physis`; Calendar/Tasks scopes отдельно не запрашиваются. Прямой URL больше не перебрасывает в «Сегодня», пока проверка ещё выполняется.
- Проверка повторяется после возврата фокуса, восстановления сети и показа вкладки. Сетевые ошибки повторяются с задержкой 1–30 секунд, без параллельных запросов. Временная ошибка не размонтирует уже открытое несохранённое хранилище; явный отказ сервера отзывает доступ. Смена аккаунта отменяет старый запрос и его таймер.
- Native Android UI, auth и сборка не меняются. Новых таблиц, миграций или ручных production SQL нет.

## Проверено

- Frozen install; lint 0 ошибок / 2 прежних img warnings; 673 JS tests; 188 PHP security checks; production build с GENESIS_MINDMAPS=true, максимальный chunk 349968 байт.
- Семь новых JS-тестов воспроизводят начальный сетевой отказ, повтор, строгую обработку server hint, foreign owner, непараллельные проверки, выход во время запроса, сохранение открытого vault при временном сбое и отзыв при явном отказе.
- PHP/SQLite/HTTP проверяют старую сессию без channel/email/verified claims, подсказку только на access, закрытость private routes и отсутствие подсказки при выключенном флаге/native/linked/unverified/outsider/anonymous.
- Локальный браузер использует реальный PHP fixture с `physis-test/login?session=legacy`; endpoint существует только в loopback CLI opt-in router и отсутствует в production. Пункт меню виден, подтверждение ведёт в existing Google login с `purpose=login`, returnTo `/#physis`; после synthetic verified web login открывается vault. Реальный Google в этом локальном сценарии не подменяется: переход перехвачен только как проверка URL, а последующий login выполнен явно через synthetic fixture.
- Light/dark на 360, 390, 768, 1440 px: горизонтального overflow нет, кнопки не меньше 44px. До: `output/playwright/physis-access-before-390.png`; после: `output/playwright/physis-access-after-{light,dark}-{360,390,768,1440}.png`. Проверены изображения light360 и dark1440. Лог: `output/physis-access-recovery-browser.log`.

Не проверены: физическое устройство, настоящий OAuth двух других тестеров, screen reader и полная клавиатурная последовательность. Итог CI и production фиксируется отдельно после публикации. Прямой SSH не использовался. Деплой — прежний workflow, Android false; repository возвращается в Private после проверки.
