# Мобильные «Дела» GENESIS — аудит и проверка 12 октября 2026

Изменения относятся к веб-сайту и PWA. База: `69653f79bc04d03dd8c23cb03400ec852be591e0`; ветка `codex/mobile-web-affairs-ux`. Нативный Android, API, БД, роли, авторизация, шифрование и Google-синхронизация не изменялись. Единственная тема STANDART и её светлая/тёмная схемы сохранены.

## Фактическая структура

React 19.2.6, TypeScript 5.9.3, Vite 8/vinext; production собирается `vite.beget.config.ts`, API — существующий PHP/SQLite. `GenesisCalendar.tsx` переключает разделы по URL/hash и лениво загружает `SharedProjects`/`Mindmaps`. Общий проект, карточка и поиск находятся в `SharedProjects.tsx`; адрес и последний открытый проект сохраняет `shared-navigation.ts`. Карты используют существующий зашифрованный `MindmapRepository`.

Оформление: `globals.css`, `universal-ui.css`, `web-standart.css`, `experimental-theme.css`, заключительный `layout-refinements.css`; локальные стили общих дел и карт. Новых библиотек и шрифтов нет. Использованы существующие иконки и токены зелёного/золотого GENESIS.

## Подтверждённые проблемы и решения

| Приоритет | Экран → действие | Наблюдение до правок | Исправление |
| --- | --- | --- | --- |
| P1 | Общий проект → создать задачу | Главная кнопка открывала форму с выбранным хаос-боксом, хотя пользователь находился в проекте | По умолчанию выбран текущий проект; выбор хаос-бокса и подпроекта остаётся доступен |
| P1 | Поиск → открыть задачу → вернуться | Открытие результата очищало запрос и меняло проект/вид под редактором | Поиск и исходное представление сохраняются; URL открытой задачи указывает её настоящий проект |
| P2 | Общие/личные дела → добраться до содержимого | Сводка, предложение Google-синхронизации и настройки пустого хаос-бокса занимали несколько экранов | На телефоне эти блоки раскрываются явными кнопками; настольная компоновка остаётся развёрнутой |
| P2 | Карточка задачи → выбрать исполнителя или написать комментарий | Исполнитель и обсуждение находились после длинной формы | Исполнитель рядом со статусом; отдельные переключатели «Задача»/«Комментарии», черновики остаются смонтированными |
| P2 | Создание задачи → сохранить название | Повторный выбор типа записи и все дополнительные поля стояли перед сохранением | Один переключатель типа; сначала название и проект; даты, вложения и настройки раскрываются по необходимости |
| P2 | Карточки → изменить статус/нажать действие | Некоторые мобильные контролы наследовали высоту 32 px | Селекторы статуса и кнопки действий увеличены до 44 px; перетаскивание не требуется |
| P2 | Майндмепы → найти карту/действие | Длинные названия обрезались; ряд действий имел только иконки, подсказки требовали наведения | На телефоне полные переносимые названия и подписи действий; видимый возврат; нажатие строки структуры открывает редактор |
| P2 | Майндмепы → поиск в выбранном проекте/архиве | Проверка отсутствия результатов учитывала карты за пределами выбранного фильтра | Сообщение об отсутствии результатов рассчитывается по фактически выбранным фильтрам |

**Дизайнерское решение, а не доказанная ошибка:** список удобнее для первоначального просмотра на узком экране, чем несколько широких досок. Поэтому телефон без явно выбранного вида начинает со списка. Доски, календарь и Гант доступны; сохранённый явный выбор имеет приоритет. Пользовательское исследование предпочтений не проводилось.

## Проверки

Работа выполнена на изолированном локальном PHP/SQLite-стенде с синтетическим аккаунтом `example.invalid`. Реальные задачи не изменялись, реальные приглашения и уведомления не отправлялись. Исполнитель проверялся назначением тестового пользователя самому себе.

1. **Исходное состояние:** браузерные сценарии открытия проекта, поиска, редактирования, назначения, статуса, комментария и возврата; снимки общих/личных дел на 360/390/430/768/1440 px в обеих схемах. Каталог карт и редактор также осмотрены.
2. **Первая итерация:** снимки новых экранов выявили слишком узкую кнопку управления и унаследованные маленькие поля статуса. Исправлены размеры, группировка формы и подписи карт.
3. **Функциональная проверка:** по шесть комбинаций ширины/темы для общих дел и карт. Итоговые снимки сделаны на собранной production-версии, а не только на Vite dev.

Общие дела: создание в текущем проекте; пустое название; срок; исполнитель; статус без drag; название/описание; сохранение черновиков между переключателями; комментарий; искусственная HTTP 500 и повторная отправка; сохранение запроса; браузерный Back; проверка записи через API после reload; пустой поиск; список/доски/календарь/Гант; offline-сообщение.

Майндмепы и личные дела: новая карта; структура на телефоне; длинный текст; пояснение; дочерний узел; явный перенос в другую ветку; поиск узла; превращение мысли в обычную задачу; редактирование обычной карточкой; reload; завершение связанной задачи; браузерный Back из редактора; полотно без горизонтального скролла страницы; пустой результат с фильтром проекта.

Дополнительно: задержанный реальный запрос и loading; некорректный диапазон дат отклонён локальным API с сохранением черновика; пустой проект и роль «может перемещать, но не редактировать/комментировать» проверены **подменой локальных ответов**, без изменения прав в БД.

На всех десяти комбинациях 360/390/430/768/1440 px × светлая/тёмная схема проверены общий проект, создание, карточка, комментарии, личные дела, каталог карт, структура, полотно и редактор узла. Горизонтального скролла всей страницы и ошибок JavaScript не обнаружено. Локальный горизонтальный скролл досок/полотна сохранён.

**PWA:** production service worker зарегистрирован вручную на localhost (приложение намеренно не регистрирует его на локальном preview). Проверены контроль страницы worker-ом, полная offline-перезагрузка с защищённой копией общего проекта и восстановление после подключения. Это не установка PWA на физическом телефоне.

## Автоматические проверки

- `pnpm install --frozen-lockfile` — успешно.
- `pnpm lint` — успешно.
- `pnpm test` — 166/166, включая аудит 14 языков.
- `GENESIS_MINDMAPS=true pnpm build:beget` — успешно, включая offline precache и бюджет JS. Главный chunk около 349 KB, лимит 350 KB не увеличен. Блок Google-подключения выделен в ленивый компонент для соблюдения лимита.
- `tsc --noEmit` — 27 существующих ошибок. Сравнение с исходным `origin/master` через TypeScript compiler host даёт идентичные имена файлов, коды и тексты ошибок; новых ошибок нет. Полностью зелёной проверку типов считать нельзя.
- 558 исходных ассетов совпадают побайтово. Исторический source-slot audit остаётся красным; его расхождения идентичны исходному `master`. Baseline не изменялся.

## Файлы и воспроизведение

Логика/компоновка: `SharedProjects.tsx`, `SharedTaskSchedule.tsx`, `Mindmaps.tsx`, `GenesisCalendar.tsx`, `WorkspaceHeader.tsx`, `InboxToolbar.tsx`, новые `MobileDisclosure.tsx` и `GoogleConnectNotice.tsx`. Стили: `layout-refinements.css`, `mindmaps.css`. Четыре новые подписи добавлены в 13 нерусских UI-словарей. Native-файлы и backend не изменялись.

Сценарии: `scripts/mobile-web/{seed,verify-shared,verify-mindmaps,verify-edge-states,verify-visual,verify-pwa}.mjs`. Требуется изолированная fixture из `scripts/mindmaps/fixture.php`, авторизованный `output/browser-state.json`, доступный Playwright через `PLAYWRIGHT_PACKAGE`, `GENESIS_MINDMAPS_TEST=isolated`. Dev-стенд — 127.0.0.1:4340 с PHP на 4341; production preview — 4342 с тем же локальным proxy. `seed.mjs` создаёт синтетический общий проект и отказывается работать с аккаунтом вне `example.invalid`. Сценарии карт используют исходный личный тестовый проект `p-pilot`.

## Непроверенное и публикация

Не проверены физический iPhone, Safari, реальная установка PWA, клавиатура/жесты физического Android, живой Google OAuth/Calendar/Tasks, реальные приглашения и все комбинации пользовательских прав. Автоматическая проверка отклонила команду USB-подключения стенда и запуска Chrome на realme с причиной `blocked by policy`; обход не выполнялся. Эмуляция Chromium не выдаётся за физическое устройство или пользовательское исследование.

Публикация — существующий `.github/workflows/deploy.yml`, с `GENESIS_DEPLOY_ANDROID=false` и сохранением `GENESIS_MINDMAPS=true`. После merge обязательны SHA в `/deploy-meta.json`, успешный `/api/health` и проверка сохранения APK 2.8.0/80. Ручной SSH не использовался. Откат кода — `git revert` merge и штатный CI; восстановление БД не требуется.
