### Удаление и срок хранения вложений: uploader и owner различаются

- **Явное удаление работает:** пользователь с правом редактирования задачи отправляет `removeAttachmentIds`; [shared-projects.php:1591](../../../server/src/shared-projects.php#L1591) проверяет write-доступ к проекту, [строка 1730](../../../server/src/shared-projects.php#L1730) вызывает обработчик файлов. [shared-task-attachments.php:70](../../../server/src/shared-task-attachments.php#L70) проверяет принадлежность ID этой задаче, [строка 80](../../../server/src/shared-task-attachments.php#L80) выполняет `DELETE`. Native показывает удаление только при `canEdit`: [SharedTaskFilesPanel.kt:109](../../../android/app/src/main/java/ru/genesis/calendar/ui/SharedTaskFilesPanel.kt#L109). Это право редактора задачи, не отдельное право первоначального загрузившего.
- **Uploader у файла отдельно не хранится:** [039_shared_task_attachments.sql:2](../../../server/migrations/039_shared_task_attachments.sql#L2) содержит `task_id`, зашифрованные имя/байты, MIME, размер и дату; `uploader_id`/`user_id` в таблице нет. `task_id` имеет `ON DELETE CASCADE`, поэтому окончательное удаление задачи удаляет её вложения. Перемещение в корзину само по себе ещё не окончательное удаление.
- **Удаление аккаунта не гарантирует удаления всех ранее отправленных файлов:** [repository.php:1482](../../../server/src/repository.php#L1482) сначала вызывает подготовку shared-данных. [shared-projects.php:1889](../../../server/src/shared-projects.php#L1889) передаёт owned-проект другому участнику, если есть преемник; без преемника удаляет проект. [022_shared_projects.sql:75](../../../server/migrations/022_shared_projects.sql#L75) для `shared_tasks.created_by` использует `ON DELETE SET NULL`. Поэтому при сохранении общего проекта/задачи файл продолжает существовать после удаления загрузившего пользователя или ухода/удаления прежнего owner. Прямого удаления вложений по uploader в этой схеме нет.
- **Owner без преемника:** удаление проекта/пространства ведёт к каскадному удалению задач и их файлов через [022_shared_projects.sql:68](../../../server/migrations/022_shared_projects.sql#L68) и migration 039. **Owner с преемником:** передача проекта сохраняет рабочие данные проекта, включая файлы; нельзя обещать их стирание только от факта удаления аккаунта прежнего владельца.
- **Отложенная очистка:** [shared-maintenance.php:9](../../../server/src/shared-maintenance.php#L9) окончательно удаляет просроченную корзину, а [строка 18](../../../server/src/shared-maintenance.php#L18) удаляет файлы проектов, закрытых 30 дней назад. Реализация предназначена существующему cron; фактический запуск cron в production не проверен. У активного/сохраняющегося общего проекта без явного удаления файла фиксированного срока удаления содержимого этим кодом не задано.
- Прежние E2E-файлы имеют другую схему: [056_private_message_files.sql:4](../../../server/migrations/056_private_message_files.sql#L4) каскадно привязывает их к переписке, sender и сообщению; удаление файла каскадно удаляет части. [shared-private-messages.php:279](../../../server/src/shared-private-messages.php#L279) хранит ciphertext частей, а [строка 269](../../../server/src/shared-private-messages.php#L269) очищает не привязанные к сообщениям загрузки старше суток.

**Оговорка для публичного объяснения удаления:** `/delete-account` достоверно описывает частичное удаление дневника, но не объясняет сохранение общих задач/файлов после передачи owner. Нельзя на основании этой страницы или этой проверки утверждать, что удаление аккаунта немедленно стирает любой файл, когда-либо загруженный этим аккаунтом, из всех общих проектов и резервных копий. Данный отчёт не вносит правки в тексты/схему хранения.

## `/delete-account`: частичное удаление действительно предусмотрено

## Health: разделить native и web

**Специализированных native Physis-экранов тренировок, рациона/калорий и массы тела в проверенном Kotlin-коде не найдено.** Поиск `physis|физис|nutrition|fitness` по `android/app/src/main/java` и манифесту нашёл только темы советов в `DailyAdviceProtocol.kt`. Произвольная привычка с названием о тренировке не считалась фитнес-модулем.

## Классификация выводов и пределы

1. **Уверенное расхождение:** Files and docs не выбраны, хотя Android отправляет серверу полные PDF/Office/текстовые вложения общих задач; дополнительно передаётся текст источников импорта и метаданные документов.
2. **Уверенное соответствие в коде:** страница удаления содержит частичное удаление дневника, обеспеченное отдельными API; Ads = Yes поддерживается native/web рекламными блоками. **Ограничение удаления:** общие файлы могут сохраняться после удаления загрузившего/owner при сохранении проекта; публичная страница этот случай не объясняет.
3. **Подтверждённая возможность, неоднозначная обязанность раскрытия:** произвольные файлы/видео в прежних E2E-чатах. Не объявлять Photos-only MIME-ограничением; не объявлять Videos mismatch без проверки исключения E2E.
4. **Разделение платформ:** полный Physis fitness/nutrition найден в web, не в native. Общие native советы требуют отдельного внимания при оценке широты Health declaration.
5. Не проверялись live OAuth, production upload/delete, account/region gates, другие распространяемые APK, полное SDK/transitive дерево, Crash logs/Diagnostics и все финансовые потоки. Статусы Actioned/Need attention из Console не являются доказательством соответствия исходников.

Для терминов проверено официальное [руководство Google Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en) 30 октября 2026: документы и их имена входят в Files and docs; для unreadable-to-developer E2E существует исключение из собираемых данных; ожидаемый инициированный пользователем обмен и обработка подрядчиком имеют отдельные исключения из sharing. Эти исключения не распространяются автоматически на server-readable вложения. Декларация охватывает практики всех распространяемых версий пакета; решение о форме должно учитывать этот дополнительный охват.
