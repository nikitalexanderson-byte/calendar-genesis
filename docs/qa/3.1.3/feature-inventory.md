# Genesis Tasker 3.1.3 — реестр функций Android

Дата инвентаризации: 30 октября 2026. Кандидат: `3.1.3 / 120`, release package `ru.genesis.calendar`. Ветка `codex/v3.1.3-today-trackers`, исходная база `3b92293b347f1a25212612c0458ea691090f3041`. Изменения ещё не зафиксированы одним итоговым commit, поэтому этот файл не удостоверяет идентичность финального APK.

Реестр составлен по текущим маршрутам `GenesisApp.kt`, `MobileWorkspaceShell.kt`, `MenuSwipeNavigation.kt`, `SettingsSubmenus.kt`, экранам и существующим тестам. Историческая матрица `docs/android/3.0-function-matrix.md` использована как список для сверки, а не как свидетельство PASS версии 3.1.3. Доступность функции в коде и наличие тестового класса не означают, что сценарий выполнен. Все строки новой матрицы начинаются с `NOT RUN`, кроме явно отсутствующих возможностей с `N/A` и причиной.

Единица реестра — отдельный проверяемый пользовательский результат. Кнопки, поля, жесты и подтверждения одного результата перечислены в одной строке; разные результаты имеют разные ID. Для каждой строки обязательны применимые этапы: найти → открыть → изменить → проверить валидацию/отмену/повторное нажатие → сохранить → повторно открыть → перезапустить → проверить связанный экран/синхронизацию. Проверка только открытия экрана не закрывает строку. Во время обхода установленного приложения обнаруженные дополнительные действия добавляются с новым ID; полноту фактического обхода ещё требуется подтвердить.

## Устройство и архитектура

- Native Kotlin / Jetpack Compose Material 3. UI не загружается как WebView. Общие каталоги, локализации и оригинальные изображения копируются в assets без замены.
- `minSdk=26`, `targetSdk=37`, compile SDK `37.2`. Debug-пакет при текущей приёмке: `ru.genesis.calendar.v313.debug`; он имеет отдельные sandbox, Room и Keystore и не доказывает обновление production package.
- Room `genesis.db`, schema version 1; локальные задачи/документы шифруются через `LocalCipher`, аккаунты разделены workspace scope. DataStore/локальные настройки, encrypted outbox, CAS/конфликты и периодический WorkManager sync проверяются отдельными сценариями.
- Сервер — существующий PHP API/SQLite; web — Next.js/TypeScript. Основные визуальные изменения относятся к Android. Общие новые возможности Оракула явно поручены для сайта и приложения; совместимость данных проверяется в обоих клиентах.
- Основной агент использует подключённый Realme RMX5000 с фактической шириной 360dp. Android API, сборка ОС, APK hash, run ID и конкретные результаты добавляются после аппаратной проверки. Samsung сейчас не является подключённым доказательством; пользователь сообщил о вылете при завершении задачи именно на Samsung.
- Внешние интеграции по коду: Google Sign-In/Credential Manager, Google Calendar/Tasks, закрытая совместимость Yandex, Google Play In-App Updates, браузерные ссылки и системные SAF/share/уведомления. Наличие SDK не доказывает живой интеграционный тест.

## Как читать результаты

`test-matrix.csv` — текущий источник статусов, ID совпадают с этим реестром. Строка с синтетическим gateway не закрывает живые Google/Play/двухаккаунтные интеграции. Старые доказательства3.1.2 служат baseline, не PASS3.1.3. Размеры390/768/1440, полученные сменой Compose density на Realme, помечаются как виртуальные viewport, не реальные планшеты. Обновление отдельного `.v313.debug` не закрывает SYS04.

Перед объявлением100% функций QA-проверки должны подтвердить полный обход экранов/диалогов/контекстных меню и отсутствие неучтённых действий, обязательные строки CSV не должны оставаться FAIL/BLOCKED/NOT RUN, а итоговый commit/APK hash должны совпасть с release-manifest.
