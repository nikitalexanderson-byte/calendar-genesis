# C4 — командные отчёты: аудит и решение

Server/web C4 реализованы в рабочей ветке после C5 —5c74efb. Полный ID C4 остаётся открытым для native, G2/G4 и общей приёмки; публикация и Android release до её завершения запрещены.

Существующий `shared-overview.php` даёт счётчики текущего состояния, но не cycle/stage time. `shared-task-query.php` уже содержит общие ACL, predicates, сохранённые представления и restart-on-change; отчёт и точные переходы должны использовать их. Число задач не означает ёмкость/занятость участника. Именовать произвольное C3-число points/часами нельзя; G2 добавит собственные единицы.

Один новый экран — окно отчёта текущего проекта с сохранёнными условиями исходного списка, возможностью явно выбрать пространство, календарным периодом и точными paged task selections. Текущее состояние отделяется от истории выбранного периода. Все показатели используют полный разрешённый набор; snapshot token фиксирует asOf, фильтры и версии. Изменившаяся выборка или права требуют обновить отчёт, а не подменяют drill-down.

Cycle time определяется явно: последний непрерывный интервал от наблюдаемого входа в выбранный незавершённый статус до подтверждённого завершения. Архив/корзина/перенос или неизвестный участок прерывают этот интервал; время вне действующей задачи не выдаётся за этап работы. Время этапов — фактическое прошедшее время только подтверждённых незавершённых состояний, с отсечением по точным границам периода в заданном timezone. Возраст текущих открытых задач использует сохранённую дату создания; неизвестная/некорректная дата не превращается в0.

Новый audit snapshot сохраняет реальное состояние задачи и revision внутри той же write transaction, без новой таблицы и без клиентского флага. Существующие события с каноническими ссылками и доказуемой семантикой можно использовать; неоднозначные старые участки остаются unknown. C5 не воспроизводит исторические события и не создаёт новые report snapshots. Исходные import sidecars не считаются подтверждёнными переходами GENESIS. Динамика относится к выбранным существующим задачам; до начала доступной истории показывается отсутствие данных, с отдельной частичной полнотой и переходом к неизвестным задачам.

## Реализация

`shared-reports-history.php` вычисляет интервалы отдельно от API; `shared-reports.php` использует существующие C6/C3/B5 scope/predicate/view, полный разрешённый набор и временные ID-таблицы. Новая миграция не нужна. Audit details дополняются доверенным `reportState` внутри исходной транзакции; старые клиентские payloads продолжают работать. Принятые no-op записи, меняющие revision, сохраняют внутреннее наблюдение без пользовательской активности, notification или automation. Из `reportBefore` сохраняется только проверенное серверное состояние; сам внутренний параметр удаляется.

POST `/api/shared/reports`, `/api/shared/reports/tasks` и `/api/shared/reports/check` требуют пользователя и существующей CSRF-защиты. Actor-bound зашифрованный token фиксирует asOf, условия, scope/query versions, audit и определения. Смена прав, статусов, полей, представления или задач требует refresh. Read-only check проверяет метаданные без повторной загрузки страниц задач. Drill-down пересчитывает ту же выборку в транзакции, возвращает страницы100 и точный total. Произвольный metric не превращается в неотфильтрованный запрос.

Окно открывается из панели проекта и наследует его фильтры, включая C3 и календарный диапазон. Есть выбор текущего проекта/всего доступного пространства, дополнительные фильтры, отдельный календарь периода, timezone, Gregorian January/March и month/year presets. Счётчики, stage seconds, среднее/медиана, возраст, участники и дневная динамика открывают точные задачи. Открытие карточки повторно проверяет актуальное чтение проекта и задачи. Изменение условий блокирует старые переходы; ошибка сохраняет условия. Offline очищает серверный результат. Проверка изменений выполняется при focus/visibility/shared updates и раз в30 секунд.

Новые47 фраз переведены на13 нерусских языков; установленные термины сохранены. Android web-i18n и серверный catalog экспортированы существующими генераторами. Смена языка не сбрасывает условия и не запускает повторный initial report.

- Frozen install, полный lint:0 ошибок,2 прежних предупреждения img.365/365 web tests. `build:beget`:90 mandatory precache,203 visual assets, largest JS349908 bytes при лимите350000.
- 33 самостоятельных PHP suites на свежих изолированных БД, включая три новых C4. Проверены независимые stage/cycle intervals, missing entry, reopen, archive, revision gaps, current mismatch, same-instant0, invalid timestamps, legacy names/definition ambiguity, DST23h и реальные timezone period clipping (Europe/Berlin/Pacific/Kiritimati).
- Каждый API metric проверен на совпадение count/точной выборки.105+ continuation, actor/revoke/stale tokens, скрытые проекты/метаданные, C3 `0`/`false`, сохранённые/несохранённые views, три календаря и неизменность ISO-границ подтверждены. Новые записи C1/C2/bulk/approval/archive/move сохраняют наблюдения; исторический C5 не создаёт их.
- Существующие bulk gates:10001 задач,10000 изменений +один конфликт,6000-node branch, bounded reports и16MiB peak memory. Это регресс bulk; большой10-летний C4 report на таком наборе отдельно не заявляется проверенным.
- Браузер, реальный HTTP→PHP→SQLite: текущие/пустые/архивные выборки, пагинация108 задач, выбранное время→исходная карточка и user XSS-as-text. Обе темы ×360/390/768/1440: переполнения страницы/диалога нет; широкие таблицы прокручиваются внутри.14 языков на390px: черновик сохранён, reportReloads0, непереведённых новых фраз нет.
- Браузерная конкурирующая правка очищает устаревший результат и drill. Offline очищает серверные данные, refresh после сети работает. Viewer/editor читают разрешённые задачи и не видят закрытый проект/метаданные; после отзыва grant окно закрывается. Outsider получает404.
- Escape возвращает focus кнопке отчёта; Enter открывает окно повторно, Tab остаётся внутри native dialog. Reduced-motion режим проверен.
- Сохранены8 PNG до,32 PNG после для основных разделов и4 locale PNG в `output/playwright/c4-*`. Detector:0 замечаний. Общий `tsc --noEmit` сохраняет ровно8 прежних ошибок вне C4; clean tsc не заявляется.

## Открытая приёмка

До интеграции G2 оценки явно отсутствуют; C3 числа не выдаются за points/часы. Native UI/протоколы6–7/offline upgrade, запуск отчёта из всех будущих B/G-точек входа, G4-история, крайне большие многолетние отчёты на production-подобных объёмах, физические Android-устройства/экранные дикторы, production PHP/runtime и итоговые K/U/L/экономика пока не проверены. Нет migration/DB rollback: структура БД не менялась. Production, master и Android release не менялись; SSH не использовался.
