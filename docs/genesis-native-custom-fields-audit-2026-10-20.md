# C3: пользовательские поля в нативной карточке задачи

Следующий срез после native C6/PR #225. Server/web C3 уже поддерживают семь типов, определения пространства/проекта, архив и преемников, историю, поиск/фильтры/сортировку, шаблоны/автоматизации и импорт/экспорт. В Android полноценные определения приходят в project snapshot, но карточка задачи их не показывает. C5 уже имеет отдельные defaults/mapping controls; G3 знает ссылки `custom:<id>`. Необходимые данные и существующий task outbox можно переиспользовать. Остаток — 21 частичный функциональный ID и 14 K/U/L.

Первый UI-экран — существующая карточка общей задачи. Показ и редактирование text/number/date/select/multi/checkbox/url, обязательные поля вне скрытых дополнительных параметров, необязательные под стандартным раскрытием; архивные значения доступны только для чтения. Пользовательские названия/текст/варианты сохраняются без перевода, системные типы/валидация/действия используют существующие 14 языков. Число, выключенный флажок и отсутствие значения различаются. Ссылки открываются только явным нажатием и для http/https.

Нужен ограниченный typed protocol определений/значений и отдельный diff полей внутри уже существующего task draft. Отправлять только изменённые IDs; null очищает, отсутствие ключа сохраняет. Не затирать неизвестные и архивные значения при правке других свойств, обновлении определений и явном rebase. Удалённые варианты, старые типы и непереносимые правки должны оставлять понятный локальный конфликт с возможностью сбросить именно свой ввод. Смена календаря отображения не переопределяет введённую дату: собственный input mode/context, канонический ISO и существующий AuthorDatePicker.

Текущий SharedOfflineStore уже шифрует task command целиком и замораживает requestId до отправки. Новое тело `customFields` должно пройти этот путь без переписывания старой очереди. Typed server rejection должен оставаться AuthFailure, чтобы работал текущий first/replayed rejection flow; понятный C3 code нужен UI. Success receipt должен подтверждать значения отправленного patch, включая null/0/false, прежде чем pending command удалится. При неполном/malformed ответе сохраняется исходная команда, а не создаётся новая.

Проверить независимость priority/checklists/G2 estimates, C6 readonly/архив/pending, stale revisions/изменение определений, неизвестные значения и старый outbox. Реальный локальный PHP/HTTP round-trip, пропавший ответ/receipt и три календаря проверяются отдельно от Google/HTTPS и физического устройства. Перед UI-правками сохранить baseline существующей карточки; затем обе схемы × 360/390/768/1440, короткое окно и локали. Используются текущие STANDART/Universal UI, без новой библиотеки, миграций и ручных production-БД изменений.

Нативное создание задач, управление определениями/историей, list visibility, фильтры/сортировка и остальные C/G/B-интеграции остаются следующими частями C3. Одна карточка не закрывает ID и не означает выпуск нового публичного APK. Операторский SSH для аудита не использовался.

## Реализация карточки и локальная приёмка

Существующая карточка теперь связывает полный project catalog с семью native controls. Обязательные поля показаны сразу, остальные — под общим раскрытием и порциями по пять; широкая форма использует две колонки. Ноль, false и null различаются. Значения архивных определений доступны для чтения; прежний архивный вариант можно сохранить или снять, недоступные собственные изменения явно сбрасываются. Пользовательские названия, варианты и текст не переводятся. Ссылка открывается только явным нажатием после проверки http/https.

Сохраняется один task save/outbox. В PATCH включаются только изменённые custom IDs, локальные calendar/draft metadata на сервер не уходят; pending identity response объединяется с прежними значениями. Неполный success receipt не удаляет зашифрованную команду. Старые команды и requestId не переписываются. Обновление карточки после конфликта сохраняет собственные правки пользовательских полей и оценок. Ошибки C3 переводятся и при первом отклонении, и в существующем окне pending retry. Малформированные определения/сохранённые metadata показывают восстанавливаемую ошибку и блокируют сохранение вместо падения формы.

Input mode/context инициализируются из UiPreferences.input, системного time zone и начала года; сохраняются в локальном task draft и переживают explicit rebase. UI проверяет выбор одной ISO-даты через все три календаря независимо от display preference. После сохранения сохраняется выбранное представление ввода. Priority/checklists/G2 estimates не заменяются пользовательскими полями.

- Полный JVM-набор: 489 tests, 0 failures/errors/skips. Включены реальные loopback HTTP/PHP C3 patch/replay/conflict, C5 import/export/undo и C6 grants/revocation/CAS. Это синтетические аккаунты локального fixture, не Google/production HTTPS.
- Workspace/outbox instrumentation: 28 выполненных сценариев на API28 и API35; три capture-only entry пропущены при обычном запуске. Исправлены два assertions/scrolling в новом тестовом harness; API35 transient filter timeout отдельно перепроверен. Финальные шесть C3 UI и три encrypted-store сценария повторно прошли на API35 после последней native правки.
- Baseline — 8 native originals; валидные initial и confirm матрицы — по112 кадров: обе схемы ×360/390/768/1440, font130, 14 языков (required/error), семь основных состояний формы. Override640×480 на API28 возвращал чёрные pixels при живом semantics tree;28 таких кадров перенесены в custom-invalid-display-* и не считаются доказательством. Повтор через system rotation settings дал14 читаемых portrait кадров без фактической смены ориентации; они также исключены и сохранены как custom-invalid-rotation-*. Настоящий landscape остаётся непроверенным.
- Frozen install, lint (два прежних img warning), 360 web tests, i18n audits и build:beget проходят. Debug/test и release/R8/lintVital компилируются; release build 3m20s, unsigned APK SHA256 861c3daa6b3a5fe38594079842d08bbf1565acf7645620f295bf9a5ff21200c4. APK не подписан, не установлен поверх официального и не опубликован.

При обязательной browser-проверке найден отдельный дефект публичной страницы входа: светлая бумажная карточка наследовала белый ink тёмной темы. Исправлен только её foreground #132426. Сохранены 8 production-before и 8 build-preview-after снимков на 360/390/768/1440 в обеих схемах; overflow отсутствует, вычисленный heading foreground подтверждён. Preview работает без PHP и закономерно показывает сообщение о недоступном API; живой Google-вход по нему не заявляется. Старый preview, открытый до обновления build assets, сохранён отдельно как c3-web-stale-preview-*.

Не подтверждены: физический Samsung, подписанный/R8 runtime и Google-вход/синхронизация, настоящий landscape и полная device/system-bar обвязка production Activity, управление native definitions/history, создание с обязательными полями, list visibility, фильтры/сортировка и сквозные C/G/B-сценарии. Независимого finish review в этом срезе не было. Общий остаток — 21 частичный функциональный ID и 14 K/U/L. Нет новых миграций, ручного изменения production-БД или операторского SSH; публикация только через deploy.yml.
