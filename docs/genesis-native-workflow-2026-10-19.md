# G3: нативный процесс и WIP-лимиты

Новый экран Android «Процесс и лимиты» добавлен для выбранного общего проекта. Он использует опубликованный серверный контракт и существующие компоненты GENESIS Affairs. Нативной части этого экрана прежде не было. Работа продолжает [аудит](genesis-native-workflow-audit-2026-10-19.md); промежуточный [checkpoint](genesis-native-workflow-checkpoint-2026-10-19.md) сохранён как история.

## Поведение

- Управляющий настраивает лимит активных задач каждого статуса, обязательные основные и пользовательские поля, разрешённые переходы и роли. Нулевой лимит отличается от отсутствия лимита. Правила не выдают базовое право изменять задачи и не включают планирование спринтов. Владелец должен сохранять безопасный путь входа и завершения.
- Читатель видит настройки, точные счётчики и историю без управляющих действий. Защищённая offline-копия доступна только для чтения. При отзыве доступа названия и локальный ввод скрываются с экрана, сохранённый черновик не уничтожается.
- Черновик автоматически сохраняется в отдельном зашифрованном workflow-журнале. Можно сохранить промежуточный незаконченный ввод, восстановить его, сохранить конфликтующую копию и явно выбрать продолжение. Обновление чужой версии требует явного согласования; ссылки на удалённые статусы/поля не исчезают молча.
- До отправки проверяются свежие права, версия, каталог и прежняя очередь задач. Тело команды и UUID сохраняются до HTTP. Неопределённый ответ допускает повтор той же команды; новая команда не заменяет её. Typed workflow-отказы остаются совместимы с прежними ветвями обработки task outbox.
- История загружается страницами. Сохранены входы из проекта, архива и корзины для исправления правил перед восстановлением. Настройки и история не раскрывают содержимое задач, участников и лишние значения пользовательских полей в локальной проекции.
- На телефоне разделы идут вертикально; в широком окне навигация расположена слева. Формы имеют ограниченную ширину. Используются обе схемы STANDART, существующие иконки и подсказки. Пользовательские названия проекта, статусов и полей не переводятся как интерфейсный текст.

## Проверки исходников

- Debug-приложение и instrumentation APK собраны для отдельного `ru.genesis.calendar.g1qa.debug`. JVM: 343 теста, 0 failures/errors, включая 19 workflow-проверок.
- Девять сценариев workflow прошли на API 28 и API 35: viewer, WIP 0, восстановление после неопределённого ответа, отзыв доступа, offline read, 131 версия истории, прежняя очередь задач, конфликт revision и сохранение промежуточного пустого набора ролей.
- На обеих API проверены реальные Android Keystore/SharedPreferences: привязка шифротекста к аккаунту, проекту и purpose, один CAS-победитель, конфликтующие копии и полное завершение/перезапуск процесса с той же pending-командой. Прежний planning-журнал прошёл аналогичные проверки, включая restart. Использовались только случайные QA-аккаунты; очистка затрагивает только их ключи.
- Release APK с R8 собран локально. Он не устанавливался в основной профиль и не публиковался. Runtime официального выпуска этим не проверен.
- Обязательные web gates повторены: frozen install, lint без ошибок (два прежних `img`-предупреждения), аудит переводов/352 теста и `build:beget`.

Итоговый общий прогон API 28: `OK (32 tests)` — 30 функциональных сценариев workflow/planning/task/list и две capture-методики, пропущенные без специального флага. Прежний list-тест исправлен для вложенной прокрутки: сначала вертикально показывается горизонтальный ряд календарей, затем выбирается его элемент и проверяется видимость. Выбор календаря в приложении не менялся. На API 35 отдельно `OK (9 tests)` для workflow. Вместе с двумя наборами Keystore/restart на обеих API выполнено 59 функциональных проверок устройства; отдельные capture-прогоны в это число не включены.

## Визуальная проверка

Сохранены 216 исходных снимков и контактные листы в `output/playwright/native-workflow-*` / `workflow-*-gallery-*`. Итоговая матрица содержит 144 снимка: чтение/поля/переходы/история в обеих схемах на 360/390/768/1440 dp, дополнительно формы на всех 14 языках при fontScale 1.3 на 390/768 dp.

Первый телефонный прогон с изменением `wm` на API 28 дал обрезанные снимки и не принят как доказательство макета. Подтверждающий прогон использует штатное разрешение QA-эмулятора и существующий в проекте способ проверки dp-ширины через Compose `LocalDensity`; логическая ширина дополнительно проверяется по semantics bounds. Для широких экранов применены реальные `wm` 768/1440 при density 160 на API 35. Подтверждение исправило тестовую геометрию; код экрана во время визуального прохода не менялся. Исходные кадры сохранены, замены или дорисовки пикселей нет. Зависший системный сервис API 35 восстановлен холодным запуском только тестового AVD; профили и данные не очищались.

Контактные листы и отдельные кадры проверены пакетно. Горизонтального обрезания содержимого в принятой матрице нет; длинные переводы переносятся, поля/роли остаются в прокручиваемом потоке. Цвета и компоненты соответствуют существующим Affairs.

## Что остаётся

Это приёмка исходников отдельного нативного экрана, а не завершение всего G3 или нового Android-выпуска. Не проверены физические устройства, TalkBack, живой Google → native → HTTP/PHP, официальный release runtime и совместная итоговая приёмка остальных B/C/G-сценариев. Визуально не пройдены все варианты системной клавиатуры и экранов ошибок; основные ограничения доступа/offline проверены функционально. Нативные отчёты G4 — следующий экран. Общий остаток сохраняется: 21 частичный функциональный ID и 14 общих K/U/L.

Серверные API, SQL, protocol 6 и опубликованный Android 2.9.0/95 не менялись. `GENESIS_DEPLOY_ANDROID=false`. SSH и production-БД не использовались.
