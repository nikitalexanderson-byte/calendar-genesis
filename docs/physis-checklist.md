# Фюзис — проверка первой web-версии

Дата: 24 октября 2026 года. Основание: полное задание «Фюзис», версия 24 октября 2026. Это трассировка реализованных сценариев и фактических проверок, а не разрешение включить модуль в production.

Архитектура и карта интеграции: [physis-architecture.md](physis-architecture.md). Точный контракт, криптография, миграция и лимиты: [physis-api.md](physis-api.md).

Обозначения: **Т** — поведение подтверждено автоматическим тестом; **К** — проверен код; **Б** — требуется отдельный результат браузерного сценария; **О** — ограничение или незавершённый критерий. Тест домена не считается проверкой кликов, реального OAuth или production.

Серверу доступны stable owner, случайные ID, revisions/cursors, schema/key versions, размеры ciphertext и времена изменения/удаления, wrapped data key. Потеря и пароля, и recovery означает невозможность расшифровки сервером. Разблокированный браузер и выполняющийся в нём вредоносный JavaScript остаются границей защиты. Ротация не стирает старые backup-файлы и не лишает старого ключа способности открыть старую копию.

Формула выполнения: в знаменателе только тренировочные слоты с текущим плановым днём не позже сегодня; отдых и будущие слоты исключены. В числителе завершённый слот даёт 1, частичный — долю отмеченных плановых подходов, ограниченную 1; явный пропуск даёт 0. При нескольких попытках берётся максимум одного слота, а не сумма. У перенесённого слота считается текущий день, исходный не создаёт второй пропуск. Внеплановые сессии показываются в факте, но не увеличивают знаменатель программы.

- Native-auth regression: passed. APK не собирался, native workflow не запускался.
- Независимая приёмка: последние 8/8 целевых проверок passed. Исправлены reset форм при отказе от локальной версии, повтор после потери ответа, сохранение более поздних правок во всех трёх retry helpers, импорт крупных записей и перенесённые на следующий день приёмы. Реальные store/WebCrypto тесты покрывают `copy/training/import × saved/offline`; импорт разбивается по размеру зашифрованного запроса, максимум 20 записей / 2 МиБ.

Логи находятся в ignored `output/`; они не включают настоящие пользовательские данные или ключи. Документация оформления: [physis-design-handoff.md](physis-design-handoff.md).

## Краткое использование

1. На разрешённой web-поверхности открыть «Фюзис», задать отдельный пароль и сохранить показанный recovery code вне зашифрованной копии. Затем подтвердить создание vault. На следующем входе понадобится пароль или recovery.
2. Для свободного занятия нажать «Начать тренировку», добавить упражнения, ввести фактические подходы и отдельно отметить выполненные. Для плана открыть «Контроль выполнения → Программы», создать цикл с занятиями/отдыхом и назначить его с даты. После занятия нажать «Завершить»; частичное завершение сохраняет факты.
3. В «Справочнике упражнений» искать стартовые записи или создать личную. Личные записи можно добавить в избранное и использовать в программе/сессии.
4. В «Списке продуктов» создать свой продукт с составом на выбранную основу; в «Рационе» добавить его через поиск/избранное/недавние. Статусы «Планирую» и «Фактически съедено» меняются явно. Для блюда задать ингредиенты, итоговый выход и порции.
5. В справочнике БАДов/лекарств указать препарат, форму, путь и единицы. В «Контроле приёма» создать схему; фактическую отметку ставить отдельно. PRN используется без ложного расписания пропусков.
6. В настройках Фюзиса включить нужные измерения, календари отображения/ввода и timezone. Измерения добавляются на обзоре; отключение инструмента не удаляет записи.
7. Перед закрытием проверить «Сохранено». При offline несохранённое живёт только в памяти вкладки: восстановить связь/повторить или осознанно экспортировать локальный вариант. При конфликте сначала сохранить нужный локальный вариант; загрузка серверного варианта явно отбрасывает локальные изменения.
8. В настройках доступны смена пароля, атомарная ротация ключа, CSV/JSON и encrypted backup. Для восстановления backup нужен recovery именно этой копии. Импорт сначала показывает preview и ошибки; затем сохраняет записи под ключом текущего аккаунта.

## Запуск, миграция, отключение и откат

- Web использует существующие React/Vite/PHP entrypoints; новый framework или сервис не добавлен. Команда доменного набора — `pnpm test:physis`; общий процесс проверки указан выше.
- Изолированную браузерную среду создаёт `php server/tests/physis-browser.php`. Она использует только отмеченный synthetic каталог `output/physis-browser/genesis-physis-test-browser`, не читает настоящий `server/config.php`. Запуск loopback router, нужные opt-in переменные и proxy описаны в [physis-api.md](physis-api.md#reproducible-checks). Test login route существует только при локальном CLI-server opt-in и отсутствует в production router.
- Миграция `server/migrations/083_physis.sql` аддитивна: отдельные Physis tables/indexes, owner FK cascade. Применяется существующим runner при первом обращении к БД. Ручные production SQL не нужны и не выполнялись.
- Деплой — только существующий `.github/workflows/deploy.yml` после согласованного merge/push в `master`, `GENESIS_DEPLOY_TARGET=hostinger`, `GENESIS_DEPLOY_ANDROID=false`. Единственный разрешённый host root — `/home/u531952483/domains/genesiscalendar.com`. Схема CI/CD не заменяется.
- Перед CI deploy существующий workflow сохраняет `server/config.php` и согласованную SQLite-копию. Операционное восстановление production backup в этом проходе не выполнялось; не объявлять его проверенным по одним доменным тестам.
- Default браузерного пилота — `GENESIS_PHYSIS_WEB_ENABLED=true` в `server/src/physis.php`; private config может явно отключить его через `physis_enabled=false`. Точный allowlist — там же; источники стартовых справочников — `training-domain.ts`, `nutrition-domain.ts` и `nutrition-seed.json`. Секреты и настоящий server config не помещать в Git или отчёты.
- После проверки опубликованного APK пользователь поручил включить Фюзис на сайте в браузерах, сохранив запрет в нативном приложении. Новые Android-сборки и публикации исключены границами этого задания. Исторические ограничения предыдущей приёмки выше не означают запрета нового браузерного выпуска; актуальная проверка — [physis-browser-access.md](physis-browser-access.md).
- Быстрое отключение: вернуть `physis_enabled=false`; данные сохраняются. Code rollback: `git revert` проблемного commit/merge и обычный CI deploy. Добавленные таблицы/данные оставить; автоматический database rollback не выполнять.
- После deploy отдельно проверить SHA `master` в `/deploy-meta.json`, успешный `/api/health`, отказ анонимному запросу и эффективный production-флаг. Анонимный 403 сам по себе не доказывает включение доступа тестерам. Результат выпуска фиксируется после завершения workflow.

**SSH не использовался.** Настоящие секреты и production-БД не читались и вручную не менялись.
