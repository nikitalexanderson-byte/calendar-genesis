## Поведение

В существующей карточке общей задачи добавлены «Наблюдать»/«Наблюдаю» и настройки уведомлений. Автор и исполнитель наблюдают по умолчанию; явная отписка имеет приоритет. Импортированные задачи не включают неявное наблюдение и напоминания до осознанной подписки либо изменения срока/исполнителя. Наблюдение не выдаёт доступ к проекту.

Поддержаны создание задач/проектов, комментарии, назначения, упоминания, приближение срока, просрочка, запрос и результат утверждения, изменения задач, проектов и участников. Новые комментарии/изменения задачи адресуются наблюдателям; назначения, упоминания и утверждения — соответствующим участникам. Один audit ID используется для всех входящих и состояния прочтения, включая совместимый API для старых клиентов.

Существующий перемещаемый блок остаётся единой точкой входа. Добавлены «Все»/«Непрочитанные», обратная отметка непрочитанным и настройки через шестерёнку. Выбранный фильтр отмечен заливкой текущего акцента с контрастным текстом: teal/cream в светлой схеме, gold/dark в тёмной. Кабинет открывает настройки и полную историю, включая явно открытую пустую историю. Автоматически пустой блок скрыт. Desktop preview исчезает через пять секунд; на мобильной ширине остаётся компактная иконка. Открытие/сворачивание списка не отмечает события прочитанными; просмотр задачи отмечает события задачи и только фактически показанные комментарии.

По уточнению пользователя окно получило внешнюю обводку акцентом: teal в светлой и gold в тёмной теме. Отдельной рамки вокруг заголовка нет. На desktop перетаскивается вся область заголовка, настройки и закрытие исключены из drag. Отдельная кнопка перемещения убрана. Угол окна меняет размер мышью и стрелками клавиатуры: минимум 320×240, максимум 760×820 px, дополнительно ограничено рабочей областью. Стрелки на заголовке перемещают окно, Home возвращает его домой. При сворачивании иконка возвращается в левый нижний угол, выбранный раскрытый размер сохраняется в текущей сессии. Мобильная версия сохраняет компактный режим и границы экрана без desktop resize-ручки.

Настройки сохраняют типы и каналы, немедленную/ежечасную/ежедневную частоту, время сводки, тихие часы, IANA-пояс и горизонт напоминания. По умолчанию часовой пояс берётся с устройства; ручной выбор имеет приоритет. Формат времени наследует существующий 24h/AM-PM и TimeClockPicker. Даты напоминаний показываются в календаре получателя; язык и часовой пояс также принадлежат получателю.

История после переноса задачи сохраняет разрешённое прежнее название в исходном проекте. Содержимое закрытого назначения не подставляется в старую запись. Глубокая ссылка повторно проверяет текущие права и ведёт к актуальному проекту/задаче/комментарию; при отзыве доступа сообщает недоступность. События удалённых в корзину задач и недействующие напоминания скрыты.

## Фоновые операции и данные

Аддитивная миграция `064_shared_notifications.sql` добавляет наблюдение, настройки, устройства, получателей, outbox и устойчивые квитанции. Исторические audit/read записи и задачи сохраняются; миграция не рассылает прошлые события, не подписывает устройства и не создаёт фоновых отправок. Признак старого импорта заполняется по существующей истории.

Действует существующий background worker с lease, ограниченными повторами, backoff и ручным возобновлением не более 20 неудачных отправок за запрос. Дедупликация выполняется по событию/получателю/каналу/устройству и времени сводки. Тихие часы откладывают отправку без расходования попыток. Завершение, смена срока, архив, удаление и отзыв прав отменяют устаревшую работу. Версия утверждения исключает прежний запрос после утверждения/повторного открытия.

Сетевой вызов освобождает SQLite writer; перед записью результата повторно проверяется lease. Поздний ответ не меняет заменённую/возобновлённую операцию. Подписки и payload очереди зашифрованы. Push содержит только непрозрачный delivery ID; service worker загружает разрешённый нейтральный текст, проверяет тихие часы, устраняет дубли после перезапуска и заново разрешает ссылку при открытии. Выход очищает идентификатор устройства, browser subscription и cache квитанций.

Web Push реализует RFC 8291/8292: aes128gcm, ECDH и VAPID; разрешены только HTTPS endpoints поддерживаемых провайдеров. Уведомление провайдеру означает принятие, а не подтверждённое отображение на устройстве. Email использует существующую PHP mail-инфраструктуру только при явной конфигурации.

Email повторно использует постоянный Message-ID отправки. Как у обычного PHP mail transport, потеря подтверждения после принятия письма внешним сервером всё ещё допускает повторную доставку; очередь не заявляет внешнюю гарантию exactly-once. Push устраняет повтор одного delivery ID на устройстве через долговечную квитанцию service worker.

## Внешняя конфигурация

В проверенном локальном окружении доступны входящие; `PUSH_KEYS_UNCONFIGURED` и `EMAIL_TRANSPORT_UNCONFIGURED` явно показываются в настройках. Закрытый production config не читался и не менялся. `/api/health` публикует только `available`/`blocker` каналов, без ключей, адресов и подписок.

Контракт указан в `server/config.example.php` с пустыми выключенными значениями:

- `notifications.web_push.private_key`: постоянный приватный P-256/prime256v1 VAPID ключ в PEM в закрытом `server/config.php`; `subject` — действительный HTTPS URL или mailto. PHP требует OpenSSL с ECDH, cURL и HTTPS-доступ к push-провайдерам. Смена ключа потребует повторного подключения устройств.
- `notifications.email.transport = 'mail'` и `notifications.email.from`: реально работающий PHP mail transport и разрешённый отправитель домена с настроенной доставкой. Нельзя подставлять фиктивный адрес или считать наличие функции mail гарантией получения письма.

CI не перезаписывает production `server/config.php`. Ключи не генерировались, GitHub secrets не добавлялись. Подписки включаются только действием пользователя и разрешением браузера. Реальные тестовые сообщения участникам не отправлялись.
