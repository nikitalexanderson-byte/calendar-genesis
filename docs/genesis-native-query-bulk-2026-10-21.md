# Native B5/B6: массовые действия в сквозной выборке

Аудит: сервер/web уже поддерживают page/all, SQL snapshot, per-project statusIds, полный scope с cursor и per-task ACL/revision. Нативный bulk editor сохраняет только одну projectId: protocol.edit, journal.verify и State.page требуют все задачи этого проекта; State.readProject получает его права. Поэтому прямое снятие одного guard расширило бы смысл прежней очереди и неверно назначало общий статус нескольким проектам.

Выбран существующий SharedBulkScreen, открываемый компактной иконкой из результатов сохранённого/временного представления. Блоки выборки → действия → preview/report сохраняются в STANDART. Задачи имеют подпись исходного проекта; status mapping задаётся отдельно для каждого проекта. Обычные icon actions48dp и короткие подтверждения, без нового UI стека/ассетов.

Проектный контракт сохраняет прежние3 ключа и строгую projectId-проверку. Новый явный query scope использует отдельный фиксированный account-local journal context и origin(filter/sort/title); эти метаданные не отправляются PHP. Даже если пользователь затем откроет другую подборку, неизвестный preview восстанавливается по первоначальному origin/body/requestId. Для него не требуется повторное чтение удалённого представления; подтверждение результата и фактическое исполнение по-прежнему проверяются сервером для каждой задачи. Project permissions не подменяются фиктивной ролью глобального проекта.

Scope собирается из всех ограниченных страниц с проверкой cursor/total/дублей/суммы, а список задач остаётся100 на страницу. «Все результаты» передаёт прежний queryVersion и фильтр; preview не скачивает все задачи. Очередь локальных task mutations блокирует новую подготовку/confirm; replay старого preview только возвращает ранее созданную операцию. Все старые project journals и frozen bodies остаются совместимыми.

Отдельно проверяется собственный ввод до preview: selection/action/calendar/origin должны сохраняться без server titles/report/permissions и без изменения ISO дат. До объявления среза принятым нужны JVM/protocol/state cases, настоящие HTTPS/PHP page/all/status/ACL/replay и API28/API35 UI/visual gates; новая IME/landscape/a11y/kill-приёмка учитывается явно. Все этапы основного промпта продолжаются;21 частичный ID пока не закрыт. Realme не используется, SSH и production-БД не затрагиваются.


## Реализация и локальная приёмка

Использован прежний `SharedBulkScreen`. Из результатов сохранённого/временного представления он открывается общей иконкой48dp; задачи подписаны исходным проектом. Отдельные блоки выбора, действия и отчёта сохраняют STANDART и общие компоненты. Для статуса показывается собственный выбор каждого проекта. Полный scope проверяется по всем страницам: стабильные total/cursor, уникальные project IDs, точная сумма taskCount и явный предел1000 проектов. Picker-запросы делятся на группы до100 project IDs с отдельными cursors и объединением совпадающих исполнителей/меток. Ни один preview не скачивает все task pages.

Прежний трёхключевой project contract не расширен. Query edit содержит явный scope/origin; frozen PHP body сохраняет только requestId/selection/action. Один известный account-local context ending006 сохраняет старую операцию при переходе к другой подборке. Pending replay не читает изменённое/удалённое представление и фиктивный проект. Новый prepare/confirm блокируется локальной task queue; повтор уже отправленного preview восстанавливает прежнюю операцию. Сервер заново проверяет задачи, ACL, revisions и workflow при исполнении.

Добавлен отдельный AES-GCM `bulk-input` journal на существующем PlanningDraftStore: неполный days/date, выбор, statusIds, origin и независимый input calendar переживают новый editor. CAS не заменяет ввод второго окна, неизвестный command остаётся отдельным и неизменяемым. Сбой raw-input store блокирует новый preview, но не лишает возможности replay сохранённого command. Новая операция сохраняет заменяющий собственный ввод до удаления предыдущего receipt. Logout очищает свой новый raw-input store.

Настоящий HTTPS выявил дефект B5: PHP добавляет spaceId в фильтр scoped view, прежняя строгая receipt comparison отвергала его. Теперь comparison учитывает только это документированное нормализующее правило; исходный frozen command не меняется. Дополнительное условие в ответе по-прежнему отвергается. Два первоначальных harness дефекта исправлены: footer buttons не требуют performScrollTo; cursor настоящего bulk report не обязан начинаться с1.
