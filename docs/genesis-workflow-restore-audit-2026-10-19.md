# G3: исправление правил перед восстановлением — аудит и решение

Основание — свежий master `588d894` после G4 PR #203. Серверные workflow guards и repair API уже существуют, но экран настроек загружает обычный snapshot проекта: он скрывает корзину. В архиве задач, завершённых проектах и корзине нет отдельного входа к правилам. Пользователь может увидеть отказ восстановления по WIP/обязательному полю, не имея доступного пути к исправлению.

Первый экран следующего среза — существующие настройки «Процесс и лимиты», открываемые из архива/корзины. Сохранить общий компонент, локализацию, CAS/replay/history и серверную проверку восстановления. Нужна минимальная read projection контекста workflow: текущие права, идентичность проекта, его статусы и только относящиеся к нему определения полей. Не читать скрытые задачи ради настроек и не вызывать обычный project snapshot для проекта в корзине.

Добавить обнаруживаемый вход для текущего manageProjects в трёх существующих местах: завершённые проекты, архивная задача и строка корзины. Настройки открывать поверх контекста восстановления; после закрытия возвращать пользователя туда же. Отказ восстановления переводить через существующий workflowError, а не показывать внутренний код. Правила не отключать автоматически: администратор явно исправляет и сохраняет их, затем повторяет восстановление.

Проверка: live/archive/trash, project-scoped поля без соседних проектов, readonly/revoke, реальный отказ → настройка → guarded restore, CAS/потеря ответа, все 14 языков, обе схемы ×360/390/768/1440. Сохранить before/after, затем общий install/lint/test/build и штатный workflow. Новая миграция, writer protocol или Android release не требуются. Durable cold-offline draft, native и общая приёмка остаются отдельным остатком.
