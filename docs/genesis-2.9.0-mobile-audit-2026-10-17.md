# GENESIS 2.9.0 — аудит мобильных дел и карта функций

Статус: реализация первого нативного экрана и проверка сценариев; весь 2.9.0 ещё не принят. Требования: [полный мобильный промпт](genesis-2.9.0-mobile-requirements-2026-10-17.md), [план выпусков и веб-деплоев](genesis-two-release-plan-2026-10-17.md). E4/E5/F/C/G и остаточные B/K/U/L сохраняются.

## Реальная среда

Android — отдельное нативное приложение Kotlin / Jetpack Compose / Material 3, не WebView сайта. `GenesisApp.kt` содержит оболочку/навигацию/личный редактор; `SharedProjectsScreen.kt` — командные API-сценарии; `ProjectsScreen.kt` и `PersonalTaskListCard.kt` — личные проекты/списки. Сайт реализован отдельно на React и использует существующий Universal UI/STANDART. Общие исходные изображения и 14 языков упаковываются в APK задачей `genesisAssets`; календари и данные нельзя подменять веб-макетом.

Физический Realme RMX5000, Android 16, serial `Z9CYS8MRVKYHH6CA`, доступен через ADB. Production `ru.genesis.calendar` остаётся 2.8.13/93 с аккаунтом/данными. Дизайн и изменения проверяются в отдельном `ru.genesis.calendar.debug` с синтетическим gateway. Нельзя считать эти проверки реальным сетевым взаимодействием двух production-участников.

В браузере действительно открыт `https://genesiscalendar.com`; после первоначальной проверки Hostinger загрузился публичный экран входа. Снимок: `output/playwright/ui290-desktop-production-public-before.png`. Закрытые авторизованные production-дела в этой браузерной сессии недоступны и не объявляются осмотренными. Для рабочих экранов используются действующие исходные STANDART и локальная авторизованная тестовая среда того же приложения. Десктоп сохраняет Inter/Source Sans, зелёный/золотой/бумажный визуальный язык; Android использует существующие Material type/color roles `standart`/`evening`, без новой библиотеки и произвольной палитры.

## Исходное наблюдение

В «Общих» пространства, дерево проектов, проект/команда, создание списков/задач, представления, календарные переключатели, содержимое и редактор открытой задачи шли одной вертикальной страницей. Поиск находился после содержимого. Выбор задачи прокручивал страницу к нижнему редактору; отдельного контекстного возврата не было. Крупная плашка, повторные карточки заголовков и действия над колонкой занимали место до первой задачи. Статусы каждой задачи были отдельной горизонтальной полосой чипов.

До изменения основного экрана на Realme получены шесть настоящих кадров `output/playwright/ui290-before-native-shared-{entry,project,task}-{light,dark}.png`; instrumentation 1/1, 8,052 с. Это изолированная Activity с центральным содержимым: её system-bar insets отличаются от production-оболочки и не служат доказательством корректности системных областей. Для них требуется отдельная проверка полноценной оболочки.

## Функция → новое место

| Существующая функция | Место в новой структуре |
|---|---|
| Выбор пространства | Экран пространств, самостоятельная строка пространства |
| Создание пространства / просмотр приглашений / присоединение | Меню экрана; в пустом состоянии явные подписанные действия |
| Дерево проектов и сохранённое раскрытие | Экран выбранного пространства; отдельная стрелка раскрывает потомков, нажатие названия открывает проект |
| Создание проекта | Главное подписанное действие экрана проектов с учётом роли пространства |
| Хаос-бокс | Отдельный вход на экране проектов → его задачи в контексте проекта |
| Приглашение участника пространства | Меню пространства, прежние ограничения owner/admin |
| Архив и восстановление проектов | Меню пространства → архив; восстановление сохраняет прежний API/роль |
| Настройки проекта / участники и роли / категории / Google-копирование | Меню открытого проекта → существующие панели |
| Создание задачи | Основное «Добавить задачу» в открытом проекте; объект создания указан текстом |
| Создание списка/колонки и дочернего проекта | Меню проекта; привязанные к колонке действия — её меню |
| Поиск / сортировка | Над содержимым проекта; прежний сохранённый порядок задач |
| Серверные фильтры | Панель с явным «Применить фильтры»; активные условия и сброс рядом с поиском |
| Список / доска / календарь | Общая компактная строка представлений проекта |
| Выбор календаря отображения | В календарном представлении, только при нескольких разрешённых календарях; обычный режим остаётся григорианским |
| Открытие задачи / полный редактор / обсуждение | Самостоятельный уровень задачи, контекст проекта и возврат назад |
| Заголовок / описание / срок | Основные поля задачи; остальные существующие поля раскрываются отдельно |
| Сохранение / ошибка / повтор | Кнопка вне длинной прокрутки, в области с учётом клавиатуры; введённые данные остаются при ошибке |
| Завершение / изменение статуса | Флажок выполнения и текстовые пункты контекстного меню; точное перетаскивание не обязательно |
| Перенос перетаскиванием, доски и изображения колонок | Существующие обработчики/полотно и исходные изображения сохраняются |
| Очередь / offline-копия / неотправленные изменения | Видимые уведомления и прежняя панель разбора/повтора ошибки |
| Информационная строка аккаунта | Компактный футер оболочки; настоящие ошибки входа/синхронизации остаются в прежнем заметном контексте |
| Настройки вида/порядка/видимости пунктов меню | Существующие preferences и навигация; правила кнопок рабочих экранов их не переопределяют |

## Общие компоненты

`AffairsComponents.kt`: размеры на базе 8/16 dp, Material роли темы, общий компактный контекстный заголовок, векторные действия 24 dp с именем/подсказкой и областью 48 dp, поиск/очистка, фильтры, раскрытие дополнительных полей, полоса сохранения и единая анатомия задачи. Строка задачи: название → выполнение → существенные метаданные → непрочитанные комментарии/дополнительные сведения. Личные и общие данные/права остаются в собственных существующих моделях.

## Оставшаяся приёмка

Промежуточный проход на Realme: SharedWorkspaceUiTest **7/7**, 26,424 с (создание, переходы/возврат, сохранённое раскрытие дерева, редактирование колонки, поиск, применение/сброс фильтра, завершение без перетаскивания, viewer без записывающих действий, неудачное сохранение/сохранность черновика/повтор). EmailTaskDisplayTest отдельно через instrument **1/1**, 3,983 с; общий контракт сортировки сохранён. Полный `pnpm i18n:audit` прошёл для 14 языков. Снимки `ui290-after-native-shared-{entry,project,task}-{light,dark}.png` получены и осмотрены; первый визуальный проход обнаружил перенос последней буквы «Календарь» в узкой кнопке. Это нужно исправить до ship. Системные области изолированного harness по-прежнему не считаются проверкой production-оболочки; это заметно и на кадрах полосы сохранения. Общие компоненты/«Личные» и финальная приёмка ещё не завершены.

Новая отдельная просьба пользователя: в десктопном обычном календаре заполнить пустые ячейки плашками задач, открывающими подробности; переполнение открывать через «…» в модальном списке для даты ячейки. Этот независимый веб-срез выполняется и публикуется раньше по согласованному режиму небольших деплоев, затем продолжается мобильный 2.9.0.

После первого прохода нужны корректирующий проход и контроль: create/open/edit/complete/search/filter/reset/view/back/menu, права owner/manager/member/commenter/viewer, ошибки/конфликты/пустые и длинные данные, клавиатура/Back/прокрутка/положение списка, крупный текст, обе схемы, системные области полноценной оболочки, возобновление и offline/reconnect. Затем перенос общих решений в «Личные» и связанные компоненты; веб-матрица 360/390/430/768/1440 отдельно от нативных результатов. Скриншоты «после» и свежий независимый finish-review ещё не приняты. Полный APK/AAB 2.9.0 пока не выпущен; промежуточные веб-деплои выполняются без Android по последнему указанию пользователя.
