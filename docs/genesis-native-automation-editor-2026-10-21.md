Эта страница описывает исходники кандидата и ограниченную локальную приёмку; полный C2 и общий остаток 21 частичный ID + 14 K/U/L ею не закрываются.

## Аудит и решение

Первый нативный экран предоставлял библиотеку, журнал и защищённые управляющие команды. Создать или изменить правило было нельзя; параметры применения шаблона нельзя было проверить в приложении. Добавлен один нативный конструктор в существующую навигацию проекта. Сохраняются native STANDART, Affairs controls, текущие шрифты, светлая/тёмная схемы и независимость календарей. Новых UI-библиотек, токенов и растров нет.

## Direction contract

THESIS: человек собирает правило из понятных полей и видит, что именно сохранено или осталось неподтверждённым.

OWN-WORLD: действующие native STANDART light/dark, Affairs disclosures и icon actions с tooltip; равные цели касания минимум 48 dp и штатные типографические роли.

STORY: создать или открыть правило → выбрать событие, условия и упорядоченные действия → при необходимости проверить без выполнения → сохранить внизу → получить явное подтверждение.

FIRST VIEWPORT: заголовок проекта и редактора, название, выключатель правила и событие; дополнительные настройки раскрываются по разделам. Телефон использует одну колонку, широкая область — две при доступной ширине формы 720 dp. Кнопка сохранения находится в нижней панели. При открытой системной клавиатуре активное поле целиком прокручивается в доступную область; на низком landscape заголовок и дополнительные действия уходят в прокручиваемую часть.

FORM: code-led расширение существующей системы; без comp, новой эстетики или изменения DESIGN.md.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.

## Реализовано

- Создание, редактирование и отдельная копия правила. Семь событий, шесть типов полей условий и девять последовательных действий; до 20 условий и 10 действий с явным изменением порядка.
- Типизированные значения семи видов пользовательских полей. Ноль, false, отсутствие значения и очистка различаются; незаконченный числовой ввод сохраняется локально и не попадает в серверную команду.
- Текущий владелец, роли, каталоги, разрешённые ссылки и revision. Несовместимые действия после смены события сохраняются до явного исправления, а не удаляются молча.
- Независимые календарь правила, календарь ввода и календарь повтора; IANA timezone, существующие 24h/AMPM окна времени и собственное расписание.
- Параметры применения шаблона используют общую форму C1 без возможности выполнить шаблон из конструктора. Проект фиксирован правилом, базовая дата определяется днём запуска. Предпросмотр не создаёт задач и команд применения.
- Проверка без выполнения не сохраняет правило, не меняет задачу, не создаёт запуск и не отправляет уведомление.
- Отдельный encrypted journal purpose `automation-editor`, contract `automation-editor-v1`, CAS и account/project isolation. При неоднозначном результате повторяется неизменный attempted body с тем же operationId. Существующий журнал управления правилами сохранён.
- Защита pause, account/access loss, disposal и late responses. Собственные черновики/копии остаются защищены на устройстве, live names очищаются при отзыве доступа. Сохранение и квитанция расположены внизу формы.
- Заголовок, сообщение о состоянии и доступность дополнительных действий получают неизменяемые значения из наблюдаемого контекста родительского экрана. Это исправляет воспроизводимое отсутствие названия проекта в уже доступной форме; при отзыве доступа название удаляется вместе с контекстом, последняя непустая строка не кешируется. Конкретная причина пропуска обновления исходных дочерних composable на уровне runtime не доказана; произвольные ключи и принудительная пересборка UI не используются.
- 83 подписи на 14 языках; пользовательские названия не переводятся. Для пустой библиотеки показано пояснение, где создать шаблон задачи. При visual-приёмке исправлен точный перевод события создания задачи, который в турецком раньше собирался из английских частей.

## Проверенный кандидат конструктора

Полный JVM прогон после исправления заголовка: 611 случаев, 606 выполнены и 5 прежних пропусков, без failures/errors; debug и instrumentation сборки прошли. Текущие API 28 и API 35 functional/storage прогоны выполнили по 15 методов и отдельно пропустили один opt-in capture-only entry каждый; ошибок нет (130.878 и 227.092 s). Это включает C1-регрессии после общей правки TemplateField. Отдельный сценарий на API 28 и API 35 подтверждает появление названия после загрузки, затем его удаление, видимую ошибку, скрытие формы и отключение всех пяти write/action controls после отзыва доступа в том же экземпляре экрана через «Обновить», без отправки команды. Аудит 83 подписей × 14 языков прошёл.

Текущая системная клавиатурная серия прошла на API 28 и API 35, portrait/landscape × light/dark, font 1.3: полное поле, полный 48 dp clickable Save над отдельным системным IME, UiDevice tap и одна настоящая HTTPS-квитанция в каждом из восьми случаев. 16 соответствующих focused/received originals входят в полную матрицу ниже. Более ранняя Compose-only серия и промежуточная Save-only серия не принимаются: первая пропускала перекрытие кнопки системным окном, вторая — частичное перекрытие самого поля.

Первый независимый finish review вернул `recapture`: 36 предварительных верхних снимков не подтверждали готовое состояние и 4 английских планшетных снимка отсутствовали. Диагностика зафиксировала настоящий дефект заголовка, а не только задержку рисования; проверка ожидания названия не ослаблялась. ## Финальные web-проверки

После native review завершены обязательные `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm test` и `pnpm build:beget`. `output/native-automation-editor-final-web-gates.json` и соответствующие `-web-{install,lint,test,build}.log` фиксируют exit 0 каждого шага: lint — 0 ошибок и 2 существующих предупреждения об `<img>`, test — i18n-аудиты и 364/364 теста без пропусков, build — проверку 90 обязательных entry assets и 203 visual assets. Это последующее подтверждение release gates; финальный native review честно сохраняет состояние своего более раннего снимка, когда web test/build ещё ожидались.

Первая web-попытка остановилась до выполнения тестов на сравнении LF/CRLF в `android/tools/export-template-copy.mjs`. Оригинальный сбой сохранён в `output/native-automation-editor-web-test-crlf-failure.log`. Однострочное исправление нормализует CRLF перед `--check`, по уже существующему образцу notification exporter. Содержимое template-каталога не изменено; checker подтверждает 51 issue, 10 options и 14 reviewed languages. Эта механическая проверочная правка не меняет UI, переводы или принятые APK и учтена отдельно от native manifest.

## Документальная сверка системы

Независимый Impeccable documenter завершён: `output/native-automation-editor-documentation-check.md`. Это обычное расширение Operate в действующей native STANDART. В фактическом коде остаются Material title/body/label roles, Affairs disclosures, общий 16 dp радиус, минимум 48 dp для действий, одна колонка и переход к двум при 720 dp доступной ширины, диалог до 1120 dp. Ширины и keyboard adaptation относятся к этому конструктору; они не объявлены глобальными web-токенами.

`DESIGN.md` и точный `.impeccable/design.json` не изменены: новой визуальной системы, ассетов или утверждённого системного требования нет. Их web-специфичные шрифты и CSS-токены не подменяют действующие native Material/Affairs роли. Прежнее расхождение sidecar narrative о положении «Хаоса» с актуальным DESIGN зарегистрировано в check-файле и не исправлялось попутно. Дефект заголовка исправлен в коде; недоказанная runtime-причина и startup ANR не превращены в правила дизайна.

## Явно непроверенные состояния

Подписанный production MainActivity startup, живой Google-вход и синхронизация, полный upgrade и cold-offline restoration всех старых очередей, полный TalkBack, физические устройства, жесты и аппаратная производительность. Отдельная C1 standalone genuine-system-IME приёмка остаётся открыта; старое Compose-only доказательство для неё недостаточно. В C2 management отображение, enable и retry для ещё не прочитанных непустых template options остаются отдельным интеграционным срезом: действующий экран защищённо направляет в конструктор и не обещает поддержку этого пути. Hostinger worker/runtime и полный межфункциональный G/C/B проход требуют отдельной приёмки. Все 21 частичный ID и 14 K/U/L остаются формально открытыми. Свежая браузерная visual-матрица в этот native/documentation-срез не входит. Публикации APK, production-БД действий и новых миграций не было; операторский SSH не использовался.
