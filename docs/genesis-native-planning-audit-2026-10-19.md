# G1/native: аудит backlog и спринтов

Основание — опубликованный master/production6739c0e, PR #208, workflow39237718858 success; SHA/health/реальные assets/старая вкладка/Android metadata подтверждены. Android2.9.0/95 и protocol6 сохраняются. Следующий основной шаг — один native экран планирования выбранного проекта, затем lifecycle/settings и durable drafts. Это не закрывает весь G1/G2 или21 оставшийся функциональный ID.

В native нет маршрута planning и методов gateway/client/controller для planning snapshot. Сервер/web уже имеют GET /shared/projects/:id/planning: текущие editTasks/organizeTasks/manageProjects, спринты с сохранёнными датами/контекстом, точные totals и суммы исполнителей, fingerprint. Существующий querySharedTasks умеет backlog/sprintId и ограниченные страницы. Существующий updateSharedTask уже поддерживает sprintId и сохраняет неизвестный результат в encrypted outbox. Нельзя создавать второй тип задачи или выводить числа из первой страницы.

Первый экран использует текущие Material3/GENESIS Universal UI: выбор backlog/спринта, состояние/период, независимые totals points/часов и «не оценено», суммы исполнителей, полноценная пагинация, открытие существующей карточки. Перенос существующей задачи отправляет только sprintId+expectedRevision через текущий encrypted task outbox; новые команды поверх pending/error этой задачи запрещены. Чтения и delayed replies привязаны к проекту/bucket; при потере доступа названия удаляются. Offline cache явно помечается и не даёт прав на новую команду без проверки свежих полномочий. Суммы разных проектов не смешиваются.

Планирование открывается из выбранного обычного проекта; вход из хаос-бокса не добавляется. Для14 языков переиспользуется planning-translations.json из generated originals. Существующие assets, независимые режимы дат и экран «Сегодня» сохраняются. На телефоне управление и список идут вертикально; планшет использует отдельную область навигации/сводки рядом со списком. Проверка по размеру окна, без device-model условий.

Baseline выбранного проекта уже сохранён на текущем исходном коде в `output/playwright/native-estimates-after-project-{light,dark}-{360,390,768,1440}.png`; project header/actions с момента этих кадров не менялись. Перед UI-изменением просмотрены390/light и768/dark. Затем проверить query/scope/page model и реальные native handlers:100+31 задач, bucket switch/late reply, current permissions/viewer, completed sprint, pending/error identity,0/null и totals, task open, offline/empty/error. Обе схемы ×360/390/768/1440dp,14 языков/крупный шрифт, клавиатура/Back и сохранение других карточек. Использовать только отдельный QA application ID и синтетический gateway; живой native Google→HTTP/PHP и физическое устройство не объявлять проверенными на основании fixtures.

После этого среза отдельно остаются настройка advanced режима, создание/редактирование/запуск/завершение спринта с явным исходом каждой незавершённой задачи, durable unsubmitted journal и полная C/G/B-интеграция. Эти пункты выполняются следующими этапами; существующие server/web lifecycle tests не заменяют native acceptance. Новых SQL-миграций, зависимостей, writer protocol и выпуска APK для первого экрана не требуется.

Первый экран завершил локальную приёмку: узкий GET whitelist/client/controller/gateway, защищённый account-scoped cache, query/page/scope/permission model, выбор backlog/спринта, независимые точные суммы/исполнители, пагинация, existing task outbox и explicit conflict/rebase. 301 JVM tests, 12 функциональных instrumentation flows, обе темы ×4 ширины, 14 языков/font130 и 20 интерактивных PNG проверены. Выполнены один visual pass, один пакет исправлений и один confirming pass.
