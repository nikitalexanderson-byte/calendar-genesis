# Android 2.8.4: закрытие «Дел» и «Календаря»

Пользователь воспроизвёл закрытие приложения после обновления на realme и подключил Samsung для проверки. На Samsung Galaxy A56 (SM-A566E, Android 16 / API 36) подтверждены оба перехода в установленном production APK 2.8.3 / 83. SHA256 установленного APK совпал с опубликованным: `cc8a6dddbac6e6562a8e81540e453677a03c4e276df934378f5b1157defbf020`.

## Причина и изменение

ART отклоняет общий класс UI с `java.lang.VerifyError` при загрузке `SharedProjectsScreen`. В готовом DEX метода `qu6.a5` 280 регистров, последние шесть — параметры. Маска необязательного аргумента находится в регистре 279, но инструкция по адресу `0x3f` читает неинициализированный регистр 23. Исходную функцию подтверждает сохранённая в DEX строка `ru.genesis.calendar.ui.SharedProjectsScreen (SharedProjectsScreen.kt:69)`. Это ошибка выпускаемого байткода, не выбранной даты или пользовательских задач.

Маленькая входная Compose-функция сохраняет прежнюю сигнатуру, включая необязательный аргумент, и передаёт явные параметры в `SharedProjectsContent`. Большая функция больше не получает маску значений по умолчанию. Разметка, изображения, навигация, данные и права не меняются. Существующее `-dontoptimize` сохраняется: оно устраняло прежнюю ошибку WorkManager, но не предотвращало этот дефект генерации DEX.

## Регрессия готового APK

Новая проверка `scripts/check-android-release-classes.sh` использует карту именно проверяемого APK и инициализирует четыре статических класса экранов через ART: основной интерфейс, общие дела, личные дела и календарь. Она не входит в аккаунт и не обращается к пользовательским записям. Простое чтение метаданных с `Class.forName(..., false, ...)` недостаточно: доказательно пропускает проблемный класс. Проверка использует `true`, поэтому ART проверяет код перед публикацией.

На Samsung и эмуляторе Android 9 / API 28 эта проверка отклонила **исходный опубликованный APK 2.8.3** с тем же `VerifyError`. Прежние debug-тесты и запуск release только до экрана входа его не обнаруживали. Теперь проверка добавлена к существующему CI перед публикацией Native и Play APK, вместе с прежним запуском приложения.

## Проверки и выпуск

Локальные Native и Play APK 2.8.4 / 84 прошли проверку четырёх классов на Samsung. Финальный Native APK также прошёл её на Android 9 / API 28. Сборки `assembleRelease`, `assemblePlay`, их `lintVital` и 239 Android unit tests успешны. `pnpm install --frozen-lockfile`, `pnpm lint` (0 ошибок, два прежних предупреждения изображений), `pnpm test` (217/217, включая аудит переводов) и `pnpm build:beget` успешны; максимальный JS-чанк — 349922 байта при лимите 350000.

Полный `lintDebug` диагностически запускался до этого изменения и обнаружил три прежние ошибки в debug network-security и notification XML. Его успешное прохождение не заявляется. Веб-разметка не менялась, повторная браузерная матрица 360/390/768/1440 для этого Android-среза не проводилась.

PR #173 опубликован: master/production `3f1902545c0cff609aae864071891fb82cd36aa8`, Actions `38738980227` success. `/deploy-meta.json` содержит этот commit, `/api/health` отвечает HTTP 200. Публичный APK 2.8.4 / 84 проверен по SHA256 `d5259c59f146c37593ad846079b89fb42a046948fa2d5e10d2af7d3b6952fce7` и прежнему production-сертификату. `GENESIS_DEPLOY_ANDROID` возвращён в `false` для следующих веб-выпусков.

Именно этот опубликованный APK установлен через `adb install -r` поверх 2.8.3 на подключённом Samsung с существующим аккаунтом. Подтверждены «Сегодня», личные «Дела», «Календарь → Месяц», «Календарь → Год», повторный вход в «Дела» и переход в общие дела. Все экраны открылись; PID приложения оставался 25533, в журнале этого процесса нет `FATAL EXCEPTION` или `VerifyError`. Аккаунт, его проекты и пространства доступны; данные не очищались, задачи не редактировались. В конце восстановлен экран «Сегодня».

До/после сохранены локально: `output/android-samsung-before.png`, `output/android-samsung-2.8.4-{today,affairs,calendar,year,shared}.png`, соответствующие XML и `output/android-samsung-2.8.4-navigation-runtime.log`. Все пять итоговых снимков просмотрены: правильные разделы, без пустого экрана. Доказательства получены на физическом Samsung в текущей тёмной схеме и портретной ориентации, не в браузере.

Непроверено: устройство realme пользователя; светлая схема, альбомная ориентация и планшет для этого исправления; полный функциональный прогон остальных разделов. Разметка исправлением не менялась. Диагностический интерфейс из экспериментальной ветки в этот выпуск не входит: подключённый телефон позволил получить точную причину без него. SSH не использовался.
