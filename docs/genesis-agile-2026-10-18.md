# G1–G4: аудит, реализация и границы проверки

Продолжение полного промпта в `codex/genesis-complete-acceptance`. Публикация, merge в master и Android release запрещены до общей приёмки. Этот документ фиксирует решение; наличие документа не закрывает ни один ID.

Первоначальный аудит обнаружил отсутствие backlog, спринтов, story points, часовых оценок и WIP. Основа: существующие задачи/статусы, C6-права, CAS/receipt, C3-поля, C1-шаблоны, C2-автоматизации, C5-обмен и C4-проверяемая история. G1–G2 server/web теперь реализованы и проверены на этой основе; параллельный тип задачи не вводился. G3 и G4 ещё не реализованы. Все четыре ID остаются открытыми до native, зависимых интеграций и общей приёмки.

Порядок: G1–G2, сначала один экран планирования существующего проекта; затем G3 с единой серверной проверкой переходов; затем G4 как расширение отчётности. Существующие карточки получают только необходимые поля и переходы. Стек, темы, ассеты и независимые календари сохраняются.

Спринт принадлежит проекту и имеет planning/active/completed lifecycle, сохранённые включительные ISO-даты и calendar context v2. Смена календаря отображения не меняет сохранённые границы. Backlog — доступные существующие задачи вне незавершённого спринта. Планирование, перенос и завершение сохраняют проверяемые события состава. Завершение требует явного назначения каждой незавершённой задачи в backlog либо разрешённый следующий спринт, в одной транзакции с проверкой revision/прав. Завершённая история остаётся доступной; удалённые/архивные задачи не подменяют прошлое текущим snapshot.

Оценки points и часы имеют отдельные nullable-значения. Ноль — известная оценка, отсутствие — «не оценено». Проект выбирает активную систему; переключение не конвертирует единицы и не уничтожает сохранённые значения. Points разных проектов без согласованной шкалы не суммируются. Суммы по спринту и участнику относятся только к разрешённым задачам; число задач и points не выдаются за человеческую эффективность. Карточка, backlog, C4/G4, C1/C2/C5 и старые клиенты должны сохранять новые поля по правилу omitted-preserves.

Workflow до явного включения сохраняет текущую семантику. После включения все серверные пути проверяют разрешённый переход, актуальную роль, обязательные поля, существующее утверждение результата и WIP. Создание, восстановление, перенос, изменение смыслов статуса и массовые операции также не обходят ограничения. Настройка не должна оставлять существующие задачи без безопасного выхода; некорректное изменение отклоняется с объяснением. Ролевые ограничения не означают выдачу доступа.

G4 использует только реальные события состава, переходов и оценок с UTC-моментами, точными локальными границами и сохранёнными единицами. Начальная фиксация спринта/плана — явное событие, а не восстановленная задним числом линия. Наблюдения C4 дополняются необходимым состоянием. До записи доказательств показывается неизвестная история; удаление задачи и поздняя правка не должны незаметно переписывать burndown, scope или cumulative flow. Любой показатель ведёт к разрешённым исходным задачам/событиям.

Обязательные проверки: additive migration/backup/old-code rollback, права и revoke, CAS/replay/rollback, конкурирующий WIP, legacy-клиенты, bulk/C1/C2/C5 и approval, points/часы/неоценённые/0, закрытие и перенос спринта, DST и четыре календарных контекста, новые/старые offline/outbox, две темы ×360/390/768/1440,14 языков, native и общая экономика без повторных наград. Пока эти состояния не реализованы и не проверены, G1–G4 открыты.

## Реализованный срез G1–G2 server/web

- В контекстных действиях проекта доступен один новый экран планирования. Расширенный режим включается явно; backlog использует полную серверную выборку существующих задач с пагинацией. Спринты имеют состояния planning/active/completed; одновременно активен максимум один спринт проекта.
- Сохранены включительные ISO-границы, CalendarContext v2, цель и календарь ввода. Начало фиксирует единицу оценок и настоящий план. Завершение требует явного решения для каждой живой незавершённой задачи: backlog либо допустимый следующий спринт. Состав проверяется fingerprint; lifecycle, переносы и audit атомарны.
- Story points и часы независимы; null означает отсутствие оценки, 0 — известное значение. Карточка/создание задачи, backlog, суммы спринта/исполнителя, C4 и точные drilldowns сохраняют это различие. Points разных проектов не складываются в общую производительность.
- C1 capture/save/apply и C5 JSON/CSV/import сохраняют обе оценки; принадлежность спринту не копируется. Инертные оценки шаблона/import не включают advanced mode. Старые PATCH и старый редактор шаблона с omitted fields не стирают оценки; явный null очищает.
- Действуют текущие C6-права, revision/CAS и actor-bound receipt с hash запроса; ACL проверяется до replay. Текст, оценки, ответы planning и planning-поля новых task mutation receipts зашифрованы. Reader старых receipts совместим; customFields остаётся JSON object.
- Межпроектный перенос снимает прежнюю принадлежность спринту, включая старый код через SQL trigger. C4 reportState дополнен planning; события start/complete содержат реальные замороженные планы и outcomes. Это основание будущего G4, не реализация графиков.
- Конфликт сохраняет draft и требует явного rebase. Потеря ответа позволяет повторить тот же pending request в открытом экране. При offline mounted draft сохраняется, lifecycle writes блокируются. Durable draft после reload/cold offline ещё не заявляется.
- Исправлена локализация изменившихся descendants внутри data-no-translate: observer учитывает protected ancestor. Все 14 языков и возврат JA→RU сохраняют draft/выбранный спринт. Ассеты и существующий GENESIS Universal UI сохранены.

## Миграция и ограничения выпуска

077_shared_planning.sql аддитивна; отдельная таблица metadata, один active sprint через unique index, FK/cascade и безопасное снятие membership при transfer. Старые клиенты игнорируют новые поля, старый сервер продолжает обычное редактирование. Code revert оставляет добавленные таблицы; автоматическое восстановление БД не требуется и не выполняется. Существующий CI server-only backup сохраняется; добавлены лишь две PHP test commands. Production-БД и server config не менялись; SSH не использовался.

Открыты G3 и G4, дальнейшие B/C-интеграции, полный native UI/device, protocol6/7 и старый offline outbox upgrade, durable planning draft/reload/cold offline, общая экономика и K/U/L-приёмка. Browser revoke во время открытого G-экрана, Safari/Firefox, physical external push и live Google roundtrip не проверялись. Runtime Hostinger проверяется только после разрешённого выпуска. Production продолжает 36027d8; публичные meta/health повторно подтверждены 18 октября. Merge/deploy и Android release запрещены до полного завершения.
