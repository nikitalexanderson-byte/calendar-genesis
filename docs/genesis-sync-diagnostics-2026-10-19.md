# Android: привычки, тема и задача второго Google-аккаунта

Пользователь сообщил о выполнении привычек в официальной GENESIS2.9.0/95 на Samsung без соответствующих отметок на сайте, различии темы и невидимой задаче из списка. У аккаунта GENESIS два связанных Google-аккаунта. Телефон отключён; пользователь поручил продолжать автономно.

## Установленное и исправленное в исходниках

На подключённом телефоне подтверждены повторные SYNC_STARTED → SYNC_FAILED, без подробной причины в старом APK. Очередь и основное приложение не очищались и не переустанавливались. Успешное фоновое чтение заменяло сообщение о неудачной отправке успокаивающим текстом. Теперь отдельный outgoingSyncIssue сохраняет ошибку при получении данных с незавершённой очередью; новое сообщение прямо говорит об ожидающей отправке. Безопасная диагностика выводит этап, класс, AuthFailure.kind и строку исходника, без содержимого исключений, пользовательских полей или токенов.

На синтетических привычках, созданных настоящими web factories, воспроизведена остановка CloudWorkspaceSync с WorkspacePatch.Conflict в dailyGoalRecords/date/updatedAt. Два устройства независимо пересчитывали одинаковые данные с разным временем. Исправление объединяет только служебные updatedAt дневных целей и userProgress по Instant; разные авторские mode/title и другие значения по-прежнему требуют разрешения конфликта. Произвольная принудительная перезапись пространства не применяется. Регрессия проверяет зашифрованный CAS/Room/outbox round-trip, сохранность обеих интервальных отметок, неизвестного web-раздела и уникальность reward idempotency keys. Это доказанный дефект того же пути синхронизации; точное исключение старого APK пользователя пока не получено.

Тема аккаунта читалась, но native UI её не использовал. Ручные light/evening теперь согласуются с account theme через account-scoped LocalPreferences; выбор отправляется штатным preferences API с сохранённым expectedThemeRevision. Старый ответ не снимает более новый запрос даже при совпадении цвета. Pending защищён от фонового pull; system/scheduled остаются самостоятельными режимами. Конкурирующая тема не перезаписывается молча — выбор сохраняется для повторного решения. Сообщения добавлены во все13 нерусских каталога; всего поддерживается14 языков.

В отдельной debug-сборке обнаружено падение при Google-входе: identity уже появилась, но encrypted workspace scope ещё не переключился, и recovery майндмепа открылся в прежнем scope. Repository теперь создаётся только после ready и совпадения account scope; ошибка чтения сохраняет черновик и не обрушает экран. CancellationException продолжает отменять старую операцию. Переходы входа/смены аккаунта покрыты регрессией.

## Задача из списка

Read-only серверный снимок подтвердил: указанная пользователем задача находится во втором связанном Google-аккаунте, в обычном известном списке, без проекта и даты, не выполнена; её ID совместим с Android. Потери серверной записи или отдельного второго аккаунта GENESIS не обнаружено. Синтетический сценарий такого же bootstrap → encrypted import → list cache → личный хаос-бокс → раскрытие списка показывает задачу на API28 и API35. Точная причина её невидимости на физическом Samsung пока не подтверждена; гипотеза о потере задачи не выдаётся за исправленный факт.

## Безопасность и границы приёмки

Локально прошли374 JVM tests и debug/release/R8 assembly. По14 instrumentation-сценариев на API28 и API35 проверяют habits CAS/outbox, preferences и фактическую видимость импортированных задач/списка. Старая проверка входа в список задач обновлена к действующей навигации «Дела → Личные» вместо удалённого submenu-tasks. Новая диагностика не требует подключения телефона; реальный Google-вход этим synthetic набором не подтверждается.

SSH использован только для read-only диагностики внутри /home/u531952483/domains/genesiscalendar.com: SQLite3 OPEN_READONLY и чтение зашифрованных снимков двух нужных аккаунтов. Наружу выведены только counts, типы/флаги и режим темы; секреты, содержимое workspace и чужие аккаунты не выводились. Production-БД, runtime-файлы и настройки Google не менялись; сетевые Google API ради диагностики не вызывались. Миграций нет.

Официальный APK остаётся2.9.0/95. Исправленная отдельная сборка ru.genesis.calendar.debug собрана и сохранена локально как output/genesis-sync-diagnostic-fixed-debug.apk; SHA256 EC0F5C28D53F8C4F6CFE6DCDE02C1B6AF6DF8C994587AA1E135152EEC83212B4. При первом отключении она ещё не была установлена. Синтетические проверки и release assembly не закрывают общий A4/21 функциональных ID.

## Повторное подключение Samsung

При кратком повторном подключении обновлена только ru.genesis.calendar.debug через install -r, без очистки данных и повторного входа. На физическом Samsung/API36 восстановлена прежняя сессия; безопасный журнал показывает GENESIS_USER_RESOLVED и повторные SYNC_STARTED → SYNC_SUCCESS. В «Дела → Личные → Хаос-бокс» после раскрытия списка фактически видна указанная задача второго Google-аккаунта. Падение при раннем mindmap scope больше не воспроизвелось в этом запуске.

У основной ru.genesis.calendar2.9.0/95 подтверждены SYNC_FAILED и сообщение о конфликте одинакового поля между сайтом и телефоном. Очередь и обе копии сохранены; кнопки принудительного выбора телефона/сайта не нажимались. Точный путь поля в старом APK по-прежнему не выведен. Его очередь не приравнивается к пустой очереди отдельной debug-сессии; новых отметок реальных привычек ради теста не ставили и награды не меняли.

Телефон снова отключён. Для последующей проверки основной очереди запущен существующий prepare-relocation.yml для того же origin https://genesiscalendar.com, run39310275915, source3684039. Это build-only кандидат с подписью выпуска, без изменения deploy.yml, repository variables или публичного Android-обновления. До получения/проверки артефакта, установки на устройство и подтверждённого round-trip основная синхронизация остаётся открытой. Повторный интерактивный Google-вход и новые исходящие отметки этим запуском не проверены.
