## Исходное состояние перед этим срезом

Web-конструктор и сервер используют schemaVersion1, семь trigger types и девять action types. Максимум20 условий,10 последовательных действий и100 активных правил проекта. Definition — типизированные данные, без исполняемых выражений. CalendarMode/context независимы от календаря отображения. Schedule/due имеют собственное время и IANA timezone. Server управляет владельцем, current ACL, revision, idempotent operationId, guard/lease/retry и атомарным запуском. Нативный gateway пока не предоставляет эти маршруты.

Список правил возвращает до50 строк, nextCursor, canCreate и workerCompletedAt. GET правила возвращает definition/canManage; недоступный шаблон редактируется сервером в unavailable placeholder. Журнал до50 строк с immutable (createdAt,id) pagination; перемещённые/удалённые/недоступные задачи не раскрываются через исторический id. PATCH/создание сохраняют operation receipt. Retry разрешён для failed при той же актуальной revision, включённом неудалённом правиле и retryCount<3.

## Предлагаемая последовательность

Начать с одного экрана правил выбранного проекта: active/deleted список, читаемые сведения, состояние worker и журнал запусков. Следующим срезом — изменение правил/создание, typed conditions/actions, отдельный input calendar и dry-run. Управление, доступное в первом срезе, требует durable encrypted команд и явного восстановления потерянного ответа; read-only экран не должен изображать доступное редактирование. Никаких JSON-полей для пользователя. Существующие task completion, queue и проектная навигация сохраняются.

На всех этапах — проверка account/project lifecycle, late-response guards, текущих прав и очистка live names при offline/revocation. Неподтверждённую команду нельзя молча заменить новой. Историю и definition не хранить в журнале команды. Использовать существующие Affairs/STANDART и общую типографику, icon actions с tooltip, disclosure по5 элементов и48dp targets. Широкий экран ограничивает меру строки; мобильный использует всю доступную ширину.

## Direction contract

THESIS: пользователь понимает, какие правила действуют в проекте и что произошло при каждом запуске.

OWN-WORLD: действующий native STANDART light/dark, Affairs icons/tooltips/disclosures, читабельные типографические роли и равные цели касания.

STORY: выбрать правило → прочитать условия/действия → увидеть запуск и исходную задачу → выполнить доступное управление с явным результатом.

FIRST VIEWPORT: название проекта, раздел автоматизаций, переключение списка, обновление/закрытие и первые правила. В detail отдельные группы условия/действия/журнал; восстановление команды всегда видно.

FORM: code-led обычное расширение существующего интерфейса без новых токенов, библиотеки, ассетов или переделки дизайн-системы.

FINISH: независимый finish review и документация в пределах этого экрана; сохранение DESIGN.md и design.json, без исправления прежнего drift как побочного действия.

## Реализованный первый срез

Добавлен нативный экран правил выбранного проекта: active/deleted, серверные страницы по50 с возвратом и раскрытие по5; читаемые владелец, trigger, календарь/timezone, schedule, условия и подписи всех девяти типов действий. Для createTemplate показано разрешённое название шаблона; непустые параметры его применения явно помечаются как доступные на сайте. До реализации их типизированного просмотра включение и новый ручной повтор запуска заблокированы в UI и state до создания команды. Остаются доступны выключение, удаление и восстановление выключенным. Нормализованные сервером опции даже с настройками по умолчанию непустые и подпадают под это ограничение; оно затрагивает большинство сохранённых template-правил. Редактор и просмотр параметров — следующий срез. Имена статусов, меток, участников, полей и шаблонов разрешаются только в актуальной области доступа. История поддерживает страницы и переход к задаче после свежей проверки её доступности.

Включение/выключение, удаление, восстановление и повтор запуска требуют явного подтверждения показанной версии правила. Восстановление всегда оставляет правило выключенным. Команда записывается до отправки в отдельный encrypted journal purpose automations, с account/project isolation и CAS; повтор после потери ответа использует тот же operationId/body. История и имена не сохраняются в receipt. Запоздалые ответы после pause/close/account change отбрасываются; при потере прав live names очищаются. Общий workflowAccessLost распознаёт также типизированные API ошибки, с отдельной C1-регрессией очистки названий.

Это не полный C2: создание/редактирование условий и действий, dry-run и редактор опций применения шаблона остаются следующим срезом. Конструктор не имитируется свободным JSON-полем.
