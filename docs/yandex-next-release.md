# Вход через Яндекс ID

Яндекс ID используется для входа в GENESIS. Пространства Google и Яндекса разделены. Проекты, привычки и настройки сохраняются в защищённом пространстве GENESIS. Задачи и списки GENESIS при входе через Яндекс пока остаются на устройстве; их синхронизация и подключение Яндекс Календаря запланированы отдельно.

## Граница провайдеров

- При создании пространства GENESIS выбирается один провайдер входа: Google **или** Яндекс. Связывать их в одном пространстве нельзя.
- Оба варианта входа показаны на начальном экране сайта и Android-приложения. После входа в настройках аккаунта отображаются только сведения и действия выбранного провайдера.
- Авторизация через Яндекс ID подтверждает личность, но сама по себе не даёт доступ к личному календарю через CalDAV.
- Для календаря потребуется отдельный пароль приложения Яндекс ID. Его следует хранить только в зашифрованном серверном хранилище, никогда в клиентском документе или логах.
- Задачи GENESIS следует синхронизировать с Яндекс Календарём как события с устойчивым идентификатором происхождения и двусторонней защитой от дублирования. Списки задач должны оставаться в зашифрованном пространстве GENESIS по той же модели, что проекты и привычки.
- Нельзя представлять списки GENESIS как списки Яндекса: документированный публичный API личных списков задач Яндекса пока не подтверждён.
- Вход с другого провайдера не объединяет пространства автоматически. Перенос данных между ними потребует отдельной явной операции.

## Регистрация приложения и включение

1. Зарегистрировать приложение на [странице Яндекс OAuth](https://oauth.yandex.ru/client/new). Выбрать платформы **Веб-сервисы** и **Android-приложение**.
2. Для веб-платформы указать Redirect URI `https://genesiscalendar.ru/api/auth/yandex/callback` и Suggest Hostname `genesiscalendar.ru`.
3. Для Android указать пакет `ru.genesis.calendar` и SHA-256 отпечаток сертификата рабочего APK. Текущий сертификат версии 2.4.7: `1E:16:1D:36:F5:74:B0:56:0D:80:8C:7E:E9:5E:1A:BE:98:16:5B:33:85:33:6D:02:76:FB:38:1D:FD:90:1C:B8`. При переходе на Play App Signing зарегистрировать также отпечаток сертификата подписи из Play Console. Поле Google Play URL оставить пустым до публикации в магазине.
4. Запросить права Яндекс ID **доступ к логину, имени и фамилии** (`login:info`), **доступ к адресу электронной почты** (`login:email`) и **доступ к портрету пользователя** (`login:avatar`). Дату рождения и телефон не запрашивать. Права Календаря сейчас не нужны.
5. После создания приложения передать разработчику только **Client ID**. **Client secret не отправлять в чат и не коммитить.**
6. В закрытом `server/config.php` на Beget внутри `/home/h/haiirodw/genesis-calendar` добавить `yandex_client_id` и `yandex_client_secret` по образцу `server/config.example.php`. Этот файл не публикуется и не попадает в Git.
7. В GitHub Actions secret `GENESIS_YANDEX_CLIENT_ID` добавить тот же Client ID для Android-сборки. Client ID публичен; он встраивается в APK. Client secret в Android или GitHub Actions добавлять не нужно.
8. После деплоя проверить `GET /api/auth/providers`: поле `yandex` должно стать `true`. Затем пройти реальный вход через веб и Android на тестовом Яндекс-аккаунте, перезапуск приложения, повторный вход, выход, удаление аккаунта и отказ при попытке занять адрес Google-аккаунта.

Пока серверные значения не заданы, сайт скрывает кнопку Яндекса. Пока Client ID сборки не задан, Android также скрывает кнопку Яндекса.

Подписи на экране входа рекомендуют Яндекс пользователям в России, а Google — пользователям за её пределами. Они не ограничивают доступ по региону; вход через Google остаётся технически доступен из России по решению владельца проекта. Соответствие такого режима части 10 статьи 8 149-ФЗ и ответственность владельца сайта по статье 13.55 КоАП требуют отдельной юридической оценки. Владелец домена и договора хостинга не становится оператором персональных данных автоматически: роль следует определить по фактическому управлению обработкой и оформить до указания конкретного лица в политике или уведомлении РКН.

## Следующий этап

Для Яндекс Календаря понадобится отдельный пароль приложения CalDAV. Доступ к календарю, события задач и зашифрованные списки GENESIS следует разрабатывать и тестировать отдельно. До этого задачи Яндекс-пользователя остаются локальными; очистка данных устройства удалит их.
