# Яндекс: подготовка следующего выпуска

Этот документ предназначен для разработчиков. В текущем выпуске нет Яндекс-входа, кнопок подключения и серверных маршрутов Яндекса.

## Граница провайдеров

- При создании пространства GENESIS выбирается один провайдер входа: Google **или** Яндекс. Связывать их в одном пространстве нельзя.
- Авторизация через Яндекс ID подтверждает личность, но сама по себе не даёт доступ к личному календарю через CalDAV.
- Для календаря потребуется отдельный пароль приложения Яндекс ID. Его следует хранить только в зашифрованном серверном хранилище, никогда в клиентском документе или логах.
- Задачи GENESIS следует синхронизировать с Яндекс Календарём как события с устойчивым идентификатором происхождения и двусторонней защитой от дублирования. Списки задач должны оставаться в зашифрованном пространстве GENESIS по той же модели, что проекты и привычки.
- Нельзя представлять списки GENESIS как списки Яндекса: документированный публичный API личных списков задач Яндекса пока не подтверждён.
- Вход с другого провайдера не объединяет пространства автоматически. Перенос данных между ними потребует отдельной явной операции.

## План реализации

1. Зарегистрировать OAuth-приложение Яндекс ID с веб-адресом возврата и Android-пакетом `ru.genesis.calendar` с SHA-256 рабочего сертификата.
2. Добавить серверную идентичность Яндекса отдельно от Google `sub`, строгую проверку `state` и PKCE для веб-входа, проверку выдачи токена и серверную проверку профиля. На Android использовать официальный LoginSDK.
3. Добавить строгую проверку провайдера во все маршруты подключения Google Calendar/Tasks и Яндекс CalDAV. Секреты держать только в `server/config.php` и CI secrets.
4. Настроить CalDAV-доступ к `https://caldav.yandex.ru` по паролю приложения, обнаруживать доступные календари и синхронизировать события задач. Перед запуском проверить на тестовом аккаунте создание, изменение, удаление, повторы, часовые пояса и конфликт правок.
5. Списки и задачи хранить в зашифрованном документе GENESIS. На сервер отправлять для CalDAV только данные событий, необходимые для синхронизации. Сохранить возможность восстановления пространства на другом устройстве.
6. Только после сквозных тестов открыть Яндекс-вход пользователям в отдельном выпуске.
