# Обязательная UX-приёмка оставшихся требований

Актуализация24 октября:32 функциональных ID прошли B/C/E/F/G release-приёмку. Общий срез и дополнительные UX-исправления описаны в [протокол K/U/L](genesis-kul-acceptance-2026-10-24.md). Упоминания21 частичного ID ниже — историческая постановка19 октября; они не заменяют текущий трекер. Непроверенные физические устройства, screen readers и комбинации перечислены отдельно в новом протоколе.

Уточнение пользователя19 октября2026: для каждого из21 остающихся функциональных ID необходим удобный, комфортный, user-friendly интерфейс десктопного сайта, мобильного сайта и Android-приложения в едином GENESIS Universal UI. Применяется к уже реализованным сценариям и дальнейшим изменениям. Выполненная серверная логика или один проверенный экран не закрывают весь ID.

Для каждой строки проверяется каждый входящий ID отдельно; общая отметка группы не заменяет его приёмку. Матрица не увеличивает число функциональных ID: остаются21 частичный ID и14 общих K/U/L.

Дизайн-код: единственная базовая тема STANDART (Experimental), светлая и тёмная схемы, существующие токены/шрифты/иконки/ассеты и компоненты. Терминология и смысл действий согласованы на трёх поверхностях. Размер окна определяет компоновку: на десктопе используется доступная ширина, на телефоне действия доступны пальцем, на планшете адаптируется нативное представление. Ассеты сохраняются на смысловых местах.

Условия закрытия ID:

1. На каждой поверхности человек может найти основной сценарий, выполнить его и понять результат; сложные настройки раскрываются по необходимости. Нет обязательных скрытых действий через hover/drag-and-drop, мышь или аппаратную клавиатуру.
2. Проверены иерархия, шрифты, размеры, отступы, читаемость, перенос длинного текста и больших чисел, прокрутка и доступность главного действия. Страница/экран не переполняется; локальная прокрутка применяется осмысленно.
3. Проверены keyboard/focus/hover для десктопа, touch targets для телефона и системный Back/IME/insets для Android. Web controls следуют действующим размерам Universal UI; нативные touch targets не меньше48dp. Понятные действия по возможности представлены иконками с едиными локализованными подсказками: hover/focus на десктопе, длительное нажатие в Android и accessible name на всех поверхностях. Неоднозначные действия и важные подтверждения сохраняют текст, когда это помогает пониманию.
4. Проверены loading, empty, error/retry, disabled, выбранное состояние, отсутствие доступа, конфликт, offline/pending и сохранение введённых данных. Причина ограничения объяснена; цвет не является единственным признаком.
5. Браузер: обе схемы ×360/390/768/1440px. Android: самостоятельные снимки phone/tablet, обе схемы и согласованная матрица размеров окна, крупный шрифт. Проверка браузера не заменяет проверку приложения.
6. Все14 языков проверены по изменённым подписям и существенным длинным/CJK состояниям. Сохранены before/after либо новый экран и актуальный эталон, перечислены непроверенные реальные устройства/браузеры/состояния.
7. Функциональные, календарные, privacy, sync и release проверки проходят вместе с UX-приёмкой. Новая функция не объявляется законченной до выполнения всех применимых K/U/L.

Работа ведётся по одному согласованному экрану с аудитом, затем функциональная и пакетная визуальная проверка, один пакет исправлений и при необходимости один подтверждающий проход. Обнаруженные непроверенные состояния фиксируются в отчёте и остатке; общая косметическая переделка несвязанных экранов не требуется.
