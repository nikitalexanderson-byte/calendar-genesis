# G2: сохранение незавершённых оценок задач

Продолжение после PR #206. Веб-редактор планирования сохраняет несколько открытых правок оценок и назначений спринта при смене раздела, страницы, закрытии окна и перезагрузке. Применяется существующий Universal UI и зашифрованный journal; новых серверных endpoint, миграций и writer protocol нет.

## Поведение и границы данных

У отдельных строк больше нет независимого mount-only состояния. Контроллер держит редакторы по task ID; правки вне текущей страницы показываются отдельным списком. Каталог локальных копий предлагает явное продолжение и удаление. Восстановление и подключение сети сами не отправляют изменения задач. Восстановленный ввод можно менять без сети.

Отдельный purpose `planning-tasks` не меняет формат G1 и G3. В документ входят ID/revision, исходные числовые оценки и sprint ID, строки ввода, явные touched flags, выбранное назначение и точная неподтверждённая команда. Названия/описания задач, участники, отчёты и cached permissions не записываются. Общий sign-out cleanup очищает новый namespace вместе с прежними. Один документ допускает до1000 редакторов; действуют общие лимиты journal20 копий на scope и2000000 UTF-8 bytes на payload. Browser quota может быть ниже.

Названия восстановленных задач появляются только после свежей scoped выборки по IDs, блоками до100, и двух planning reads с одинаковым fingerprint. Запись другой project ID, неполная страница или сменившийся fingerprint не становятся доверенными ссылками. Перенесённая/недоступная/удалённая задача скрывается, введённые оценки сохраняются. Архивная задача допускает подтверждение прежней отправки, но не новую правку. Ответ receipt не используется как источник имени задачи.

PATCH содержит только изменённые поля. Ноль, явное очищение null и отсутствие поля различаются. Явное обновление базы после конфликта сохраняет введённые поля и берёт свежие значения остальных полей. Отсутствие изменений закрывает редактор без изменяющего запроса. Выбранный перенос при отзыве organize не исчезает: пользователь может явно вернуть прежний спринт и сохранить разрешённые оценки.

До отправки сохраняются точные UUID/body/revision. Потерянный committed response повторяется с той же идентичностью. Поздний403 или новая ошибка quota при повторе не доказывают, что прежняя отправка не выполнилась, поэтому pending остаётся. Определённый отказ первой отправки и storage error до неё сохраняют редактирование. CAS не удаляет изменившуюся копию другой вкладки. Повреждённые байты можно скачать без изменения и удалить отдельно; quota сохраняет прежние байты и текущий ввод.

Обычный неизменившийся planning poll больше не сбрасывает загрузку следующей страницы. В контроллере строк ошибка уже вытесненного чтения не сбрасывает результат более свежего чтения. Отмена редактора блокирует краткую crypto operation, чтобы завершившаяся очистка не удалила новую правку.
