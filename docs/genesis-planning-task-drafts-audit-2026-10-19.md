# G2: аудит незавершённых оценок задач

Основание — опубликованный PR #206, master/productiona05f6b7, workflow39205763510 success. В PlanningTaskRow оценки, destination и base task остаются локальными состояниями; несколько строк могут редактироваться одновременно, но смена bucket/page/reload теряет их. В текущем rebase изменённая другим человеком вторая оценка остаётся старым полем формы и может быть перезаписана.

Решение на том же экране планирования: управляемые редакторы нескольких task IDs и отдельный encrypted journal purpose planning-tasks. G1 schema остаётся прежней; sign-out уже очищает общий prefix. В документе нужны ID/revision, исходные числовые значения, raw input, явные touched flags, destination и точный pending command. Task titles/описания/участники/cached permissions не записываются.

После восстановления имена берутся через существующий querySharedTasks с projectIds/ids/includeArchived:true, блоками до100 IDs. Свежий planning read до и после проверяет текущие права и fingerprint; чужие/перенесённые/удалённые ссылки скрываются. Receipt не используется как источник имени задачи. Архивная ссылка годится только для подтверждения прежней команды, новая правка требует обычного доступного состояния. Новый серверный endpoint или миграция не нужны.

В PATCH входят только изменённые поля:0 и null различаются, omitted сохраняет соседнюю оценку. Явный rebase сохраняет touched поля и обновляет untouched. No-op не отправляет изменение. Если право organize отозвано после выбора переноса, выбор не пропадает: отправка заблокирована до явного возврата к текущему sprint либо восстановления права. Pending сохраняет UUID/body при повторном ACL/storage отказе по правилам PR #206.

Лимит формата —1000 открытых редакторов в одном документе; общий journal сохраняет20 записей на scope и2MB UTF-8, browser quota может быть ниже. Превышение не должно удалять прежние байты или live edit. Вне текущей страницы восстановленные редакторы показываются отдельно; на текущей странице остаются на своих местах. Применяется прежний Universal UI без новых библиотек.

До реализации сняты8 before PNG: обе схемы ×360/390/768/1440. План проверки: несколько строк/buckets/pages/reload/cold offline,0/null/omitted, untouched sibling rebase, quota/corrupt/two writers/CAS/sign-out, lost response и поздний403, current task move/archive/trash/revoke,14 языков и две схемы ×4 ширины. Этот аудит не закрывает G2/native/интеграции и21 открытый функциональный ID.
