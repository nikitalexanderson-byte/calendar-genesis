# G1/native: первый экран планирования проекта

Основание — [аудит](genesis-native-planning-audit-2026-10-19.md), опубликованный master/production 6739c0e и существующие server/web planning API. Реализован первый нативный экран чтения и переноса задач. Это часть G1/G2; 21 полный функциональный ID и 14 общих K/U/L остаются открытыми.

## Поведение

Из меню выбранного обычного проекта открывается «Планирование». Хаос-бокс не получает неподходящий вход. Backlog, планируемые/активные/завершённые спринты используют существующую коллекцию задач и прежнюю карточку. Список загружается страницами по 100, включая последнюю задачу из 131. Точные totals и суммы исполнителей приходят от сервера, а не вычисляются по видимой странице; points, часы, ноль и отсутствие оценки сохраняют разный смысл. У недоступного участника не придумывается имя.

У спринта видны состояние, цель и период из сохранённых calendarMode/calendarContext. Для сакрального/лунного вида дополнительно показана локализованная гражданская дата с годом. Изменение вида не переписывает период. Экран «Сегодня», ассеты и остальные календарные сценарии не меняются.

Перенос отправляет только sprintId и expectedRevision через существующий encrypted task outbox. Перед записью заново читаются права, planning/config, задача и её ревизия; pending/error той же задачи блокируют новую команду. После неопределённого результата исходная queued-команда остаётся у действующего механизма синхронизации. Конфликт сохраняет выбранное назначение и требует явного обновления до новой отправки. Завершённый спринт доступен для чтения; назначить задачу в него нельзя.

Новый GET-маршрут разрешён узким whitelist и использует прежний account-scoped protected cache. Кеш явно обозначен и не разрешает новую команду без свежей проверки. Чтения привязаны к проекту/bucket/queryVersion; поздний ответ не заменяет другой bucket, смешанные/повторные страницы отклоняются. Отзыв доступа удаляет задачи, сводку, выбор и название проекта из нового экрана.

На телефоне навигация/сводка и задачи идут вертикально; при ширине содержимого от 720dp используются две области. Строки переиспользуют AffairsTaskRow; обновление и перенос — общие векторные иконки с локализованным accessible name, PlainTooltip и областью касания 48dp. Важные сохранение/отмена остаются с текстом. Светлая и тёмная схемы используют действующие Material3/STANDART роли. Общий task row теперь соблюдает disabled и для открытия карточки.

## Проверки

301 JVM tests / 68 suites прошли без failures/errors. Первый instrumented прогон: 8 успешных сценариев — 100+31 страниц, независимые 0/часы, dirty-only перенос, сохранность pending identity, cache/viewer/revoked access, late bucket response, completed sprint, conflict/rebase, открытие прежней карточки и regression G2. Пакетный первый visual pass сохранил 64 PNG: обе схемы × 360/390/768/1440dp и 14 языков при font130 на 390/768dp. Снимки до исправления сохранены как `native-planning-initial-*`.

Первый просмотр обнаружил отличие строк от общего task-компонента и избыточную текстовую кнопку переноса. Выполнен один пакет исправлений: общий row, icon actions, явные стрелки списков, группировка исполнителей; дополнительно устранено сохранение названия проекта после отказа в доступе. Подтверждающая сборка/301 JVM tests, 12 функциональных instrumentation-сценариев и 8 capture runs прошли. Дополнены проверки точной сводки исполнителей, системного Back, личного поиска и списков хаос-бокса. После перехода к общему card исправлен test selector вложенного текста конфликта (unmerged semantics); сам конфликт/rebase повторно проверен без изменения production-кода. Итоговые 84 PNG просмотрены одним подтверждающим пакетом: 8 обычных, 56 font130/i18n, 20 состояний tooltip/assignment/sprint/cache/access на phone/tablet в обеих темах. Дальнейшие visual-итерации не выполнялись.

Web install/lint/352 tests/build:beget и English web/native i18n audit уже прошли на этой ветке; после них web/PHP/lockfile не менялись. Доказательства: `output/native-planning-{web-install,web-lint,web-tests,web-build,i18n,icon-build,confirm-build,functional,acceptance}.log`, PNG `output/playwright/native-planning-*.png`. Используется только QA application ID `ru.genesis.calendar.g1qa.debug` на принадлежащих этой проверке API28 phone и API35 tablet. Runner восстанавливает размер, density и font scale; release/default debug-профили не очищаются.

## Остаток и выпуск

Отдельно остаются [native settings, формы и жизненный цикл спринта, durable unsubmitted journal](genesis-native-planning-lifecycle-audit-2026-10-19.md), workflow/WIP, отчёты, межэкранные C/G/B-интеграции и общая приёмка. Открытые ID не закрываются на основании первого экрана.

Gateway fixtures не подтверждают живой native Google→HTTP→PHP, физические touch/TalkBack, foldable/multi-window, все сочетания старых очередей или release DEX/startup. UI-периоды сакрального/лунного спринта и полная матрица четырёх контекстов года на новом экране также требуют отдельной проверки при lifecycle-этапе; общие calendar vectors её не заменяют. Светлые системные иконки status bar в QA Activity не выдаются за проверку production Activity. Эти состояния остаются открытыми. Browser UI не менялся; результаты browser matrix предыдущего выпуска не заменяют нативную проверку.

SQL, server API, зависимости и writer protocol не меняются. Новый официальный APK не выпускается: Android production остаётся 2.9.0/95, protocol 6 и GENESIS_DEPLOY_ANDROID=false. E4/F/protocol7 из отдельной ветки автоматически не объединяются. Ручной SSH и изменения production-БД не использовались. Публикация исходников через существующий deploy.yml фиксируется после merge и проверки production отдельно.
