# E3 — исправление истории привычек

Рабочая ветка `codex/habit-history` от master `d4b517b`, выпуск 2.8.13/93. Реализация принята локально в описанных ниже границах; публикация и проверка production ещё выполняются. E2 опубликован в PR #185; workflow 39000474521 успешен, production/официальный APK/Realme и VAPID runtime подтверждены; см. отчёт E2.

## Аудит и решение одной поверхности

Прежний дневной экран блокировал изменение прошлого. Измеряемые события уже имели append-only corrections, но бинарные отметки не сохраняли такой журнал. Экономика, квесты и достижения используют результаты и дневные цели, поэтому простое снятие today-only запрета создало бы ретронаграды.

Расширяется существующая история/«Прогресс», затем ссылка из календаря на прошлый день. Поле даты не меняет экран «Сегодня». Пользователь выбирает привычку/прошлый день, задаёт результат и заметку, видит предварительное влияние и сохраняет отдельную корректировку. Действуют дата создания, сохранённое расписание/правило/пояс, отсутствие конфликтов и запрет сегодняшнего/будущего дня в этом историческом сценарии. Обычное выполнение сегодня сохраняет прежний путь.

## Контракт данных

`habitHistory` / native `history` — неизменяемый журнал с устойчивым ID, фактическим civil day, UTC временем внесения, rule ID, источником, родительскими heads, результатом и исходным completion до первой правки. Повтор ID возвращает ту же операцию; другой смысл того же ID отклоняется. Одновременные правки остаются отдельными heads и требуют явного решения. Общий reset epoch запрещает восстановление старого журнала после сброса. Совместимый envelope marker history6: останавливает старый offline reader до перезаписи; новый decoder сохраняет исходный timer epoch, операции таймера не меняются. Проверен защитный отказ по фактическому reader из 2.8.12.

Статистика получает исправленную проекцию, существующий XP credit сохраняется. Экономика видит исходную запись и исходные неисторические измерения. Правка прошлого не выдаёт XP/Лавры, не расходует/не возвращает защиту, не создаёт квесты/достижения задним числом. Уже выданные транзакции не удаляются. Измеряемые правки дополнительно используют существующий append-only measurement journal с historical=true.

Web сохраняет команду с одним ID до успеха, применяет её под существующим workspace lock к последнему локальному состоянию и использует encrypted durable outbox. Native повторно проверяет её внутри Room transaction. Историческое сохранение не запускает completion-анимацию и не продвигает Google-напоминание сегодняшней привычки.

Writer protocol 6 активируется при наличии истории. Старые writers 1–5 не могут перезаписать документ после этой активации. Без истории минимальная версия остаётся прежней; старые данные не переписываются ради нового поля. Миграция production-БД не требуется. Code rollback сохраняет защиту данных: старый клиент/сервер не получает право стереть новый журнал, для продолжения записи потребуется исправленный совместимый выпуск. DB restore не автоматический.

## Ограничения и публикация

Не проверены Safari/Firefox, screen reader, native landscape/tablet/font scale, полный авторизованный production history flow, физическая доставка внешнего push и исчерпывающая визуальная матрица 14 языков. Native изображения показывают сфокусированный ввод с клавиатурой. Функциональная проверка новых подписей/контекста по языкам, календарям и форматам времени дополняет аудит переводов, но не заменяет эту визуальную матрицу.

Публикация: commit/push → PR/review → merge master → существующий deploy.yml → SHA/health → официальный APK/AAB и установка Realme с сохранением данных. SQL-миграции нет; автоматического DB rollback нет. Для E3 SSH не требуется; исправлен безопасный stateless readiness в уже использованном E2 runtime installer, повторная настройка SMTP/VAPID не нужна.

E4/E5/F/C/G и остаточные B/K/U/L остаются в объёме; локальная приёмка E3 не завершает исходный промпт.
