## Аудит

Основной C1 — **шаблоны задач и проектов**. Исторический `genesis-native-bulk-audit-2026-10-20.md` называет массовые действия C1, но они относятся к B6 и не закрывают C1. На старте этапа в native отсутствовали template library/manifest editor/capture/preview/apply и HTTPS routes. Сервер и web уже предоставляют эти сценарии; менять их контракт или создавать отдельный тип задачи не требуется. G2 отдельно требует сохранения независимых points/hours через шаблоны.

Действующие маршруты: library GET/POST `/shared/spaces/:space/templates`, PATCH `…/:id`, source GET `/shared/templates/:id`, preview/apply POST `…/:id/preview|apply`. Системные IDs — только event/publication/launch/control. Library пагинируется по50 с fingerprint; source проверяет все исходные проекты. Save/apply используют immutable operationId/body, CAS/preview fingerprint, актуальные права и атомарные receipts. Сохраняется5MB manifest limit; server workflow/WIP действует и на template entry. Нативный whitelist сейчас этих маршрутов не знает. Превью не считается сохранённой задачей.

Расширить текущий selected-project workspace входом «Шаблоны», а карточку задачи — «Сохранить как шаблон». Использовать существующий STANDART/Material/Affairs,48dp иконки с общими tooltip, rectangular controls, disclosures и шрифты; никаких новых theme families, UI libraries или изображений. На телефоне список → выбранный шаблон → редактор/предпросмотр с системным Back; от720dp библиотека слева и содержимое рядом, формы ограничены720dp. Пустые/loading/error/нет доступа/offline/conflict/pending/received — явные состояния, первичное действие не скрыто в длинном списке.

Внутри этого экрана нужны библиотека активных/удалённых и стартовых шаблонов, независимая capture-база/календарь, rename/copy/delete/restore, редактирование структуры проектов/досок/статусов/меток/полей/задач, checklist/subtask/dependency/member/approval и relative date/time. Все семь типов C3 и0/null G2 сохраняются. Изменение шаблона не меняет созданные ранее задачи. Перед apply показываются переносимые данные, назначения/сопоставления, сроки, конкретные blockers/notices, весь результат страницами и отдельное подтверждение. ## Данные и восстановление

Расширить существующий encrypted CAS journal отдельным templates namespace/AAD; полные редактируемые manifest/drafts нужны для восстановления ввода и остаются зашифрованными в account/project scope. Превью с текущими каталогами/именами не кэшировать на диск: хранить только reviewed hash/fingerprint, повторно проверять fresh ACL/catalog перед новой отправкой. До network commit сохранять точный operationId/body и attempts; после неопределённого ответа разрешать только replay того же запроса. Не заменять pending-команду редактором или rebase. Received receipt исключает второй apply. Account/project/controller scope и запоздавшие ответы защищаются существующими guards. При revoke очищать читаемые names/preview/source; отправленная неоднозначная команда сохраняется в закрытом journal для безопасного replay под тем же аккаунтом.
