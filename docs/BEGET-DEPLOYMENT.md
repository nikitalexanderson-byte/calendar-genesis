# Развёртывание GENESIS на Beget

## Структура

Рекомендуемая серверная структура:

```text
/home/h/haiirodw/genesis-calendar/
├── public_html/     # собранная PWA и /api
└── server/
    ├── config.php   # секреты, вне web-root
    ├── src/
    ├── migrations/
    ├── cron/
    └── var/         # SQLite, WAL и PHP-сессии
```

SQLite хранит общую физическую базу приложения, но каждая рабочая сущность имеет обязательный `user_id`. Все выборки и изменения ограничены текущим пользователем из защищённой PHP-сессии. Google refresh token шифруется Sodium secretbox; ключ хранится только в закрытом `config.php`.

## Домен и Google

Файлы уже размещаются в созданном сайте `genesis-calendar`. Само имя сайта в Beget является каталогом, а не публичным адресом: для доступа извне Beget требует прилинкованный домен либо отдельно арендованный выделенный IP. Обычный общий IP сервера не выбирает этот каталог по HTTP-заголовку Host.

Google OAuth для веб-приложений требует точного HTTPS callback и не принимает обычный IP-адрес. Поэтому вход Google включается только после появления постоянного HTTPS-адреса; работа по IP может использоваться для предварительного просмотра и API без Google.

Необходимые значения `server/config.php`:

```php
'app_url' => 'https://genesiscalendar.ru',
'google_client_id' => '...',
'google_client_secret' => '...',
'cookie_secure' => true,
```

Для голосового помощника Gemini дополнительно нужны server-only настройки:

```php
'gemini_enabled' => false, // включать только после проверки доступного региона
'gemini_api_key' => '...', // auth key из Google AI Studio, ограниченный Gemini API
'gemini_model' => 'gemini-3.8-flash',
'gemini_api_endpoint' => 'https://generativelanguage.googleapis.com/v1beta/interactions',
```

Ключ Gemini нельзя добавлять в Git или клиентские переменные Vite. По умолчанию `gemini_enabled` равен `false`: наличие ключа само по себе не включает API или кнопку. Включать флаг можно только после проверки поддерживаемого Google региона. Голосовая запись ограничена одной минутой и 4 МБ, передаётся через авторизованный same-origin API только после явного действия пользователя и не сохраняется GENESIS. Любые созданные Gemini действия сначала отображаются как черновик и требуют отдельного подтверждения.

Gemini Developer API проверяет регион исходящего серверного запроса. Если Beget получает ответ `GEMINI_REGION_UNAVAILABLE`, одного API-ключа недостаточно: `gemini_api_endpoint` нужно направить на принадлежащий владельцу HTTPS-relay в поддерживаемом Google регионе с тем же контрактом Interactions API. Ключ остаётся только в `server/config.php` и передаётся relay по HTTPS; публичный клиент его не получает.

Бесплатный GENESIS Voice работает независимо от Gemini и server-only ключей. Речь преобразуется в текст средствами устройства или браузера; при доступности современного Chrome используется on-device распознавание и устанавливаемый языковой пакет. Разбор названия, даты, времени, проекта, списка, тегов, приоритета и напоминания выполняется локально в клиенте. Аудиозапись не передаётся на сервер GENESIS и не сохраняется. Если браузер не поддерживает голосовой ввод, та же форма принимает текстовую команду.

Разрешённый redirect URI:

```text
https://genesiscalendar.ru/api/auth/google/callback
```

Единственный рабочий конфигурационный файл на сервере — `server/config.php`. Локальный `server/config.example.php` служит только шаблоном и сценарием публикации на сервер не загружается. Резервные копии конфигурации хранятся вне рабочей директории сайта в `/home/h/haiirodw/codex-backups/`.

Административная панель не имеет отдельного парольного входа. Она появляется только после обычной авторизации Google для точного адреса, указанного в `admin_email` (в production — `nikitalexanderson@gmail.com`). Сервер повторно проверяет это условие для каждого административного API-запроса.

## Синхронизация

Клиент сразу отправляет изменения в API, а при потере сети сохраняет до 2000 последних мутаций в локальной очереди. Планировщик Beget должен запускать `server/cron/sync.php` каждые 5 минут для изменений, сделанных непосредственно в Google Calendar.

## Основной CI/CD workflow

GitHub — единственный источник отслеживаемого кода. После merge/push в `master` workflow `.github/workflows/deploy.yml`:

1. устанавливает зависимости из lockfile;
2. выполняет lint, тесты и обе production-сборки;
3. добавляет PHP-роутер в единый артефакт `public_html`;
4. создаёт согласованную runtime-копию `config.php` и SQLite через `VACUUM INTO`;
5. выкладывает закрытый server-код без `config.php` и `var/`;
6. выкладывает клиент и API-роутер;
7. проверяет `/api/health` и SHA в `/deploy-meta.json`.

Параллельные production-деплои сериализованы. Workflow хранит 20 последних runtime-копий в закрытом каталоге `/home/h/haiirodw/genesis-calendar/backups`. В них нет полной копии исходников: tracked-код восстанавливается из Git. PHP-сессии также не копируются.

`server/config.php`, Google OAuth secrets, refresh/access tokens и `server/var/` не попадают в Git и не перезаписываются rsync.

SQL-файлы из `server/migrations/` применяются автоматически при первом запросе, который открывает БД. Поэтому изменение схемы требует отдельной проверки миграции и плана database rollback; преддеплойная runtime-копия обязательна.

## Откат

- Для отката кода выполнить `git revert` проблемного merge/commit в `master`. Новый push запустит тот же проверяемый деплой предыдущего состояния.
- Не восстанавливать всю папку сайта из ручной копии: отслеживаемый код уже находится в Git.
- Восстановление SQLite или `config.php` выполнять только отдельно, в окно обслуживания и после проверки выбранной runtime-копии. Автоматического database rollback нет.

## Ручные операции

Обычные изменения не требуют ручного SSH или локальной упаковки сайта. SSH используется только для точечной диагностики внутри `/home/h/haiirodw/genesis-calendar`: права, PHP/runtime, cron, логи, server drift или восстановление server-only данных. Соседние сайты трогать нельзя.

Для дополнительной офлайн-копии server-only состояния можно выполнить:

```powershell
.\scripts\backup-secrets.ps1
```

Сценарий вызывает тот же согласованный backup-механизм и скачивает `config.php`, SQLite и metadata в игнорируемый Git каталог `backups/`.

Старый ручной deploy остаётся только аварийным fallback:

Корневая сборка и безопасная SSH-выкладка выполняются командой:

```powershell
.\scripts\deploy-beget.ps1
```

Сценарий собирает клиент с путями `/assets` и `/api`, не перезаписывает `server/config.php` и завершает работу API health-check. Не использовать его для штатных изменений вместо GitHub Actions.
