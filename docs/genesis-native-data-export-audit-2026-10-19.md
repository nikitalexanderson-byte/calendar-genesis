# C5: первый нативный экран экспорта

Актуализировано 20 октября 2026 года по исходникам рабочего среза `codex/native-data-export`. Основание — master `8c9351f` после PR #218; точный WIP stash `dc064599` восстановлен без удаления. Источник API и web-поведения — существующие `SharedDataExchange` / `shared-data-exchange`, `server/src/shared-data-export.php` и общий календарный контракт `server/src/calendar.php`.

Первый нативный экран экспорта реализован в рабочем дереве; итоговые локальные и эмуляторные проверки приведены ниже по `.impeccable/review/native-data-export/packet.md` и журналам `output/`. C5 остаётся частичным, общий остаток сохраняется: **21 частичный функциональный ID + 14 K/U/L**. Публикуется исходный срез; публичный APK остаётся 2.9.0/95.

## Реализованный экран

`SharedProjectsScreen.kt` открывает `SharedDataExportScreen.kt` из действующего меню «Общие → Проект → Действия → Экспорт данных». Доступны объёмы `project` / `tree` / `space`, GENESIS JSON v1 и CSV, независимые календарь экспорта и часовой пояс, необязательные границы дат, включение задач без даты и архивных данных. Календарь экспорта использует свой контекст v2 и существующий `AuthorDatePicker`, сохраняя сакральный, лунный и григорианский режимы и настройку начала года.

Фильтры сворачиваются существующим `AffairsDisclosure`; действие «Сохранить файл» остаётся видимым. Используются STANDART Material3, текущие шрифты и компоненты, форма до 720 dp и действия не менее 48 dp. Высота ограничена доступным окном и следует содержимому, без пустого низа на планшете. Ход операции, валидация, ошибки и точные счётчики сохранения находятся над кнопкой вне скролла; изменяемые сообщения доступны как live region. Замечания сервера раскрываются общим спойлером. Ассеты и семейство темы этим срезом не меняются.

Файл выбирается через `ActivityResultContracts.CreateDocument` с MIME `application/json` или `text/csv`. `AndroidDataExportDestination` пишет исходную строку содержимого в UTF-8 через `ContentResolver`, проверяя актуальность операции перед открытием потока, при записи частями и перед завершением. Содержимое JSON не сериализуется повторно; BOM, Unicode, кавычки и переводы строк CSV передаются как получены. Успех показывается только после завершения записи.

## Сессия, восстановление и границы контракта

`DataExportState.kt` проверяет и замораживает параметры до открытия picker. Экспортный HTTP-запрос выполняется только после выбора назначения; отмена picker не вызывает API. Сохраняется только команда с привязкой к аккаунту и пространству, без содержимого файла и URI. После восстановления команда повторно валидируется. Повторный callback не запускает второй экспорт; ошибка provider допускает повторную попытку.

Внешний ключ композиции стабилен по UID / пространству / проекту. `controller` включён в параметры `rememberSaveable` и saver: восстановленная команда получает новый gateway, а замена контроллера в живом экране закрывает прежнее состояние. Закрытие экрана или смена аккаунта/контекста инвалидируют поздний ответ до записи. Поля `active` / `epoch` имеют `@Volatile`, поэтому фоновые IO-проверки видят закрытие состояния. Валидация snapshot выполняется на `Dispatchers.Default`; после возврата повторно проверяется актуальность операции, до передачи содержимого writer. `AuthController.sharedOnlineCall` дополнительно проверяет текущие UID, поколение сессии и workspace до и после сетевого вызова. Экспорт использует текущие серверные права; offline cache и outbox для него не применяются.

`SharedWorkspaceGateway` и `AuthSessionClient` вызывают `POST /shared/spaces/{space}/data-export`. Сервер строит полную согласованную разрешённую выборку независимо от текущей страницы и первых 100 карточек native UI. Клиент проверяет UUID, объём, формат, типы флагов, известные поля команды и календарный контекст v2. Даты допускаются в диапазоне 1900–2100 включительно; неверная дата или обратный диапазон дают `DATA_DATE_INVALID`.

Общий для UI и команды `DataExportProtocol.timeZone` принимает `UTC` либо существующий IANA ZoneId с тем же шаблоном имени, что PHP-валидатор. Смещения и псевдонимы `GMT`, `Z`, `+03:00`, `UTC+03:00` отклоняются. Поле UI проверяет введённое значение после trim и блокирует picker при ошибке; команда возвращает `INVALID_CALENDAR_TIME_ZONE` для неверного контекста. Неподдерживаемый системный часовой пояс заменяется начальным значением `UTC`.

Содержимое ограничено **20 MiB UTF-8**. Обычный native shared-reader сохраняет лимит **32 000 000 байт**. Для экспортной JSON-оболочки `DataExportInput` / `DataExportReader` / `DataExportStream` используют отдельное потоковое чтение: предел wire-ответа `6 × 20 MiB + 256 KiB` (**126 091 264 байта**), ограничение декодированного строкового токена и глубины 64. Финальная проверка считает UTF-8 без второй полной копии файла и отклоняет повреждённые суррогаты. Проверяются формат, целочисленные счётчики, замечания, дубликаты полей, повреждённый UTF-8 и данные после конца JSON. Это не расширяет бюджет остальных shared-маршрутов и не делает экспорт чтением непосредственно из сети в provider: содержимое сначала проходит проверку в памяти.

## Происхождение HTTP fixtures

`android/app/src/androidTest/assets/native-export-http-README.md` фиксирует получение 20 октября прямых HTTP-ответов неизменённого локального PHP API на master `8c9351f78379431128b4acbbd6ce22fb6e1ba19e` через изолированный `127.0.0.1:4338`. Использованы только синтетические данные: два импортированных проекта, 131 задача, подзадача/ссылка чек-листа, зависимость, комментарий, Unicode, кавычки, многострочные описания, нулевые/null оценки и нулевые/false custom values. Временное fixture-пространство удалено после записи ответов.

Команда: `scope=tree`, синтетический корневой проект, JSON или CSV, `undated=true`, `archived=true`, `calendarMode=lunar`, контекст v2 / `America/New_York` / `march`. Сохранены исходные HTTP-оболочки без повторной сериализации их строк `content`. Оба ответа содержат счётчики **2 проекта / 131 задача**.

## Визуальное подтверждение

После одного общего fix/confirm-прохода oversized-форма планшета заменена ограниченным по окну wrap-content, а ход операции, ошибки, receipt и счётчики вынесены в фиксированную область над кнопкой. Confirm-снимки и `isDisplayed` assertions подтверждают их видимость. После этого внешний вид продукта не менялся; заключительное изменение усилило только видимость guard между потоками. Сохраняются текущие формы, шрифты, цвета, disclosure и действия 48 dp.

Принятый пакет в `output/playwright/` содержит **86 оригиналов**; contact sheets являются производными и в это число не входят:

- **8 parent baseline** `native-export-parent-*`: обе схемы на 360, 390, 768 и 1440 dp. Это существующее меню входа в новый экран, снятое в изолированном QA host перед его открытием; прежней реализации экспортного экрана такой baseline не изображает.
- **50 main** `native-export-confirm-{light,dark}-{360,390,768,1440,592}-ru-*`: обе схемы и пять состояний `form`, `filters`, `waiting`, `saved`, `offline` на четырёх портретных размерах и подтверждённом phone landscape.
- **28 языковых** `native-export-confirm-languages-*`: 14 языков, обе схемы, 390 dp и font scale 1.3.

Capture-тест проверяет фактические viewport, density и fontScale через `TextLayoutResult`. Landscape получен настоящим `UiDevice.setOrientationLeft`: `SurfaceOrientation=1`, кадр **1920 × 1080**, фактическая ширина контента **592 dp** после боковой навигации 48 dp. Десять landscape-оригиналов и соответствующий contact заменены после исправления поворота. Невалидный wm-size-only contact сохранён как `native-export-invalid-sheet-landscape.png` и исключён из принятых доказательств. Размер, density, font scale и rotation эмуляторов восстановлены.

Browser UI этим срезом не меняется. PR #218 уже содержит полную браузерную матрицу из восьми случаев: светлая/тёмная схемы × 360, 390, 768 и 1440 px; её не следует выдавать за новую native-матрицу.

Независимый `.impeccable/review/native-data-export/finish-review.md` завершён с **`disposition: ship` для исходного export-среза**; незакрытых material findings в его пределах нет. Reviewer отдельно открыл все 86 принятых оригиналов и девять contact sheets, исключил неверный landscape contact и прежние initial batches, подтвердил исправления восстановления/UTC-IANA и единственный визуальный fix/confirm-проход. Вердикт разрешает shipment исходников и не подтверждает готовность нового APK или закрытие C5.

Остаются непроверенными реальный Samsung/Google, живой native HTTP с действующей сессией, физический SAF, подписанный APK/release/R8, аппаратный TalkBack, tablet font scale 1.3, foldables и landscape с IME. Landscape-пакет подтверждает начальный viewport и footer при малой высоте, но не нижние позиции раскрытых контролов. Языковая матрица подтверждает форму на 390 dp/font 1.3, без заявления обо всех состояниях/ширинах и без редакторского одобрения носителями языков. Эмуляторные provider/registry-проверки и сохранённые fixtures не переводят эти границы в проверенные.

Импорт JSON/CSV/Trello, mapping, preview, replay/undo и история уже существуют на server/web; полный native import/mapping/durable command journal/history/undo и дальнейшие C/G/B-интеграции остаются следующими срезами. Экспорт отдельно не закрывает C5, A4, **21 частичный функциональный ID или 14 K/U/L**. SSH и ручные изменения production-БД не использовались. Проверки выполнены на изолированном PHP fixture и двух эмуляторах; реальный Samsung не затрагивался.
