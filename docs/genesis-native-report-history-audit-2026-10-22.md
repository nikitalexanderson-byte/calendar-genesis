# G4/U: аудит многолетнего нативного графика

Следующий отдельный срез после `87fbf0f`, без публикации, SSH и физических телефонов. Строгий остаток 21 частичный ID и14 K/U/L сохраняется. Сетевой/контрастный срез принят отдельно; он не доказывает производительность большой истории.

`SprintReportProtocol` допускает до20 003 точек, текущий status catalog — до30 записей; исторические status IDs могут дополнять набор графика. Сейчас `SprintReportChart` в каждом Canvas draw повторно читает JSON и суммирует `statuses.take(statusIndex)` для каждой нижней/верхней границы каждого шага. Это квадратичная зависимость от числа статусов; для730 точек/30 статусов один связный draw содержит порядка1,3млн обращений к метрикам, без учёта предварительной проверки known. Текущий stress fixture покрывает30 статусов только на семи днях.

Первый узкий шаг — воспроизвести нагрузку в существующем экране на синтетической многолетней истории с реальными API28/API35 и сохранить исходные кадры/время переходов. Это ещё не измеренный runtime failure. После baseline подготовить числовые границы слоёв один раз, сохраняя исходный порядок суммирования, нули, unknown/unestimated, разрывы и временные координаты. Предпочтительна разреженная структура: плотная матрица N×M не должна увеличивать память при большом наборе исторических статусов. Canvas должен получать числовые данные без повторного JSON-разбора.

Разметка, подписи, палитра STANDART, общие иконки/48dp/10dp и исходные названия не меняются. Сохранить все точки/источники и полную вкладку данных; не соединять неизвестные интервалы и не заменять неизвестное нулём. Отдельные semantic tests должны подтверждать границы/порядок/разрывы; время измерять как evidence, без хрупкого абсолютного порога для всех компьютеров. Повторить реальные обе схемы ×360/390/768/1440dp и ключевую нагрузку двух SDK, проверить совпадение графика до/после. Пределы полной истории и транспортного payload нужно сверить с серверным контрактом, а не выводить только из верхней границы native parser.

Получены исходные flow/data PNG, реальные geometry assertions и восстановление display. Остальные ширины исходной матрицы проходят тем же APK.

Узкое исправление: запомненные числовые sparse prefix sums в порядке отображения, проверка unknown/partial и непрерывные диапазоны готовятся вне Canvas. Нулевые/отсутствующие observed слои не занимают отдельные ячейки, отсутствие в partial сохраняет неизвестность. В draw нет чтений JSON, повторных `take/sumOf` и создания списков индексов. Каждый слой сохраняет исходную последовательность сложений Double; точки, текстовые данные и источники не прореживаются. Подготовлены проверки двух лет/30 статусов, разрывов, union20 030 исторических ID, независимости от JSON и настоящего сохранённого server corpus для всех единиц.
