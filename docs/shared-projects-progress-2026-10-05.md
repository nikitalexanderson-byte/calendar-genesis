# Общие проекты: архитектура и состояние на 2026-10-05

## Граница данных

Личные задачи, проекты, привычки и календарь остаются в существующем зашифрованном пространстве пользователя. Новый командный контент хранится отдельно в SQLite (`022_shared_projects.sql`) и доступен серверу GENESIS для проверки прав, синхронизации и обсуждений. Экран сообщает участникам об этой границе. Личные данные не копируются автоматически. Перенос личных данных ещё не реализован: перед ним нужны явный предварительный просмотр полей, безопасная операция переноса и проверка поведения связанных Google-объектов.

## Текущий серверный контракт

- `GET/POST /api/shared/spaces` — пространства пользователя и создание.
- `GET/POST /api/shared/spaces/{id}/projects` — только доступные проекты и создание, последнее недоступно гостю.
- `GET /api/shared/spaces/{id}/archived-projects`, `POST /api/shared/projects/{id}/archive|restore` — архив и восстановление с защитой иерархии.
- `POST/PATCH /api/shared/spaces/{id}/members/{userId}` — роль участника пространства, только владелец.
- `GET/POST/PATCH /api/shared/projects/{id}` — снимок и изменение проекта; изменение требует роль владельца или менеджера. `POST` для нативного Android, где стандартный HTTP-клиент не поддерживает `PATCH`.
- `POST/PATCH /api/shared/projects/{id}/members/{userId}` и `DELETE` — проектная роль и отзыв доступа; только владелец проекта.
- `POST /api/shared/projects/{id}/invitations`, `POST /api/shared/invitations/accept` — одноразовое приглашение, связанное с email, срок семь суток; хранится только SHA-256 токена. Ссылка передаётся вручную, отправка почты не заявлена.
- `POST /api/shared/projects/{id}/tasks`, `POST/PATCH /api/shared/projects/{id}/tasks/{taskId}` — создание и изменение задачи с проверкой версии.
- `POST /api/shared/projects/{id}/statuses`, `POST/PATCH/DELETE /api/shared/projects/{id}/statuses/{statusId}` — настройка статусов с переносом задач при удалении и защитой последнего статуса завершения.
- `POST /api/shared/projects/{id}/categories`, `POST/PATCH/DELETE /api/shared/projects/{id}/categories/{categoryId}` — категории проекта; удаление снимает категорию с задач и увеличивает их ревизию.
- `GET/POST /api/shared/projects/{id}/tasks/{taskId}/comments` — обсуждение.

Все изменяющие запросы используют действующую CSRF-проверку и сессию. Включение функции разрешено только администратору и восьми указанным Google-аккаунтам. Для других аккаунтов переключатель виден как платная функция, но сервер запрещает его включение. Флаг выключен по умолчанию; выключение скрывает раздел и сохраняет данные.

## Матрица прав реализованного среза

| Роль | Чтение проекта | Комментарии | Задачи | Проект и приглашения | Проектные роли | Создание проектов в пространстве |
| --- | --- | --- | --- | --- | --- | --- |
| Владелец проекта | Да | Да | Да | Да | Да | Только при роли owner/admin/member пространства |
| Менеджер | Да | Да | Да | Да | Нет | Только при роли owner/admin/member пространства |
| Участник | Да | Да | Да | Нет | Нет | Только при роли owner/admin/member пространства |
| Комментатор | Да | Да | Нет | Нет | Нет | Только при роли owner/admin/member пространства |
| Читатель | Да | Нет | Нет | Нет | Нет | Только при роли owner/admin/member пространства |

Гость пространства видит только проекты с явным проектным членством. Приглашение делает нового участника гостем; владелец пространства может отдельно повысить его до member/admin/owner. Только владелец пространства меняет роли пространства. Последнего владельца пространства и проекта понизить или удалить нельзя. При отзыве доступа сервер прекращает новые чтения и записи; уже полученные на устройстве данные невозможно отозвать у отключённого клиента.

## Готово и проверено локально

- Feature flag и пожизненный доступ указанным тестерам в настройках сайта и нативного Android.
- Подменю «Личные / Общие» только при включённом флаге; личный раздел визуально сохранён.
- Пространства, общий хаос-бокс, проекты и подпроекты; контейнер задач и доска; редактирование и архив/восстановление проекта; настройка статусов и категорий проекта; участники, роли, назначения, перемещение между статусами, комментарии, отметка автора завершения.
- Серверные проверки изоляции, приглашений, отзыва прав, сохранения доступа к архивному проекту при отзыве доступа к другому, конфликта ревизий и передачи владения при удалении аккаунта в `server/tests/shared-projects.php`.
- `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm test` (95 тестов), `pnpm build:beget`, PHP smoke и Android `:app:testDebugUnitTest :app:assembleDebug` прошли. Общий PHP smoke повторно прошёл после проверки ссылок на категории и статусы другого проекта и сохранения роли пространства при исключении из проекта. Перед выпуском полный набор нужно повторить после всех следующих изменений.
- Браузерная проверка сайта через локальный PHP API в темах Standart и Experimental на 360, 390, 768, 1024 и 1440 px. Снимки до/после сохранены локально в игнорируемом `output/playwright/shared-projects/`; ширина страницы не превышала viewport. Проверены раскрытые настройки статусов на 390 px.
- Через браузер создана категория «Срочно» и новая задача с этой категорией; метка появилась на карточке доски. После этого обе темы повторно сняты на всех указанных ширинах.
- Локальный HTTP-сценарий с двумя независимыми сессиями и двумя браузерными контекстами: до приглашения B получил 404, повтор токена получил 404, A увидел завершение задачи пользователем B, оба браузерных контекста открыли общую доску. Сценарий использовал тестовые аккаунты и локальный PHP сервер, не внешнюю авторизацию.

## Не реализовано или не проверено

- **Не реализовано:** безопасный перенос личных задач/проектов в общие, окончательное удаление, чек-листы и зависимости, поиск/представления, командные уведомления и календарный слой, Google-проекция, файлы/документы, шаблоны, автоматизации, аналитика, импорт/экспорт и офлайн-очередь. Пункты этапов B–E приложения к заданию остаются открытыми.
- **Не проверено:** реальное устройство Android, доставка уведомлений, живые Google-сервисы, внешний OAuth, почтовая доставка, нагрузочный профиль 50 проектов/10 000 задач, production. PHP smoke моделирует несколько пользователей внутри одного тестового процесса; отдельный локальный HTTP-сценарий проверил две независимые сессии.
- Общие задачи пока ограничены первыми 500 записями снимка проекта. Для большого объёма нужна постраничная загрузка.
- Политики хранения/удаления командного контента, резервного копирования, инкрементального обновления и событийной очереди ещё требуют реализации перед выпуском.
