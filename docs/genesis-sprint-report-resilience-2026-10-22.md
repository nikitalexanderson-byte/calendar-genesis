# G4/C6/L2: отчёт, потеря сети и пользовательские названия

Локальное продолжение после `47b9889`, ветка `codex/post-release-acceptance-no-deploy`. Публикация запрещена: push/merge/deploy, новый APK, production DB и SSH не использовались. Остаток — 11/32 приняты, 21 частичный ID и отдельно14 K/U/L; этот срез не закрывает G4 целиком.

## Найдено и исправлено

Пользовательский статус «Описание» переводился в Description в легенде, WIP-фильтре, таблице и источниках отчёта. Названия теперь передаются дословно; системные подписи сохраняют локализацию. Связанный переход из источника обнаружил вторую причину: общий DOM-перевод превращал заголовок задачи «Сохранить» в Save. `#shared-task-title` теперь явно защищает пользовательский текст.

При потере сети родительский planning полностью размонтировал отчёт, поэтому исчезали выбранная единица, раскрытие и сводка, а существующая offline-подсказка не появлялась. Отчёт теперь остаётся в памяти. Неподтверждённый родительский контекст сбрасывает источники, отменяет запросы и помечает данные неактуальными. Сводка содержит прежний timestamp; её кнопки заблокированы. После подключения и проверки planning требуется явное обновление отчёта. При настоящем отзыве доступа диалог закрывается и данные удаляются с экрана; поздний ответ не возвращает их.

Refresh, события, изменения и дневные источники используют общий `IconActionButton`:44×44px, радиус10px, имя/tooltip. Выбранный тип источника получает `aria-pressed`, дневная кнопка включает отображаемую дату в доступное имя. Метрики сохраняют числовые подписи. Новый стек, ассеты и CSS-система не вводились.

## Проверки

[Receipt](../output/g4-source-receipt.json) содержит source/PNG SHA256, конкретные результаты и очистку. Все проверки выполнялись на локальном Chromium/PHP с отдельными синтетическими данными. Новые browser contexts изолируют offline и viewer-сессию; их закрытие и возврат языка/темы выполняются в `finally`.

- Спринт запущен через UI с тремя задачами: points0/3/null, hours1.5/0/null. Три единицы отчёта различают известный ноль и отсутствие оценки.
- 14 языков сохраняют исходные названия статуса/задач, выбранную единицу и три источника. Отдельно заголовок открытой задачи проверен на всех14 языках.
- Реальный переход оценки0→2 инвалидирует прежний token через409. После обновления scope=5, первоначальный план=3; источник сохраняет before0/after2 и hours1.5.
- События, изменения и дневная кнопка читают реальные API sources. Дневная кнопка содержит дату, таблица сохраняет название статуса.
- Завершение через UI подтверждено состоянием сервера, затем два reopen/re-complete цикла проверены через фактический POST `/move`. При трёх completion transitions результат остаётся одной задачей: tasks1, points2, hours1.5, без ложного scope exit. Источник открывает исходную карточку.
- Обе темы ×360/390/768/1440px: обычный отчёт/источники —8 профилей/16PNG, offline —8/8PNG, заголовок задачи —8/8PNG. Нет горизонтального переполнения. Offline сохраняет hours/раскрытие/план1.5, убирает источники, не отправляет запросы при принудительном клике и требует refresh после сети.
- C6,390px: у реального read-only viewer удержан ранее разрешённый ответ с тремя sources. После удаления участника проверка доступа отклонена, диалог закрыт; поздний ответ отброшен. Новый sources request —404, без прежних task IDs/titles.

Исправленный predicate и отдельное подтверждение12 этапов проверили настоящий endpoint, повторное завершение, точные три единицы и переход к задаче. Ожидание русского heading затем обнаружило реальный DOM-перевод, исправленный и повторно проверенный на14 языках. Ошибки измерения скрытых кнопок в закрытом details исправлены через `checkVisibility()`.

## Непроверенное и продолжение

Новые Android source/эмуляторные тесты не запускались; проверка исходников показывает прямое использование native status titles, но это не свежая runtime-приёмка. Не проверены Firefox/WebKit/iOS Safari, screen reader/TalkBack, реальный телефон, текущий signed MainActivity, fresh OAuth/Calendar, worker/внешние уведомления, полная C/B/E/F и cross-client матрица. Языковая проверка доказывает сохранность названий и состояния, не носительскую вычитку всего экрана.

Остальные пользовательские значения карточки задачи, включая название доски/категории, требуют следующего C/B/L2 аудита: фиксация заголовка не объявляется устранением всех совпадений с UI-словарём. Канонические PRODUCT/DESIGN и чужие review-артефакты не изменены. Следующий рабочий срез — эти связки C/B и оставшаяся нативная интеграция, без публикации.
