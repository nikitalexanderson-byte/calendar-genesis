## Существующая модель

`habitMeasurements` — неизменяемый журнал с устойчивыми ID, историей исправлений и конфликтами. Значения длительности — целые тысячные доли минуты. Схема зашифрованного workspace — 16; writer protocol — 4. Коллекции перечислены явно в web sync и подписанном Android account adapter. Native `HabitsRepository` хранит локальное представление и outbox; импорт/обратный patch аккаунта выполняют `CloudAccountImporter`, `CloudWorkspaceSync`, `WorkspacePatch`.

Обычная запись сейчас разрешена только сегодня. Для E1 нужен отдельный проверяемый путь исторических частей таймера без ретронаград; общий ручной ввод истории относится к E3. Новые поля должны переживать normalizer, cloud cache/merge, offline queue, native codecs, import и старых writers. Недостаточно добавить React setInterval или только local-draft Android поле.

## Поведение

- Старт из карточки привычки. Один незавершённый таймер на устройство/аккаунт; другие устройства показывают сессию и её владельца, управляют своими отдельными сессиями. Одновременно запущенные offline-сессии сохраняют разные ID и отображаются явно; они не заменяют друг друга. Управление сессией остаётся на запустившем устройстве. Два окна одного браузера сериализуют действия и читают актуальный журнал перед изменением.
- Секундомер либо Pomodoro с целыми рабочими/перерывными минутами. Настройки фиксируются при старте. Старт/пауза/продолжение/завершение опираются на UTC timestamps; пауза останавливает рабочую и перерывную части. Рабочее время считается формулой по накопленному активному времени, без зависимости от числа UI-тиков или перебора каждого цикла.
- Журнал операций с родителями сохраняет редкую конкуренцию действий как явные ветки. Незавершённая или спорная сессия не записывает прогресс. Изменение системных часов назад отклоняется с сохранением журнала. Повторные finish/save применяют тот же результат.
- Часовой пояс и календарный контекст привычки фиксируются при старте. Каждая UTC-часть распределяется по фактическим местным гражданским дням с учётом DST. Граница календарного периода определяется сохранённым правилом привычки. Сумма тысячных минуты получается из суммарных миллисекунд с переносом остатка между днями; округление не увеличивает результат.
- Завершение сначала сохраняет готовую сессию. Перед отдельным сохранением результата видны привычка, даты, рабочая длительность, исключённые перерывы и соответствующие периоды цели. Ошибка не очищает сессию. Запись — атомарный workspace update с устойчивыми ID измерений и подтверждения.
- Цель по длительности получает минуты за доступные запланированные дни. Прошедшие дни не дают ретронаград. Для количества и бинарных привычек сохраняется длительность сессии, без подстановки минут в количество или автоматической отметки. Изменённая/удалённая/поставленная на паузу цель не переназначает результат молча: готовая сессия остаётся доступна, привязку нужно проверить явно.

## Первая поверхность и проверка

Расширяется существующая карточка привычки и компактная общая панель незавершённых сессий, чтобы таймер оставался доступен после смены дня. Используются Universal UI, текущие поля дат/времени, обе темы и все 14 языков. Новый визуальный мир/библиотека не вводятся.

Обязательная проверка: обычный и Pomodoro расчёт, паузы/перерывы, скрытая вкладка/фон, перезагрузка и повторное открытие, offline save failure/retry, два окна, web/native round-trip, старый writer, midnight/DST/границы периода, конфликт, несколько устройств, отсутствие повторных записей/наград. UI: две темы × 360/390/768/1440 с до/после, native Realme. Непроверенные состояния фиксируются отдельно. SQL-миграция для зашифрованного документа не требуется; production-БД вручную не изменяется.

## Реализация и результаты проверки

Web: `habit-timer.ts` хранит неизменяемые операции, проверяет граф состояний и считает рабочие части по UTC. `habit-timer-workspace.ts` связывает их с журналом значений. `habit-timer-storage.ts` сохраняет операции при записи устаревшего кэша и сериализует команды через Web Locks, при отсутствии API — через lease в IndexedDB. История сессий остаётся доступна после сохранения. `HabitTimerPanel` встроен в карточки фактического сегодняшнего дня и экран привычек.

Android: `HabitTimers`, `HabitTimerCodec` и `HabitTimerWorkspace` реализуют тот же контракт; команда выполняется внутри существующей Room-транзакции с outbox. `HabitTimerShelf` подключён к «Сегодня» и списку привычек. Все фактические account adapters обновлены: import, migration, sync и обратный `WorkspacePatch`. Общие JSON-векторы подтверждают обмен в обоих направлениях. Сброс истории создаёт новое поколение таймеров: старые offline-операции и их измерения не возвращаются после merge.

Writer protocol повышен до 5 только для workspace с таймерами либо маркером их сброса. Старые пространства остаются совместимы. Старый клиент после активации таймеров получает существующий ответ о необходимости обновления при попытке записи; чтение и исторические данные не удаляются. Новая SQL-миграция не нужна. Откат кода — штатный revert и workflow; защита БД от старого writer продолжает действовать. Вручную понижать protocol или восстанавливать production-БД нельзя.
