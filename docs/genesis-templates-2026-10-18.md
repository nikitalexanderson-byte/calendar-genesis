# C1 — шаблоны, аудит и рабочее решение

Непубликуемая ветка `codex/genesis-complete-acceptance`. Серверная и веб-часть C1 реализованы и проверены, включая14 языков. Нативная часть и зависимые C/G/B-интеграции остаются открыты. Используются текущие PHP/SQLite, task revision/receipts, C3 и C6; стек не менялся. Деплой запрещён до завершения всего поручения.

Срез: библиотека шаблонов в текущем проекте и действие «Сохранить как шаблон» в существующей карточке задачи/настройках проекта. Перед применением — anchor date, собственный календарь шаблона/context v2, выбор переносимых данных, фактическая структура и понятные пропуски/блокировки.

Единый версионированный снимок структуры переиспользуется затем C5: проекты/подпроекты, статусы, метки, задачи, чек-листы, подзадачи и C3. Источники проверяются по текущему C6, а назначения участников — в целевом проекте. Применение не переносит файлы, обсуждения и права. Исходные задачи не связаны с последующим редактированием шаблона.

Снимок из нескольких исходных проектов не должен открывать закрытый подпроект через библиотеку шаблонов: сервер сохраняет исходные scope IDs отдельно от редактируемого JSON и перепроверяет доступ ко всем исходным scopes при чтении/применении. Удаление источника и отзыв доступа должны давать явное объяснение, а не частичный скрытый перенос. Созданные из шаблона задачи получают новые ID и самостоятельные данные.

Добавлены четыре локализованных стартовых шаблона: мероприятие, публикация, запуск проекта, проверка/контроль. Системный шаблон маркируется и копируется в пользовательский перед изменением. Создание, переименование, редактирование, удаление/восстановление и применение проверяют актуальные полномочия. Повтор применения использует устойчивый operationId и единую транзакцию с receipt.

Фабрики проектов, статусов, категорий, меток и C3 definitions теперь сохраняют владение внешней транзакцией. Обычные вызовы по-прежнему фиксируют собственную транзакцию. Применение шаблона дополнительно использует savepoint внутри чужой транзакции: поздняя ошибка не оставляет частичного дерева даже при перехвате ошибки вызывающим worker.

Относительные месяцы/годы не заменяются фиксированным числом дней: Gregorian сохраняет номер месяца/день; Sacred использует13 периодов, включая Апейрон; Lunar — реальные новолуния и 12/13 месяцев года. Несуществующий день явно сдвигается на последний день периода и объясняется в preview. Canonical результат — ISO civil date, переключение отображения не меняет сохранённый context.

Откат кода только через Git. Миграция073 добавляет sidecar tables и не меняет исходные задачи. Миграция074 исправляет служебный trigger при каскадном удалении: обновление родительской/категорийной ссылки больше не создаёт paging row для уже удалённого проекта. Production/SSH и деплой не используются.

Календарное основание: `server/src/template-dates.php`. Проверены Gregorian Jan31→Feb29, Feb29→Feb28, отрицательный месяц; Sacred Apeiron6→5 и переход в13-й период; Lunar30→29 и год13→12 месяцев с явным clamp. Offset limits:74000 дней,2400 месяцев,200 лет; итоговая ISO-дата1900–2100. Черновик сохраняет calendar context v2, IANA zone и начало года независимо от календаря отображения.

## Реализовано

- `template-manifest.php`: version1 portable schema, typed values, parent order, references, cycle/completion-graph validation, bounds и запрет executable/private payloads.
- `template-capture.php`: согласованный снимок существующей задачи с подзадачами или дерева проектов; каждый source scope проверяется по C6. Пропуски архивных/внешних/частных данных явно перечисляются.
- `shared-templates.php`: encrypted title/manifest/notices, CAS и operation receipts; независимость от созданных задач, переименование, редактирование, удаление/восстановление, pagination50 и filtered source ACL. Копирование сохраняет ACL evidence исходного шаблона; физическое удаление source не открывает snapshot.
- `template-apply.php`: текущие разрешения и доступные участники, явные сопоставления статусов/категорий/C3/вариантов, десять групп переносимых данных, обязательные поля,0/false, сдвиги календарей, headroom quotas, stale preview/replay, новые ID и атомарное дерево. Workspace fields копируются в новые project scopes. Task template в существующем проекте сопоставляется с доступными definitions.
- Подтверждения не теряются молча: недоступный действующий или бывший участник блокирует перенос политики до явной замены/исключения. Completed/checklist/approval confirmations сбрасываются, исходные задачи не изменяются.
- API и `SharedTemplates`, `SharedTemplateStructure`, `SharedTemplateApply`: библиотека, обычный редактор, сохранение из задачи/проекта, предпросмотр, применение, конфликты с сохранением копии, удаление/восстановление. JSON editor не используется. Выбор назначения учитывает write права; reader шаблона может применять его в другом writable проекте. Доступ открытого шаблона перепроверяется при focus/обновлениях и по таймеру; отозванный snapshot закрывается.
- Четыре readonly starter templates на14 языках; пользовательская кириллица сохраняется. Локализованы новые UI/error/activity strings. Кодированный `system:…` ID декодируется API; все четыре реальных HTTP GET проверены.

## Выполненные проверки и границы

Frozen install,365 web tests, полный lint:0 ошибок и2 прежних img warnings. TypeScript повторно подтвердил ровно8 исходных ошибок и отсутствие новых C1-ошибок после исправления active-project DTO; успешным общий tsc не объявляется. Production-compatible build сохраняет90 обязательных и203 визуальных assets; max JS349908bytes, лимит350000 не увеличивался.

Чистый PHP regression suite подтвердил collaboration/security, C6/C3, task details/lifecycle, series, views, bulk, notifications, migrations, UI/settings/files. Дополнительные C1-тесты покрывают manifest, CRUD/CAS/replay, source ACL и deleted-source evidence, nested rollback/receipts, даты, IDs, required/mapped values и бывших approvers. Миграции073/074 отдельно проверены со схемы072: consistent SQLite backup, повторное включение, откат частичного сбоя, legacy write/code revert, foreign keys и nested deletion.

Реальный браузер: save as template → изменение offset на месяц → целевой проект; 31 октября→30 ноября с пояснением,0/false, исходная задача без изменений. Потерян ответ после commit: повтор использует тот же operationId и создаёт ровно два ожидаемых экземпляра. CAS сохраняет draft и копию; delete/restore и focus возврат проверены. Editor/viewer direct reads, forbidden edits и hidden child sources проверены; отдельно прошли source-reader/destination-writer и отзыв доступа при открытом preview.

До/после: `output/playwright/c1-before-*`, `c1-confirm-{library,editor,apply,workspace}-*`; обе схемы ×360/390/768/1440.32 cases подтверждены без overflow, с доступными основными действиями. После смены локальной сборки обязательно выполнять настоящий reload: goto того же hash URL может оставить прежний документ. Проверенная entry до последней типовой правки — `index-Bj0YcpFe.js`; новые проверки сверяют актуальную entry.

Языковая приёмка:14 системных шаблонов/локалей и14 сценариев пользовательского редактора; сохраняются кириллица черновика и типовые0/false. Последнее переключение на японский превысило30-секундное ожидание обновления аккаунта; продолжение с текущего состояния подтвердило японские подписи, отсутствие русских системных контролов и overflow, затем вернуло язык RU.
