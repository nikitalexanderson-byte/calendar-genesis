# G2/native: аудит карточки общей задачи

Основание — свежий master/production2597a3e, PR #207, workflow39214562143 success. SHA/health/chunk/старая production-вкладка подтверждены. Android остаётся2.9.0/95 и protocol6. Подготовленные E4/F/protocol7 из отдельной ветки в этот срез не включаются.

## Текущее состояние

Карточка `SharedProjectsScreen` редактирует основные поля, priority и checklists, но не показывает/не редактирует storyPoints и estimateHours. Существующий PHP snapshot уже возвращает `project.planning` и authoritative `project.permissions`; для карточки новый API не нужен. Gateway/outbox сохраняет произвольные известные task PATCH fields в encrypted account-scoped queue с requestId и expectedRevision, поэтому старые клиенты не удаляют неизвестные оценки.

В карточке права редактирования пока выводятся только из role. При явных C6 permissions UI должен учитывать серверное editTasks; fallback на прежнюю role допустим лишь при отсутствии permissions у совместимого старого snapshot. Серверные guards остаются источником разрешения операции.

По коду `AuthController.sendSharedTaskChange` network/pending возвращает короткий task `{id,projectId,revision,pending:true}`. Существующий `saveTask` затем заменяет поля формы отсутствующими значениями этого ответа. До изменения обработчика нужен воспроизводимый instrumented сценарий: queued save не должен стирать введённый title и оценки. Неподтверждённая команда хранится в прежнем encrypted outbox; новая команда той же задачи не должна создаваться поверх неё без явного решения.

## Решение: один экран

Добавить в карточку отдельную группу оценок на существующих Material3/Universal UI компонентах. Points и часы — два независимых необязательных числа,0 отличается от отсутствия. На телефоне поля располагаются вертикально, при достаточной ширине — рядом. Показать существующую подсказку о независимости единиц. Когда планирование выключено, уже сохранённые оценки остаются видимыми.

Для системных подписей использовать тот же14-язычный `planning-translations.json`, включённый как оригинальный generated asset. Не создавать вторую копию переводов и не менять остальной интерфейс.

Raw input, base values и touched flags войдут в уже сохраняемый state карточки. В API отправляются только dirty estimate keys; blank=null,0=0, omitted сохраняет соседнее значение. На явном обновлении после конфликта touched input остаётся, untouched обновляется из свежей задачи. Метаданные редактора никогда не входят в PATCH. Невалидные/отключённые/неразрешённые оценки блокируют отправку, не исчезая из черновика. Блокировка по pending учитывает и запись с ошибкой до явного решения пользователя.

Для pending-ответа использовать только проверенную идентичность и прежнюю задачу/отправленные поля; короткий receipt не считается полной задачей. Поля формы сохраняются, UUID/body остаются в действующем encrypted outbox. Окончательный ответ берётся из очередного свежего task read. Новых server migrations, зависимостей, writer protocol и публикации APK в этом срезе нет.

## Приёмка и остаток

До UI-изменения сохранить baseline с QA-эмулятора. Проверить модель dirty-only0/null/scale/range/rebase/serialization, существующий native regression и encrypted outbox; instrumented карточку, роли, pending, конфликт и no-op. Снять обе темы на QA phone/tablet, проверить увеличенный шрифт, клавиатуру и14 языков. Нативные снимки получать с эмулятора, не из браузерной имитации.

Этот этап адаптирует карточку G2. Полный native backlog/sprints, lifecycle, project planning settings, workflow/WIP, отчёты и общая приёмка остаются.
