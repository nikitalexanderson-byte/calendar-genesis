# Связанная приёмка E4/E5/F1–F3/G1–G4

Используется тот же guarded loopback PHP/TLS стенд, что и для C1–C6. Продуктовые API, Room, Android Keystore, AuthController и зашифрованный outbox остаются настоящими. Только синтетические участники `@example.invalid`; внешние Google credentials, почта, push и production-БД не используются.

В инструкциях [стенда C](../c-suite/README.md) установите дополнительно `GENESIS_ACCEPTANCE_SUITE=efg-suite` **во всех трёх процессах** (setup, PHP router, TLS proxy). Runtime и сертификат находятся в ignored `output/efg-suite/https/`. Существующий runtime не заменяется. Для PHP CLI suites нужна отдельная fresh SQLite, как в deploy.yml; не переключайте config работающего HTTPS-стенда.

1. После запуска свежего стенда выполните `node scripts/efg-suite/exchange.mjs seed` с `GENESIS_IMPROVEMENTS_TEST=isolated`. Сайт создаёт четыре типа привычек и сохраняет их через текущий encrypted workspace API.
2. Установите отдельные debug/test APK с application ID `ru.genesis.calendar.ghttps.debug` и origin `https://localhost:4443`. Подключите `adb reverse tcp:4443 tcp:4443`. При повторном использовании старого стенда очистите **только собственный синтетический debug package**, чтобы чужой runtime cookie/старый outbox не подменили новый fixture. Release package не очищать.
3. Запустите метод `NativeHabitExchangeHttpsTest#portableRecoveryAndLifecycleKeepIdentityCreditsAndAllCalendarReportsAcrossRealClients`, передав `genesisPlanningHttps=true` и `genesisFixtureCa=<base64 public PEM>`, как в C-стенде. Он проходит обычный account import/sync, паузу/архив, duplicate operation, checksum rejection, conflict-copy restore и однократный receipt.
4. Скопируйте через `adb exec-out run-as ru.genesis.calendar.ghttps.debug cat cache/...` файлы `efg-native-backup.json`, `efg-native-metrics.json`, `efg-native-history.csv` в `output/efg-suite/native-backup.json`, `native-metrics.json`, `native-history.csv`. Выполните `node scripts/efg-suite/exchange.mjs verify`: сайт читает Android JSON/CSV, восстанавливает чистое пространство, проверяет повторное применение и сравнения во всех трёх календарях.
5. Выполните `node scripts/efg-suite/exchange.mjs race`. Затем метод `NativeHabitExchangeHttpsTest#concurrentWebsiteAndOfflineNativeCreditsMergeOnceAndAvailabilityRequiresExplicitResolution`. Пока Android хранит независимые локальные изменения, второй web snapshot сохраняется через текущий API. Outbox проходит обычное трёхстороннее слияние. `node scripts/efg-suite/exchange.mjs verify-race` проверяет оба измерения, один дневной XP, отсутствие повторов наград и явное разрешение pause/archive.
6. `SharedGSuiteHttpsUiTest` проходит обычное меню приложения → workflow → planning settings → создание и запуск спринта → отчёт → исходная задача → Back → завершение с явным backlog. `genesisGSuiteCapture=true` сохраняет PNG в cache; `genesisCaptureDark=true` выбирает тёмную схему. Дополнительно используются существующие `NativePlanningHttpsIntegrationTest`, C-suite template/export/import, lifecycle/backup/report/timer instrumentation и серверные workflow integration suites.

После работы остановите собственные процессы и выполните `php scripts/c-suite/setup.php cleanup` с теми же двумя переменными. Очистка проверяет SHA конфигурации и точный путь к своей SQLite. Удалите только собственные adb reverse mappings. Runtime-файлы, сертификат/ключ и cookie не входят в Git.
