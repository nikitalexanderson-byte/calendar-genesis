# GENESIS: правила работы с проектом

## Границы и источник истины

- GitHub-репозиторий `nikitalexanderson-byte/calendar-genesis` — единственный источник отслеживаемого кода.
- Production: `https://genesiscalendar.com`, Hostinger; `GENESIS_DEPLOY_TARGET=hostinger` выбирает существующий путь CI/CD.
- Единственный разрешённый корень на Hostinger: `/home/u531952483/domains/genesiscalendar.com`.
- Единственный разрешённый корень прежнего хостинга Beget: `/home/h/haiirodw/genesis-calendar` (совместимость старых клиентов).
- Старый домен сохраняет рабочий интерфейс до подтверждения Google-входа и синхронизации нового Android-выпуска. Только после этого можно включать объявление о переезде.
- Публичный вход и документы на новом домене — Google-only. Исторические записи пользователей и закрытые совместимые маршруты нельзя удалять ради изменения публичного текста.
- Никогда не читать и не изменять соседние сайты или их каталоги.
- Не заменять существующую CI/CD-схему без подтверждённой необходимости; сначала изучить текущий diff и последние запуски workflow.

## Оформление и сохранение функций

- По решению пользователя от 10 октября 2026 используется оформление Experimental как единственная базовая тема `STANDART` со светлой и тёмной схемами. Переключателя семейства тем нет; сохраняется только выбор дневного и ночного режима.
- В обеих цветовых схемах сохранять все текущие изображения, иконки, PNG/JPG/SVG/WEBP и другие ассеты на существующих смысловых местах. Не удалять и не заменять изображения ради компактности.
- Сохранять сакральный, лунный и григорианский выбор дат, независимость календаря отображения и календаря ввода/повторов, кастомные окна времени 24h и AM/PM, существующие функции и данные.
- В нативном Android-календаре месячный и годовой экраны строить из самостоятельных блоков: плашка с иконкой и названием календаря отдельно, навигация по периоду отдельно, содержимое отдельно. Плашка находится в общем вертикальном потоке: уходит вверх при прокрутке и возвращается при прокрутке назад. Её нельзя закреплять над содержимым или помещать вместе с навигацией и сезонами в одну общую карточку.
- Экран «Сегодня» всегда показывает только фактическую сегодняшнюю дату, её задачи и привычки. Просмотр любого другого дня и переходы из счётчиков задач выполняются в «Календарь → Месяц». Не использовать выбранную дату календаря как дату экрана «Сегодня».
- Развивать уже согласованный `GENESIS Universal UI`. Не менять стек и не подключать новую UI-библиотеку без подтверждённой необходимости.
- Совершенствовать и унифицировать удобный дизайн вместе с каждой функцией на десктопном сайте, мобильном сайте и в Android. Группировать интерфейс по смысловым блокам. Использовать общие стили и состояния кнопок; понятные второстепенные действия оформлять компактными иконками вместо длинных текстовых кнопок, с локализованными доступными именами и подсказками. Неоднозначные действия и важные подтверждения сохраняют короткую подпись. Цели касания — не меньше 44px в web и 48dp в Android, кроме уже документированных исключений общей шапки.
- Сначала проводить аудит и предлагать изменения. Реализацию начинать с одного экрана, а не с переделки всего приложения сразу.
- После реализации проверять светлую и тёмную схемы в браузере на ширинах 360, 390, 768 и 1440 px.
- Сохранять скриншоты до/после и в итоговом отчёте явно перечислять непроверенные состояния.

## Экономный порядок работы

По новому указанию пользователя от 22 октября 2026 после завершения текущих правок разрешён промежуточный деплой сайта через существующий workflow. Сохранить последние параллельные изменения `master` и публиковать только согласованный web/API-срез. Новые сборки и публикация Android пока запрещены; использовать `GENESIS_DEPLOY_ANDROID=false` и не запускать native build workflows. Проверки уже собранного изолированного QA APK можно завершить. Пункт 6 ниже применяется к этому web-релизу; Android требует нового указания пользователя.

1. Начать с `git status --short --branch`, `git diff` и точечного `rg` по связанным файлам.
2. Не перечитывать весь репозиторий и не создавать полные локальные/серверные копии кода.
3. Сохранять незакоммиченные изменения пользователя. Работать в отдельной ветке от свежего `origin/master`.
4. Менять только относящиеся к задаче файлы.
5. Перед публикацией выполнить `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm test` и `pnpm build:beget`.
6. Затем: commit в рабочую ветку -> push -> merge в `master` -> дождаться GitHub Actions -> проверить production.

## Деплой и rollback

- Деплой выполняет только `.github/workflows/deploy.yml` после push/merge в `master`.
- Клиент и PHP API публикуются в `/home/u531952483/domains/genesiscalendar.com/public_html`; закрытый PHP-код — в `/home/u531952483/domains/genesiscalendar.com/server`. Beget остаётся только для согласованной совместимости; соседние каталоги запрещены.
- Перед каждым CI-деплоем автоматически сохраняются только server-only данные: `server/config.php` и согласованная SQLite-копия. Полные копии отслеживаемого кода не нужны: его история уже находится в Git.
- Code rollback: сделать `git revert` проблемного merge/commit в `master`; новый push автоматически развернёт предыдущую версию.
- Database rollback не выполнять автоматически. Сначала остановить изменяющие запросы, проверить нужную runtime-копию и согласовать восстановление.
- После деплоя `/deploy-meta.json` должен содержать SHA текущего `master`, а `/api/health` — отвечать успешно.

## Данные, миграции и секреты

- Никогда не коммитить и не выводить содержимое `server/config.php`, `server/var/`, `.env*`, SSH-ключей, Google client secret, refresh/access tokens и GitHub secrets.
- `server/config.php`, `server/var/`, `deploy-private/`, `backups/` и `sshp.txt` должны оставаться вне Git.
- SQL-миграции из `server/migrations/` применяются приложением при первом обращении к БД. При добавлении миграции отдельно проверить backup, совместимость и путь отката.
- Не изменять production-БД вручную без отдельной задачи и явного плана восстановления.

## SSH

- SSH допустим только когда Git/GitHub Actions и публичные health-checks недостаточны: диагностика deploy, права, PHP/runtime, cron, server drift, логи или безопасная проверка server-only состояния.
- По умолчанию использовать read-only команды и точные пути внутри корня GENESIS.
- Не показывать секреты в выводе. Не читать `config.php` целиком.
- Любую аварийную правку на сервере немедленно перенести в Git и повторно развернуть через workflow.
- В итоговом отчёте указать, использовался ли SSH и зачем.
